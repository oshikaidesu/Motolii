対象: skin/book/lib/sets/inspector/cards_table.dart（行番号はこのファイル）、cards_set.dart、integration_test/cards_test.dart、reports/card_ui/*/ の絵。

ひどい順に並べる。各項目は「手順 → 起きること（行） → なぜ困るか → いちばん小さい直し方」。

## 1. 運んでいる最中に ⌘Z を押すと「運んでいる」状態が抜けなくなる。「外す」の幕が手札と棚を覆ったまま、押せない（いちばん重い）

**手順 A**: 値に揺れを重ねる → その揺れの印を掴んで運び始める → 掴んだまま ⌘Z（いま重ねた揺れが取り消される）→ どこかで離す。
**手順 B**: 棚から「散らす」を付ける → そのカードの色の角を掴んで棚へ運び始める → 掴んだまま ⌘Z（付けたのが取り消され、カードは棚へ戻る）→ 離す。
**手順 C（タッチ）**: 1本の指で印かタイルの名前の帯を運び、別の指でそのカードの目（伏せる）か裏返すを押す。

**起きること**: 取り消し（118-141行）は `carrying`、`preview`、`cardPreview` に触らない。取り消しで掴んでいた元の部品が木から消える（印は 913行の `if (d != null)` で消え、カードの角は一覧から消える）。Flutter の Draggable は、元の部品が消えた後のドラッグ終わりで `onDragEnd` を呼ばない（`mounted` を確かめている）。なので `t.carry(null)`（647、870、1208、1282行）が来ない。
- 印の場合: `carrying` が文字列のまま残る → 1291-1301行の「外す」の幕が手札と棚の上に出続ける。幕は飾りの付いた Container なのでタッチを受け止め、**手札のカードも棚のカードも掴めなくなる**。どのタイルも「ここに落とせる」の色で縁取られたまま（861-862行）。
- カードの場合: `carrying` が棚にあるカードのまま残る → 舞台の枠（497-501行）が出続ける。
- 元に戻すには、たまたま別の物（タイルの名前の帯、カードの角）を運んで離すしかない。そんなことは誰にも分からない。

**なぜ困るか**: 物差しの 7「戻せない、何が効いているか分からない」そのもの。しかも「戻す」を押したせいで壊れる。
**直し方**: `undo()` の中で `carrying = null; preview = null; cardPreview = null;` を入れる。運んでいる間は ⌘Z を効かせない（`if (carrying != null) return;`）のでもよい。

## 2. 日本語入力のまま数字を打つと黙って無視される。「−5」は 5 になる、「3e2」は 32 になる

**手順**: 「180px」をタップ → かな入力のまま 240 と打つ（全角の「２４０」になる）→ Return（変換確定でもう一度 Return）。
**起きること**: 946行 `c.text.replaceAll(RegExp(r'[^0-9.\-]'), '')` が全角数字を全部消して空にする → `tryParse('')` が null → 何もせずに閉じる（951行）。間違いも知らせも出ない。
- 「−5」（U+2212 のマイナス）、「ー5」、「－5」→ マイナス記号が消えて **5 として入る**（符号が逆）。
- 「3e2」→ e が消えて **32**。「1.2.3」「1-2」→ null で黙って無し。
**なぜ困るか**: 使う人は日本語しか読まない。全角入力はいつものこと。「打ったのに変わらない」は壊れて見える。符号の逆転は黙って間違う。
**直し方**: 解く前に全角を半角に直す（０-９、．、－、−、ー → 0-9 . -）。解けなかったら閉じずに、欄を赤くして開いたままにする。

## 3. 束の帯に値を落としても束に入らない。試験もこれを見逃している（絵が失敗を写している）

**手順**: 半径と大きさを束ねる → 上に束の帯が出る → 「1つずつ回す」の名前の帯を長押しで持ち上げ、上の束の帯（「束1 大きさ 半径」）に落とす。
**起きること**: `_BundleTile`（1121-1156行）は DragTarget ではない。落としても何も起きず、タイルは帰っていく。
**証拠**: `reports/card_ui/束ねる/05_spin_joins_bundle.png` では、束1 は「大きさ 10px / 半径 93px」のままで、1つずつ回すには束の印が無い。試験（cards_test.dart 129-136行）は `tile('大きさ')` = `find.text('大きさ').first` を狙っているが、束を作った後の最初の「大きさ」は**束の帯の中の文字**なので、帯に落としていた。人の手も同じことをする。試験は何も確かめていないので通ってしまう。
**なぜ困るか**: 束の帯はいちばん目立つ「束」の場所なのに受け口ではない（物差し 1 と 4）。
**直し方**: 束の帯を `DragTarget<Val>` にして `tie(a, bundles[i].first)` を呼ぶ。試験は撮るだけでなく `expect(t.bundles[0].length, 3)` を足す。

## 4. 打ち込み中に ⌘Z か戻る矢印を押すと、打ちかけが消えるうえに、一つ前の別の操作まで取り消される

**手順**: 揺れを重ねる → 「44px」をタップして 4 と打つ → 打ち間違えたので ⌘Z（文字を戻したい）。
**起きること**: 表の `CallbackShortcuts`（449-453行）は、文字欄より先に ⌘Z を受け取る。文字欄の外側だが、アプリにある文字用ショートカット（DefaultTextEditingShortcuts）よりは内側にあるので先に取る。結果 `undo()` が走り、`editing = null`（139行）で欄が閉じ、**さっき重ねた揺れまで消える**。
戻る矢印（582行）の場合は、押した時点で `onTapOutside`（974行）が打ちかけを捨て、そのあと onTap で取り消しが走る。押し1回で効き目が2つ。
**なぜ困るか**: 「打った文字を消したい」と思って押すと、関係ない作業が消える。気づきにくい。
**直し方**: `editing != null` の間は表の ⌘Z を流す（`if (editing != null) return` にして文字欄に任せる）。戻る矢印は、打ち込み中なら打ちかけを閉じるだけにする。

## 5. 端にある値を束ねると、その向きには束が全く動かない。しかもどれが止めているか見えない。不透明は最初から端（100%）にある

**手順**: 不透明（初期値 100%、上限 100。396行）を大きさに束ねる → 束の帯を右にこする。
**起きること**: 355-363行で、`hi = (v.hi - start)/span` が不透明では 0 → 束の割合が 0 より上に行けない → 大きさも動かない。帯は何の反応も出さない。左へは動く。
**なぜ困るか**: 「束が壊れた」に見える。どの値が止めているか、どの絵にも出ない（物差し 2 と 7）。
**直し方**: 止めている値のタイルを光らせる（束の帯の中のその値の棒を赤く）。または、止まった値だけ端で止めて残りは動かす切り替えを用意する。

## 6. 棚が溢れる。カードを4〜5枚棚に戻すと、はみ出したカードは見えず掴めない＝付け直せない

**手順**: 見た目・複製・波・色の角を順に棚へ運ぶ（散らすは最初から棚にある）。
**起きること**: 棚は高さ 36 の折り返さない `Row`（1270-1287行）。カードの札は幅およそ 75-85px で、使える幅は 360 から両脇を引いた約 336px。5枚目あたりで右端がはみ出す（デバッグでは黄黒の縞、本番では切れる）。はみ出した札はタッチを受けない。
**なぜ困るか**: 取り消し以外にカードを戻す道が無くなる（物差し 7「外せない／戻せない」の逆、「付けられない」）。
**直し方**: `Wrap` にするか、横に送れるようにする（`SingleChildScrollView(scrollDirection: Axis.horizontal)`）。

## 7. 裏返したカード（裏の行）は「束の印が出ない、持ち上げられない、数字を打てない」

## 9. 取り消すたびに揺れの時計が巻き戻り、動いている星が全部跳ぶ。重ねた瞬間にも跳ぶ

- 81行で時計も一緒に写し、121-124行で戻している。何秒か前の操作を取り消すと、すべての揺れ・ノイズの位相が飛ぶ（数字を一つ戻しただけでも）。コメントにある「速さを変えても波が飛ばない」の約束と食い違う。

**直し方**: 取り消しでは時計を今のまま残す（同じ id の Drive の clock を引き継ぐ）。新しい Drive は `..clock = clock` で始める。

## 11. 表以外を一度触ると ⌘Z が効かなくなる

454行の `Focus(autofocus: true)` は最初の一度だけ注目を取る。Widgetbook の検索欄やつまみの欄を触ると注目はそちらへ移り、表をクリックしても取り戻さない（どこにも `requestFocus` が無い）。戻る矢印は効くが、⌘Z は黙って効かない。
**直し方**: 表全体のタップで `focusNode.requestFocus()`。あるいは `Shortcuts` をアプリの階層に置く。

## 12. 束を番号で指しているので、こすり中に束の並びが変わると別の束が端まで暴走する

**手順**: 大きさと半径を束ねる（束1）→ 色相と明るさを束ねる（束2）→ 束1の帯をダブルタップしてほどく（束2が繰り上がって「束1」になる）→ その帯をこすり続けたまま ⌘Z を2回押す（1回目でこすりの写しが消え、2回目でほどいたのが戻り、並びが [大きさ・半径, 色相・明るさ] に戻る）。タッチなら、1本の指で束1をこすりながら、別の指で束1の値のタイルの束の印をダブルタップしてほどくだけで起きる。
**起きること**: こすりは添字 `i=0` で束を指している（1128-1129行）。帯は印の無い for で並んでいる（593行）ので、0番目の帯の部品はそのまま使い回され、指はいまや**別の束**（大きさ・半径）をこすっている。`_bundleStart`（351行）にはこの束の値が無いので、毎回 `?? v.v`（359、365行）になる。すると毎フレーム「今の値 + たまった割合 × 範囲」が足され、数フレームで端まで飛ぶ。
**直し方**: 束を添字でなく束そのもの（List の同一性）で持つ。`_bundleStart` に無い値は動かさない。

## 物差し 7（壊れない）の見立て

1（運んでいる状態が抜けない）と 3（束の帯が受けない、試験が見逃す）は直すまで 6 未満。2・4 は日本語で打つ人には毎日起きる。私の点: **4 / 10**。

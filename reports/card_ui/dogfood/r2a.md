# ドッグフーディング 2回目 A（r2a）

目標（ユーザーの言葉）: 星が親分。星の輪が大きく・小さくなったら、四角6つも一緒に大きく・小さくなってほしい。

## 1. できたか

**できた。** 32手（自分の窓での手は31。もう1手はこちらの手違いで別の試す人の窓に送ってしまい、無効）。

ただし四角の大きさを元の 90px のまま保てたのは S1 と S2 だけ。S3〜S6 はつないだ瞬間に 180px（輪の半径と同じ数）になったので、半径を 120 にした今は 120px。倍率を 0.5 に直すには1つにつき4手かかり、手数の上限に入らなかった。

### 先に報告: 試しの途中で起きた事故（アプリのせいではない）

道具置き場（scratchpad）に作った手送り用の小さなスクリプトを、同時に動いていた別の試す人（r2b）が同じ名前で上書きした。そのため次のことが起きた。
- 自分の窓の命令の帳面に、自分が送っていない `tap 750 158` が2回入った（絵 003 と 007）。007 で S1 が選ばれ、次の手 5 は狙いと違う物をつかんだ。
- 自分の手 12（Scale を押す）は r2b の窓に入ってしまった。r2b の試しに余計な1手が混ざった可能性がある。
- 手 13 からは自分専用のスクリプトに替えた。

## 3. 一番詰まった所

- **絵 005〜006（手 4）と 017（手 15）**: 「星の Radius を四角につなぐ」入口を探していた。タイルを舞台の四角に直接落とすのが一番自然だと思ったが、2回とも何も起きなかった。落とした時に「つながらない」の合図も無いので、失敗したのかやり方が違うのか分からない。手札を通す道（タイル → 手札 → 相手のタイル）は当てずっぽうで見つけた。
- **絵 019（手 17）**: 2つ目からは「選んで手札を押すだけ」でつながったが、S1 で合わせた倍率 ×0.5 は持ち越されず、毎回 ×1（180px）に戻る。6つ全部を元の大きさで揃えるには1つにつき4手（選ぶ・印・Scale・打つ）かかり、ここで手数が尽きた。

## 4. 「こうなっていると思った・あると思ったのに無かった」もの

- 値を舞台の物に落とすと、その物のどれか（大きさ）につながると思った。四角には Radius という名前の値が無いので、何も起きない（合図も無い）。
- 2つ目以降も、最初に決めた倍率（×0.5）のままつながると思った。つまり「最初の四角と同じつなぎ方を、他の四角にも」。
- 6つの四角をまとめて選んで一度につなぐ方法があると思った（Shift で複数選ぶ、など）。見当たらなかった。
- 「親分を大きくしたら、今の大きさから同じ割合で大きくなる」（今の 90px を保ったまま比例する）つなぎ方が最初に来ると思った。実際は相手の値そのもの（180 なら 180px）で、比例させるには自分で倍率を計算して打つ必要がある。

## 5. どうやって分かったか

- 絵 013: Size が緑の数字に変わり ↗R の印が付き、四角が 180px になった（Radius と同じ数）。
- 絵 031: R を選ぶと Radius の名前の横に「→6」。
- 絵 033: Radius を 180 → 120 にすると、星の輪が縮み、6つの四角も全部同時に縮んだ。S1/S2 は 90 → 60px、S3〜S6 は 180 → 120px。星が親分になっているのが絵で見えた。

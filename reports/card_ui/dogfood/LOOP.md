# ドッグフーディングのループ（2026-10-19〜）

ユーザー：「CSS によく見られる一つのオブジェクトが全体に作用するような動きを、このカード型で直感的に作れるかをドッグフーディングにしよう。サブエージェントにはそれ（仕組み）を伝えずに、迷わずにできるかを検査して、ループを回す」
ユーザーの気づき（未対応、試す人が詰まるかで決める）：手札に持ってきて別の物を選ぶと、元の物のインスペクタが消えて見えなくなる。

## 1回の流れ
1. 試す人用の窓を2つ立てる（scratchpad/hand/lab_book.app を AGENT_DIR=scratchpad/hand/rNa, rNb で起動。AGENT_PAGE なし＝Link 頁）。見本を直したら `flutter build macos --profile` してから app を scratchpad/hand に写し直す。写し直しは `rm -rf "$D/lab_book.app"` を単独で（同じ行に該当なしのグロブを混ぜると zsh が止まり、cp が古い app の中に入れ子で写す：3回目に一度これで古い版のまま試させた）。写した後、`strings App.framework/App | grep <新しく足した一文>` で新しい版か確かめる。
2. 知らない試す人2人に TESTER.md を渡す（GOAL は毎回言い方を変える。仕組みの言葉＝手札・値のカード・つなぐ・リンクは絶対に入れない）
3. 結果 rNa.md / rNb.md を読む。一番多く詰まった所を1つか2つ直す。撮影テスト（integration_test/cards_test.dart）を通してコミット
4. 窓を閉じて次の回

## 合格
2人とも「できた」、20手以内、迷い2（当てずっぽう）が1回以下。2回続けて合格で止める。

## 進み具合（各回1行）
- 1回目: A できた 23手（不合格）・B できた 18手、2人とも『名前を長押しして運ぶ』を当てずっぽう、四角に直接落とせない、つないだ数字が絵と合わない、四角の番号が分からない → 直してコミット
- 2回目: A できた 32手（不合格、半径を四角に落としても無反応・つなぐたび180pxに膨らむ）・B できた 16手（当てずっぽう1、空っぽの棚の枠が謎、物に属さない変数が欲しい）、3人目も『まとめてつなぐ』を欲しがる。試す人どうしの手送りが混ざる事故 → 直してコミット
- 3回目: A できた 10手・当てずっぽう1（合格）・B できた 13手・当てずっぽう1（合格）。2人とも最初の『名前の帯を持てば運べる』は勘、空いた所に落とすと全部は見つけず、つながった側・親の側にその一覧が見えない
- 4回目: A できた 5手・当てずっぽう1（空いた所に落とすと全部は勘、星の輪までつながった）・B できた 11手・当てずっぽう0（6回くり返し、つないだ瞬間に色が変わらず一瞬つなぎ損ねたと思った）→ 2回続けて合格、ループ終了
- 5回目（名札に作り直した後、課題に「1つだけ外す」を足した）: A できた 12手・当てずっぽう1（合格）・B できた 14手・当てずっぽう2（不合格）。外す方は2人とも迷わず（名札を押す→一覧の ×）。詰まりは2人とも同じ1つ：運んで物の上で止まると値の輪が開き、真ん中で離すと何も起きない → 止まってから離しても同じ名前の値に名札が付くよう直した。A の最初の絵では、試す人が何も送っていないのに Fill のカードが持ち上がっていた（窓に本物のマウスが入った疑い）

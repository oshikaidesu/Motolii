## 1. マウスでは名前の帯の長押しで持ち上がらない。帯でもこすれて値が動く（束ねる手つきに実質届かない）
- 手順: マウスかトラックパッドで、タイルの名前の帯（例「半径」）を押したまま 0.3 秒待って運ぶ。
- 起きること: 帯の `LongPressDraggable`（1106）は、タイル全体を包む横こすりの `GestureDetector`（1133-1141）の内側にある。Flutter ではマウスの横ドラッグは 1px 動けば始まる（kPrecisePointerHitSlop）。長押しのほうは 18px まで待つ。0.3 秒のあいだに手が 1px でも横に揺れると、こすりが勝つ。`mark()` が呼ばれて値が動き（1141）、持ち上げは起きない。コメントの「持ち上げは名前の帯だけ（こすりと取り合わない）」とは違って、帯はまだこすりと取り合っている。
- テストで見えない理由: `t.startGesture` はタッチ扱いなので、遊びが 18px ある。テストは通るが、Mac の手では通らない。※コードを読んだ上での推論で、実機のマウスでは確かめていない。
- なぜ困る: 束ねるの入口が手の揺れ次第になる。失敗すると値が勝手に動き、取り消しの段も積まれる。
- 直し: こすりの `GestureDetector` を帯の外（数字と下の部分）だけに付ける。帯の上では横ドラッグを受けない（帯を `Padding` の外に出して、こすりの子にしない）。テストに `kind: PointerDeviceKind.mouse` で 1px 揺らす長押しを足す。

## 2. 舞台の輪: 縁の近くで止まると、手を動かしていないのに向きが選ばれている。角では開いて閉じてを繰り返して選べない
- 手順A: 手札（右下）から「揺れ」を運び、舞台の右の縁を越えてすぐ（縁から 90px 以内）で止まる → 離す。
- 起きること: 輪の中心は舞台の内側に押し込まれる（623、縁から 118/88px）。手と中心が 28px 以上離れるので、`_aimAt`（635-640）がすぐに「半径」（右）を選び、`hover` で先に効いて見える。そのまま離すと半径に付く。下の縁なら「1つずつ回す」に付く。手札は右下にあるので、運んでくる手はまさにこの右縁・下縁を通る。
- 手順B: 右下の角の近く（例: 縁から x 20px・y 20px）で止まる。
- 起きること: 押し込まれた中心と手の距離が 110px を超える（下の縁から 20px なら約 119px）。少しでも動くと 614 で輪が閉じ、0.25 秒で同じ場所にまた開き、また閉じる。運んでいるカードも小さな印 ↔ 大きな札を行き来する（1695）。
- なぜ困る: 「止まって、向きで選ぶ」約束が、入口のあたりで破れる。自分で選んでいない値が動く。
- 直し: 中心を押し込んだときは、手の位置を「中立」として扱う（`_aimAt` は中心ではなく、開いた時の手の位置 `at` からの差で測る）。輪の絵だけを内側に描けばいい。

## 3. つまみ（幅・速さ・シード）のこすり中は ⌘Z が通ってしまう。取り消しの段を食い、⇧⌘Z で途中の値に戻される
- 手順: 揺れの印を押してつまみを開く → 「幅」を横にこすっている最中に ⌘Z → 手を離す → ⇧⌘Z。
- 起きること: つまみのこすりは `mark()` を呼ぶだけで（1374）、`scrubbing = true` を立てない。そのため `undo()` の守り（148）が効かない。⌘Z でこすり前に戻るが、こすりはそのまま続き（作り直された `d` に `setDrive` が届く）、値はまた動く。こすりの前の段はもう消えている。次の ⌘Z では、その一つ前の、関係ない変更まで一緒に戻る。やり直しの山には「⌘Z を押した時の途中の状態」が残っていて、⇧⌘Z を押すと、こすって決めた幅がその途中の値に上書きされる。まだ動かしていない時に ⌘Z を押すと、こすり前の段は「何も変わらない段」として飛ばされる。すると揺れを付けた手つきまで戻り、手の下でつまみが消える。
- なぜ困る: タイルと束では塞いだ「こすり中の ⌘Z」が、つまみだけ開いたまま。
- 直し: つまみの `onHorizontalDragStart/End/Cancel` でも `t.scrubbing` を立てて、下ろす（タイルと同じ3行）。

## 4. 何も変えない手つきが、やり直しの山を黙って消す
- 手順: 何か変える → ⌘Z → 次のどれか1つをする →  ⇧⌘Z。
  - 数字を押し、同じ数字のまま Return か Tab（1202 `t..mark()..set`）
  - タイルや裏の行を少しこすって元の値に戻す（1136 / 1328 で始めた瞬間に `mark`）
  - 束の帯をクリックした時に 1px 揺れる（1455 `startBundle` → `mark`）
  - ずれの起点で、今選ばれている「端」をもう一度押す（1418）
  - 幅がもう最大の値に、同じ揺れを重ねる（316 で幅は変わらないのに 313 で `mark`）
- 起きること: `mark()`（139-143）は、変更があったかどうかに関係なく、`_redo.clear()` を最初に呼ぶ。⌘Z の側は「何も変わらない段」を飛ばす（151）。でも、やり直しの山はもう空になっている。⇧⌘Z は何もしなくなり、↷ は灰色になる。説明は出ない。
- なぜ困る: 取り消して確かめるという往復が、確かめるための1回の押しで切れる。
- 直し: `mark()` では今の状態を「待ち」として取っておくだけにする。`_redo.clear()` と `_undo.add` は、次に `_changed` が来て `!_pending.same(_Snap(this))` だった時だけ行う。

## 5. 打ち込み中に ↶ を押すと、打ちかけを捨てたうえ、その前の変更まで1つ取り消す
- 手順: 半径の数字を押して「240」と打つ（まだ Return は押さない）→ 見出しの ↶ を押す。
- 起きること: 押した瞬間に `onTapOutside`（1255）が `type(null)` を呼び、打ちかけが消える。指を離すと ↶ の `onTap`（797）が `undo()` を呼ぶ。この時はもう `editing == null` なので、本当の取り消しが走る。⌘Z の時は打ちかけを閉じるだけ（149）なので、同じ「戻る」なのに効き方が違う。
- なぜ困る: 「打つのをやめたい」が、気づかない1段の取り消しになる。しかも、打ちかけの数字はクリックで外すと黙って捨てられる（1255）。AE のように「外したら決まる」を期待する手には、2重の驚きになる。
- 直し: ↶ と ↷ を `TapRegion` の内側として扱う（`TextFieldTapRegion` で包む）。打ち込み中は ↶ も `type(null)` だけにする。ついでに、外側を押した時は捨てずに `_keep()` で決めるのを考える（読めない時だけ捨てる）。

## 6. 「数」と「波の速さ」が束に入る（「数は束ねない」が破れる）
- 手順: 「数」のタイルの名前を長押しして持ち上げる → 上の束の帯（束1）に落とす → 束の帯をこする。
- 起きること: 名前の帯の `LongPressDraggable` はすべてのタイルにある（1106。点の印 1128 は canDrive の時だけだが、掴むことはできる）。タイルに落とすと `_ok` が断る（1063）。ところが束の帯の `DragTarget<Val>` は `!vals.contains` しか見ていない（1451-1452）。数が束に入り、こすると星の数が 3〜48 で動き、`v.v` が小数になる。波の「速さ」（perCopy: false）も同じ。
- なぜ困る: 束をこすったら輪の星の数が増えたり減ったりする。しかも「断られる」の絵（×）も出ない。運んでいるのが Val の時、× は Beh と String にしか出ない（1174, 1190）。
- 直し: 1451 を `!vals.contains(e.data) && CardTable.canDrive(e.data)` にする。canDrive でないタイルには、帯の `LongPressDraggable` を作らない。

## 7. 予告と結果が食い違う（落とす前に見えるもの ≠ 落とした後）
- 7a. 揺れの印（String）を、同じ揺れが付いた別の値に運ぶ: タイルの ± は「同じ種類なら +.15 広がる」を見せる（1104）。でも `moveDrive`（331-336）は入れ替えなので、幅は運んだ印のものになる。違う種類の値に運んだ時も、± は相手の幅を見せる。実際に付くのは運んだ印の幅。
- 7b. 揺れを3回重ねて幅 .65 にした値に、ノイズを重ねて止める: 舞台の予告は幅 .2・全体の時計・速さ 1 で動く（244）。離すと `lay` は幅 .65・前の揺れの時計・前の速さを引き継ぐ（318-321）。そのため、離した瞬間に動きの大きさと位相が跳ぶ。タイルの ± は .65 を見せていて、舞台とタイルで言っていることが違う。
- 直し: 1104 で、`over` が印の時は `t.drives[mark].width` を使う。244 の違う種類の分岐は `(d?.width ?? .2)` にし、時計は `d?.clock ?? clock`、速さは `d?.speed` で回す（`lay` と同じ式を1か所にまとめる）。

## 8. 舞台の輪は、伏せたカードの値を選べてしまう（付いても何も見えない）
- 手順: 「色」を伏せる → 揺れを舞台で止めて輪を開く → 左（色相）を選んで離す。
- 起きること: `_aimAt` は `valOr` だけを見る（639）。`valOr` は伏せたカードも返すので、色相は選べる。付けた後、`at()` は伏せたカードの値に代わりの値を返す（240）ので、星は何も変わらない。タイルも伏せていて見えない。一方、手札を押した時は、伏せたカードを断って揺れる（267）。同じことが、入口によって通ったり断られたりする。
- 直し: `_aimAt` と、輪の丸い札の明るさに `cards.contains(cardOf) && !cardOf.down` を足す（丸い札は「—」の灰色にする）。

## 9. 日本語入力の「ー」をマイナスとして読まない
- 手順: 位置 X の数字を押す → 日本語入力のまま「ー50」と打つ → Return。
- 起きること: 全角に直す処理（1224）が知っているのは、FF0D「－」と 2212「−」だけ。かな入力でマイナスキーを押すと出る 30FC「ー」は残り、正規表現は「50」を拾うので +50 になる。赤（読めない）にもならない。
- 直し: 1224 の置き換えに `0x30FC`（と `0x2010-0x2015`）を足す。

## 10. 止めの赤（bundleStop）が、止めていないのに残る
- 手順: 束をこすって大きさを下の端で止める（大きさの数字が赤くなる）→ 手を離す → 束をダブルタップでほどく → 大きさを別の値と束ねる。
- 起きること: `bundleStop` が消えるのは、`startBundle`（436）と取り消し（167）の時だけ。離しても、ほどいても、束ね直しても、打ち込んでも赤いまま（1479）。新しい束で、動かしてもいない大きさが「止めている値」の赤で出る。絵 束ねる/05 でも、こすり終わった後に大きさが赤い。
- 直し: こすりの終わり（1458）と `tie / untie / untieOne / set` で `bundleStop = null` にする。

## 11. 並べ替えで一番下に運び過ぎると、カードが棚に外れる。着せ直しても束は戻らない
- 手順: 「色」（一番下）の見出しを、少し下へ運んで並べ替えようとする → 手札の帯に入ってしまって離す → 棚から舞台へ投げて着せ直す。
- 起きること: 手札の場所（`_Hand`、1601）は、カードの並びのすぐ下にある。落とすと `shelve`（391-401）になる。揺れは覚えていて戻るが、束からは外されたまま（396）。`wear` は一番下に足すだけで、束は戻さない。開いていたつまみ（`open`）は外しても消えず、着せ直すと急に出てくる。
- なぜ困る: 「揺れは戻るのに束は戻らない」という、半分だけの記憶。⌘Z に気づかなければ、束が黙って消える。
- 直し: `shelve` で、カードごとに抜けた束の相手を覚えておき、`wear` で戻す（揺れと同じ扱い）。または、並びの一番下に「ここが最後」の落とし所を作り、手札との間に隙間をあける。

## 12. 「最後に触った値」が見えない所にある時、手札を押すとそこへ付く
- 手順: 「見た目」を裏返して「位置 X」の行をこする（または束の帯の数字を打つ）→ 表に戻す → 手札の「揺れ」を押す。
- 起きること: `touched` の下線はタイルにしか描かれない（1175）。裏の行と束の帯には出ない。付く先が見えないまま押すと、裏の位置 X に付く。表では「裏」の小さな印が増えるだけ。
- 直し: `_BackRow` にも同じ下線を出す。表に出ていない値が `touched` の時は、手札の上に「→ 位置 X」の小さな名前の札を出す（ことばを減らす方針なら、値の色の点だけでもいい）。

## 13. シードはこすると小数のまま、表示は丸めている
- 手順: ノイズのシードを少しこする（3.0 → 3.4、表示は「3」のまま）→ 押して「3」と打つ → Return。
- 起きること: こすりは `d.seed + dx/8` を小数のまま持つ（1411, 358）が、表示は `round()`。同じ「3」でも絵が違う。「3」と打つと、数字は変わらないのに絵が変わる。
- 直し: `setDrive` で `seed` を `roundToDouble()` する。

## 14. 束の帯: 数字の打ち込みが 0.3 秒遅れる。数字をダブルクリックすると束ごとほどける
- 帯のダブルタップ（1461）が、内側の数字のタップ（1479）と取り合う。1回押すとダブルタップの待ちが切れるまで開かない。2回押すと（打つつもりでも）束がほどける。マウスの 1px の揺れでこすりも始まる（4 の `mark` で、やり直しも消える）。
- 直し: ほどく手つきは束の印（束1 の丸）のダブルタップだけにして、帯全体からは外す。

## 15. 同じ束の印なのに、表と裏で手つきが違う
- 表のタイルの束の印は運べる（手札に落とすと抜ける、1180）。裏の行の束の印はダブルタップで抜ける（1351）し、運べない。裏の値は、名前を持ち上げて束ねることもできない（行に `LongPressDraggable` が無い）。
- 直し: 裏の行の印も、表と同じ `Draggable<Val>` にする。

## 16. 「複製」を棚に戻した時の矛盾
- 星は1つになる（744、代わりの値 1）。ところがタイルの下の細い線は 12 本描かれる（1303、代わりの値 12）。波の札「1つずつ」は残っていて、押しても何も起きない（461-462 で早く戻るだけで、揺れて断ることもない）。
- 直し: 1303 の代わりの値を 1 にする。`copiesFirst` が決められない時は札を隠す。

## 17. 種類を替えると、シードと起点が 0 に戻る
- ランダム（シード 7）の上にノイズを重ねると、シードは 0 になる。ランダムに戻しても 0 のまま（318-321 が引き継ぐのは幅と速さだけ）。「替えても残る」の約束が半分。
- 直し: `seed` と `from` も引き継ぐ。

## 18. 小さいもの
- 範囲の外の打ち込みは黙って丸められる（半径 500 → 300、回転 400° → 40°、31）。数字が一瞬赤く光るなどの合図が無い。
- 運んでいる値（Val）が数のタイルの上に来ても、× が出ない（1174/1190 は Beh と String だけ）。
- 舞台は揺れの印（String）を断るが、× が出ない（舞台は `refusing` に触らない、658-669）。タイルの上では出るので、言っていることが揃っていない。
- 何も変わらない段しか残っていない時も、↶ は明るい（`canUndo`、797）。押しても何も起きない。
- Ctrl+⇧Z が無い（552-554）。Mac では困らない。
- 束を2つ作って束1をほどくと、束2 が「束1」に名前を変える（1439）。見ていた印の名前が入れ替わる。

## 上の6つ（直す順）
1. マウスでは名前の帯の長押しが 1px のこすりに負ける。束ねるに届かず、帯でも値が動く（1106 / 1133）。
2. 舞台の輪: 縁では中心が押し込まれて、選んでいない向きが先に選ばれる。角では開いて閉じてを繰り返す（623 / 635 / 614）。
3. つまみのこすりは `scrubbing` を立てないので、こすり中の ⌘Z が段を食う。⇧⌘Z で途中の値に戻される（1374 / 148）。
4. 何も変えない手つきでも、`mark()` がやり直しの山を消す（139-143）。
5. 打ち込み中の ↶ は、打ちかけを捨てたうえ、前の変更まで取り消す（1255 / 797 / 149）。
6. 数・波の速さが束の帯に落とせる（1106 / 1451）。

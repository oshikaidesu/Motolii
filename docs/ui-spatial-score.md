# S. 空間スコア — 動線・大きさ・視覚重みの機械化(裁定163)

- 制定: 2026-08-21(利用者提起「スクショ目視の宣言をスコア化に置換する。従来の UI 認知による段差を何より大事に。位置替えの反復を無くし最初からビタイチで置く。パネルごとにヒーローを逆算確定する」)
- 位置づけ: [品質バー](ui-quality-bar.md)の第3軸。Q=操作品質規則・B=時間予算に対し、**S=空間の規則とスコア**。データ源は入口台帳([κ 調査](reviews/2026-08-21-ui-entrance-atlas-survey.md))・normal-map の entries 分布・tokens の段・screenshot 画素
- 検収規則: UI 系 order の oracle へ S 番号を引用する。スコアは**設計時に生成器として**(置く前に位置・濃度・大きさを導出)、**検収時に評価器として**(柵)使う。反証可能 — 実測で満たせない場合は条件つきで本書を改訂する(黙って破らない)

## 種別の文法(全操作の4分類 — 住所の前提)

| 種別 | 定義 | 住所 |
|---|---|---|
| a. 視界状態 | 見え方だけ変える(Document・export 不変) | その視界の縁(常設 chrome) |
| b. 対象への動詞 | Document を変える・対象が特定できる | 直接操作 > 対象右クリック > Inspector |
| c. 大域動詞 | 対象なしで Document を変える | メニュー+ショートカット |
| d. セッション既定 | 起動を跨ぐ | Settings |

既知の構造的欠落(κ FINDING 2/3): メニューバーと右クリック基盤が不在 — b の中段・c の片方は現状代替(header ボタン+ショートカット)で埋める。基盤の新設は別 campaign。

## S0. 慣習段差(支配項・辞書式最優先 — 利用者裁定)

**Motolii の入口種別は、先例多数派の入口種別と一致しなければならない。** 期待分布= normal-map の entries 列(menu:shortcut:panel:pref)。S1〜S5 の幾何・視覚最適は S0 適合の**内側でのみ**探索する — どれだけ Fitts が良くても慣習に反する置き場は却下。

- 意図的逸脱は**裁定文書がある場合のみ合格**(拘束7(a) の型)。機械は旗を立てるだけ、判断は裁定へ
- 先例が割れている行(両論併記)・出典が薄い行(freq1・M/S/L の menu 偏重疑い= κ EVIDENCE_GAP 3)は自信度を下げ、裁定へ回す

## S1. 到達コスト(住所+大きさの統合)

`コスト = log2(距離/寸法 + 1)`(Fitts)。距離=直前の操作の入口から、寸法=ヒットターゲット実寸。

- **ヒット寸の下限柵**: 12×12px — **Motolii 実測由来のドメイン固有値**(キー菱形 hit の実績)。ISO 9241-411 の 9mm・Apple 44pt・Material 48dp は**タッチ規格でありマウス精密操作の根拠にならない**(裁定164/ξ 調査 — 誤借用の柵)。**見た目の主張とヒット領域は分離してよい**
- 分岐点数の上限は Hick-Hyman(`RT ≈ 200ms + 150ms·log2(n+1)`)で秒予測(巡回ボタンの選択肢数が増えたら dropdown 化する分水嶺の算出に使う)
- 違反ランキング= freq(normal-map)× コスト の降順。入口なし=コスト∞(最上位)
- 第2波候補: Accot-Zhai steering law(`T = a + b·A/W` — 細いレーン内ドラッグの経路コスト)

## S2. 工程動線(KLM 秒数 — 裁定164 で「距離の和」から格上げ)

正準ワークフロー(素材ドロップ→配置→トリム→キー→再生確認→書き出し、を初期セットとし利用者の実感順路で上書き可)ごとに、**KLM(Card, Moran & Newell 1980)の演算子秒数で予測時間を出す**:

`T = ΣP(ポインティング 1.1s) + ΣK/B(打鍵・クリック 0.2s) + ΣH(マウス⇄キーボード持ち替え 0.4s) + ΣM(思考準備 1.35s)`

ペイン跨ぎ=P、修飾キー併用=K、入力切替=H、判断点=M(挿入規則は KLM Rule 0-4)。「このワークフローは何秒かかる設計か」が置く前に出る。方向反転回数は補助指標として残す。

KLM は**儀式の見える化**でもある(利用者洞察 2026-08-21): AE の null 作法のような「意図の前の準備操作」(補助オブジェクト作成・命名・親子付け・組み方の思考)は M+P+K として全部計上される。ユーザーが直接意味を選べる動詞設計との差を秒数で比較できる — 将来の parent/rig 系設計の判定レンズ(直接意味選択 > 準備物経由、を定量で守る)。

## S3. 視覚動線

screenshot 画素から判定。**基盤は自前の重心・分散でなく確立指標を使う**(裁定164): 第一候補 Rosenholtz **Feature Congestion / Subband Entropy**(2007、公開ツール有)、代替 Miniukovich & De Angeli の8指標(CHI 2015 — clutter・figure-ground contrast・contour congestion・grid quality・white space)。「注意の重みが意味のある場所(選択・再生位置・ヒーロー)に集中しているか」= clutter スコア+強調位置の照合。**F/Z パターンは反証済みにつきプライアとして採用しない**(NN/g 自身の訂正)。Itti-Koch saliency はオフライン計算可能な注意予測の第2波候補。

## S4. 視覚重み写像(大きさ・濃度の生成規則 — 「ビタイチ」の核)

**視覚的主張 = 視覚発見への依存度に比例させる**:

```
発見依存度 = (1 − shortcut/直接操作の期待比率(S0 分布から)) × 頻度補正(初回発見の重み)
```

導出した重みを**連続値でなく tokens の段へ量子化**する(調和の実体は黄金比でなくモジュラースケールの一貫性):

| 重み | 段 | 例 |
|---|---|---|
| 高(視覚発見が主経路) | 行高段(20px 級)+ ink 強 + ラベル | Browser の素材カード、Inspector の値セル |
| 中 | glyph 段(12〜16px 級)+ ink 中 | M/S/L、レーンバー glyph |
| 低(shortcut/直接操作が主経路。入口は存在表示+初回発見用) | text 段(body_text)+ ink 弱(muted) | Undo/Redo、1/2 プレビュー表示 |

- **段の数値定義= WCAG コントラスト比**(裁定164、W3C 導出式 `(L1+0.05)/(L2+0.05)` を逐語確認済み): ink 弱≥3:1・中≥4.5:1・強≥7:1(対背景)。screenshot 画素から機械判定可
- 柵: **新規 UI は tokens の段以外の寸法・濃度を使えない**(裁定142 新色ゼロと同型)。**意味役割が新しい時は段の借用でなく新ロールを起こす**(市松が surface 対を借りて不可視化した実測 2026-08-21 の教訓)
- 「黄金比のような何か」の実体= **比率の一貫した反復(モジュラースケール)**。特定値 1.618 の優位を示す研究は無く、隣接領域では反証あり(ξ 調査)— 黄金比そのものは導入しない
- 概念の学術先行: information scent(Pirolli & Card 1999)—「発見依存度」は情報採餌理論の獲得コスト概念と同型
- 帰結の実例: Undo は shortcut 多数派(3:3)→ 重み低 → 薄いボタン → 薄い物の家(header)へ自然集約。1/2 プレビューは稀操作×常時状態表示 → text 段 ink 弱のクリック可能な現在値表示

## S5. ヒーロー構図(pane 相対の情報設計 — 利用者提起 2026-08-21 夜)

**各 pane は「ユーザーが何をしにここへ来るか」からヒーロー(主役)を逆算確定し、残る全要素はヒーローの補完として縁に退く。** pane はジグソーのピース — ヒーロー+補完情報で1つのまとまった情報になり、ピースの縁同士が組み合って全体の UX になる。

| pane | ヒーロー | 補完(縁の住人) |
|---|---|---|
| Stage | 合成結果の絵そのもの | 下縁=状態帯(倍率・解像度 1/2・市松 — 「どう見えているか」の説明列。AE 下端列と同型= S0 適合)。overlay は状態表示のみ(選択枠・カメラ金枠)、操作 chrome をヒーローの内側に浮かべない |
| Timeline | 時間構造(bar・キー・playhead) | 左縁=レーンバー、上縁=ルーラー(どちらもヒーローの座標軸) |
| Inspector | 選択対象の値 | section 見出し・ident 帯(値への案内) |
| Browser | 素材群(カード grid) | 左縁=rail、上縁=filter |
| Settings | 設定一覧それ自体(d の家) | ― |
| header/transport | pane ではなく**世界の縁** — 重み低の物の家 | ― |

機械柵:
- **S5a ヒーロー占有率**: pane 面積に占めるヒーロー領域の下限(初期値: Stage 90%・Timeline 80%・Browser 75%・Inspector 70%)。**外部定数は存在しない(ξ 調査で確認)— 実測較正が正**。較正法: 実プロ NLE の screenshot から density/white-space 指標の percentile を測る(輸入でなく実測)
- **S5b 濃度序列**: pane 内の最大 ink/コントラストは**ヒーロー領域内**(またはヒーロー上の選択 ACCENT)にのみ許す。縁の chrome がヒーローより目立ったら違反 — screenshot 画素で機械判定
- **S5c 二重発話禁止**: 同じ情報を2つの pane が同じ重みで主張しない(Q5 単一の真実の視覚版)。台帳判定

## S6. 非隠蔽(Ableton 原理 — 利用者裁定 2026-08-21 夜、S0 と並ぶ公理)

Motolii は Ableton フォロワーであり、Ableton の情報密度が「読める」理由は**目的ごとに触れる部分が隠れていない**ことにある。反例= FL Studio(右クリックへの機能格納=隠蔽)。目標: 一目でどこを触ればいいか分かる(動画編集ソフトの踏襲=前提)から一歩踏み込み、**一目でどこを触れば欲しい情報・状態が得られるか分かる**状態へ。

1. **状態は隠れない**: ユーザーが欲しい情報・状態は、パネルを開く/メニューを掘る/右クリックする前に、表面のどこかに常時見えている(低重み= S4 の text 段 ink 弱でよい — 見えていることが要件、目立つことではない)
2. **唯一の入口を隠し場所にしない**: 右クリックは悪ではない(利用者訂正 2026-08-21)— 対象の動詞群を対象のそばに集める正当な家であり、Ableton 自身がクリップ右クリック(quantize・色割当等)で好例を示す。種別 b の住所階梯に右クリックが入っているのはそのため。禁じるのは「**そこにしか無い**」こと: ワークフローを定義する機能や状態が右クリック・メニューの奥に**のみ**存在する構成(FL Studio の失敗)。可視の表面入口・標準ショートカット・状態表示のいずれかが必ず併存する
3. **隠すより、小さく薄く全部見せる**: 密度は敵ではない — S4 の段量子化が密度を秩序に変える(Ableton の密度はこの秩序があるから読める)

機械化: 入口台帳へ「唯一の入口」列 → menu/右クリックが唯一なら違反 fence。状態台帳(再生中・実効プレビュー解像度・市松・観測中・blend mode 等)→ 各状態に表面の常時表示があるかを fence。κ FINDING 4(観測カメラの痕跡ゼロ)はこの公理の違反第1号として状態帯で解消する。

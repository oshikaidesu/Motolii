# AGENTS.md（アーカイブ）

> 2026-08-19にroot入口から退役したrepo固有agent規則。歴史記録であり、現行のagent指示ではない。

このファイルはrepo固有の最小入口である。時点依存の進捗、model名、運用手順、歴史説明は置かない。

## 常時規律

- **依頼境界**: 利用者の依頼が許可範囲。相談・説明・観察・レビュー・診断・計画はread-onlyとし、編集、build/test、外部LLM、Git統合へ進まない。実装・修正・変更の依頼では、その成果に必要な変更と直接関係する検証だけを行う。skill、finding、test、reviewは権限を増やさない
- **現在地**: [CANON](../../CANON.md)、current code/tests、該当する決定文書を現在値とする。日付付き履歴やhandoffを現在値にしない。製品意味、公開API、永続形式を変える時だけ[decision index](../../decision-index.md)を主題で検索する
- **製品状態**: WIP、fixture、probe、test green、review、integration、製品完成を相互に読み替えない。完了時は変更、実際に通した検証、未検証範囲を分ける
- 利用者のdirty差分を保持する。明示依頼なしにreset、clean、stage、commit、push、mergeしない
- 危険、不可逆、外部公開、課金、依頼範囲の拡大を伴う操作は、利用者の確認なしに行わない

## 条件別に読む正本

- 製品UI、現在のshell、面ごとの視覚参照、起動・撮影は[CANON](../../CANON.md)
- core、render、plugin、persistenceへ触る時は[全体で守る規律](../../README.md#全体で守る規律コードレビュー最重視項目)と対象spec
- 外部LLMへ発注する時だけ[Launch card](../../llm-dispatch-observation-and-allocation-runbook.md#launch-card)
- build/testを回す、またはレーンへtargetを配る時は[ビルド運用](../../reviews/2026-08-19-build-speed-investigation.md)
- 歴史調査は利用者が明示した時だけcurrent authority確認後に行う

必要な正本だけを読む。通常の局所変更へrepo全体のbootstrapや正式な採択packetを要求しない。

## Motoliiの絶対規律

Document/single writer、GPU、色、座標、Preview/Export、plugin契約の詳細は[全体で守る規律](../../README.md#全体で守る規律コードレビュー最重視項目)が所有する。触る境界に該当する項目だけを適用し、入口へ複製しない。

## 計画と実装

- 現行の製品hostと新規機能targetは`motolii-shell-iced`。`motolii-blitz-shell`とegui製品UIはlegacy/referenceであり、明示依頼なしに製品機能を追加したりfallback先にしない。Timelineの視覚参照とRerun Stage島内のeguiは[CANON](../../CANON.md)の区別に従う
- icedのDocument編集は既存の`view → Message → Shell::update → UiIntent → ShellGateway/D2 → immutable snapshot`へ通す。第二のDocument/gatewayや迂回書き口を作らず、新しい編集操作は対応するiced drive/replay oracleで実結果まで確認する
- 新しい依存または横断機構を作る時だけ既存実装を先に探す。通常のhelperや局所修正を調査projectへ広げない
- test、golden、threshold、期待値を実装都合で変更してgreenにしない。oracleとの衝突は別のfindingとして報告する
- worktree、branch、Issue、commit、PR、main統合は依頼されたworkflowまたはtaskに必要な場合だけ使う。常時の完了条件にはしない

## 外部LLMと検収

利用者が「発注して」「並列エージェントに頼んで」など委任を明示した時だけ起動する。外部providerを使う場合の観測、scope、review、採否はLaunch cardから辿る。通常の「実装して」は自動委任を意味しない。

## 実装規約

既存の型、owner、error構造、resource lifetimeを保つ。公開/永続contractの変更、第二authority、新しい依存が必要になった時は、黙って広げず exact gap と選択肢を返す。

## 検証と完了報告

taskに直接関係する最小の検証を選ぶ。実行していないbuild、実機、UI、performance、platform結果は未検証と明記する。

# 構成

絵の経路は [one-day.md](one-day.md) が新しい。この文書の Rerun は、その計画では使わない。

検査と実装の前に置く、技術の理想。今のソースの説明ではない。
何を作るかは [concept](../concept.md)、設計の物差しは [ideal](ideal.md)、コードで確かめた境界の記録は [technical-boundaries](../product/technical-boundaries.md)。

## 一言

モーショングラフィックスを、手で作る。絵は一種類ではない。作品の意味（層、時間、キー、Undo、親子）は Document が持つ。文字、形、点群、ガラス、動画の中身は、一つのカメラの空間に同居する。

## 並び

同居させる空間は、いま Rerun の Spatial3DView が一つ持っている。点、ガウシアン、メッシュ、そしてカメラ投影の下に置いた画像と動画が、同じビューに出る。

| 種類 | 空間に入る形 |
|---|---|
| 点群、ガウシアン | そのビューの `Points3D` と `GaussianSplats3D` |
| 動画の中身 | ffedit がビットストリームを書き換えた結果を、そのビューの動画かメッシュのテクスチャにする。書き戻せるのは MPEG-2 と MPEG-4 Part 2 |
| 文字、形 | そのビューのメッシュか画像にする。Lottie の再生を別窓にしない |
| ガラス | このビューのメッシュに、屈折と厚みは無い。Filament の glTF 透過は、まだこの空間の外 |
| 窓 | Flutter。作品の正本は持たない |

## 規則

- 種類が違っても、カメラと奥行きは一つ。別の窓へ分けない。
- その空間を替えても、層と時間は残る。
- 覗く操作は作品を変えない。書き込みは Intent だけ。

## 検査

並列の検査は、種類の違う絵が一つのカメラの空間に居るかを見る。別窓へ分かれたものを、完成として採用しない。

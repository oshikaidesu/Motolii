レビュー前の計画。2026-10-04。参考画で確定したのは、速いガラスでは欲しい透明体が出ない、ということだけである。実装の記録ではない。今のソースの説明でもない。A0、B、A1 は macOS で通った。salsa 0.28.5 の採用は確定した。五つの測りの記録はこの文書にある。`frame_graph` は移さない。基盤探しは終わった。到達点は、動画・画像・ベクトル・文字・Lottie・3D・ガラス・Gaussian・Datamosh が一つの時刻と一つの空間に混ざることである。2026-10-05 の実機は、立方体・動画カード・文字カード・Gaussian が一つのカメラを共有し、ガラスの中心はそのカメラで投影した点である。文字の z が動画カードを前後に抜ける。動画は H.264 の最初の IDR だけを残し、後の IDR を外し、P を重ねた列を VideoToolbox が復号している（IDR 1 保持、4 破棄、P 55 反復）。時刻の引数は `frame(t)` で、時計はまだ glue のループである。Document のスクラブと保存はまだ繋いでいない。

外部の LLM が、この文書だけで突けるように書いた。[composition.md](composition.md) の「Rerun が空間」は、この計画では使わない。[AGENTS.md](../../motolii/AGENTS.md) の「書く範囲」のうち、絵を CPU の一枚で受け渡す部分も、この計画では使わない。層と時間を Document が持つ、という軸は残る。

## 範囲

この計画は、A/B の合成と GPU の接着である。Motolii 全体の評価モデルを置き換えない。

A0、B、A1 は通った。その合否に、Camera もノード評価器も入れない。避けるのは、将来の Evaluation 層を潰す不可逆な設計だけである。

前提は、ノード評価による最小の再評価である。変わったものだけを、もう一度評価する。その評価器は自作しない。

Document は作品の意味を持つ。意味の評価は salsa を採る。採用は確定した。2026-09-24 の最新は 0.28.5（Apache-2.0 OR MIT、まだ 0.x）。tracked function が実行中に読んだものが依存になる。入力が変わっていなければ再計算しない。再計算しても結果が同じなら、その先へ伝播しない（backdate）。循環は `cycle_result` で打ち切れる。スクラブの中断は `CancellationToken`（0.26 以降）がある。新しい機能は、入力と、そこから求めるクエリである。

時刻はクエリの引数にする。データベース全体の入力にしない。入力にすると、再生ヘッドが動くたびに全クエリが汚れる。時刻を読まないクエリ（不変のジオメトリ、カメラを読まない 2D）は、カメラや別の時刻が変わっても再計算しない。

今の `frame_graph` は移植しない。文書の改訂ごとにトポロジを一度組み、同じノードは再利用する。毎フレーム作り直してはいない。ただし依存は `NodeKind` と各 program が辺として先に書く。`SceneProgram::compile` がその列である。実行時に別時刻を足す `dynamic_inputs`（層の時計、lookbehind、粒子の前フレーム）は、salsa では同じクエリを別の時刻で呼ぶだけである。`GpuScene` は意味の中にあり、カメラを入力に取る。このグラフは、凍結した絵の経路と一緒に残す。

salsa が返すのは `GpuExecutionPlan` までである。接着の試験には入れない。五つの測りは、この節の記録である。絵の経路（`engine` と `compositor` の読み戻し）は延ばさない。

wgpu は `GpuExecutionPlan` を command に符号化して submit する。submit、デコード、テクスチャは salsa のクエリにしない。salsa が再評価不要と判断しても、画面は毎フレーム描くことがある。この壁は崩さない。クエリは決定的である。

クエリは粗く始める。`position_x` のようにプロパティを一つずつ tracked query にしない。1000 層 × 50 プロパティを独立にすると、依存の台帳自体が重くなる。最初の粒度は `sample_transform(layer, t)`、`sample_appearance(layer, t)`、`evaluate_layer(layer, t)`、`evaluate_composition(comp, t)`、`build_gpu_plan(comp, t)` である。割るのは、実測のあとである。

A0、B、A1 のあとの salsa スパイクは、次の五つだけを測って採否を決める。①実行時間。②ピークメモリ。③release バイナリの増分。④消せた自前コードの行数。⑤新機能を足すときに手で書く依存の数。

スパイクの記録（macOS、salsa 0.28.5、2026-10-04、1000 層）。新しい意味の経路に採る。`frame_graph` は移さない。submit、デコード、テクスチャはクエリにしていない。同じ時刻の再評価は 0 回で、画面を出す回数は 2 だった。カメラを変えても transform は 0 回で、計画だけが 1 回走った。循環は `cycle_result` で戻った。`CancellationToken` の cancel は捕捉できた。親子を足したとき、手で書いた辺は 0 本である。親を変えると transform は親と子の 2 回だった。

①初回 1.047ms。別の時刻 0.902ms（各クエリ 1000 回）。一層の編集 0.265ms（transform 1 回）。同じ時刻を 30 回 0.006ms。30 時刻の連続は 21.073ms。メモの無い同じ計算は 0.051ms。増分の台帳は、初回は素の計算より遅い。同じ時刻と、一つの編集で取り返す。②ピークは、同じ時刻の反復が 2.8MB、30 時刻の保持が 19.8MB、メモ無しが 1.3MB。時刻を全部残すと、メモリは時刻の数に比例する。再生で要らなくなった時刻は捨てる。捨て方は次の実装で測る。③release は 435,136 バイトから 1,092,784 バイト。増分は 643KiB。④消せた行は 0。凍結した `frame_graph` は 9293 行のまま。台帳の核（scheduler、topology、compiler、cache、evaluate、key）は 1051 行。家の意味の計算は、まだ移していない。⑤家のグラフは `NodeKind` が 51、`compile` が 26、`dynamic_inputs` が 14。スパイクで親子を足したときの辺の追加は 0。

時刻を引数にすると、中身がその時刻を読まなくても、その時刻の初回は実行される。`sample_appearance` は opacity だけを読み、別の時刻で 1000 回走った。同じ引数の二回目は走らない。プロパティ一つのクエリにはしていない。

軽さは、依存を減らすために自作することではない。一般の問題は小さな専門ライブラリへ渡し、Motolii 固有のコードを減らす。バイナリに加え、保守量、LLM が読む量、バグの面積を含めて軽い。

実装の前に、同じ責務だけを解いている小さい既存を探す。責務が合う部分だけを比べて奪う。製品全体は採らない。近い思想の compositor を、Motolii の合成器にはしない。既存があるから採る、にはしない。Motolii 側がすでに薄く、所有まで合っていれば、自前を残す。

`frame(comp, t, target)` を、全レイヤーを毎回上から直接評価する仕組みとして固定しない。その日の呼出の形である。中で何を再評価するかは、後の Evaluation が決める。

Camera は、ガラスやガウシアン固有の状態にしない。要る時点で、Motolii 共通の依存入力として定義する。Camera が変わっても、動画のデコード、不変のジオメトリ、無関係な 2D 層まで再評価しない。

ガラスやガウシアンが、独自のシーングラフ、カメラ、dirty、キャッシュを持ち始めたら止める。既存レンダラーを土台にした問題の再発である。

## 一文

モーショングラフィックスを、一つの GPU のメモリの上で作る。層と時間だけを書き、絵はそのメモリのテクスチャに描く。ピクセルの GPU から CPU への読み戻しは 0。最初の一時間は macOS で接着を確かめ、その後に並列の LLM がファイルを分けて進める。

「同じ `wgpu` デバイス」ではない。Rust の `Device` と、wgpu-native の `WGPUDevice` は別の状態である。VRAM の上に両方あることは、ゼロコピーではない。

## 完成

その日の合否は、一つのタイムラインで、動画、画像、図形、文字、Lottie、変形、ブレンド、薄いガラスを、キャッシュの中でスクラブでき、ハードウェアデコードの絵が GPU のまま画面に出ること。

冷たいシークは合否に入れない。長い GOP の任意位置は、前のキーフレームからデコードし直すため、数十から数百ミリ秒かかることがある。デコード 1.0ms は、順方向の再生と、キャッシュに当たったスクラブだけである。

ガウシアン、データモッシュ、ガラスの見た目はスパイクである。その日に未完でも、レンダラーは失敗していない。作品の範囲からは外さない。同じ GPU メモリに入り、画素の読み戻しが 0 のときだけ、常時の経路へ足す。スパイクの優先は、ガラスの見た目、ガウシアン、データモッシュの順である。

プレビューはリアルタイム。動画、文字、Lottie、合成、速いガラスは 120fps（8.3ms、1080p）を狙う。この数値は計測値ではない。ガラスの見た目に、別の fps は先に与えない。8.3ms に入るかは、作ってから測る。クロスプラットフォーム。バイナリは小さい。

コミュニティは AviUtl。手順は手の数で、実装量とは別である。

## 前提

デコード後の画素と、レンダー済みの画素について、別の allocation へのコピーを接着の手段にしない。共有できる同一 allocation を参照するか、同一のネイティブデバイスの上で扱う。GPU の内部コピーをするときは、キャッシュへ残すなど目的を書き、測る。CPU から見える画像への読み戻しは 0 である。

文書、ビットストリーム、ユニフォーム、コマンドのエンコードは、CPU にあってよい。静止画、フォント、ThorVG の頂点を CPU から GPU へ送るのも、これに含まれる。インポート済みの動画フレームを、毎フレーム CPU から送り直さない。

GPU 内のパス数は、描くために要る最小限。パスを 1 本に固定しない。読む合成の書きは GPU 上で、CPU 転送ではない。予算の合成の行に数える。

別デバイスから渡すときは、同じ physical allocation を複数の API が参照し、所有と同期が取れていることである。VRAM にそれぞれコピーがある状態は、これに入らない。試験 B で調べる接着の候補は三つ。(1) wgpu-native の C API に寄せる。(2) 同じ `MTLDevice` から両方を作る。(3) 別デバイスのまま同一 allocation を共有し、同期する。どれを採るかは、試験 B の記録で決める。(1) は、取り込みが Rust の `wgpu` の上にある。

窓は、今の Flutter である。タイムラインもスクラブも、そこにある。絵は Flutter が描かない。プレビューの面は、レンダラーが持つ `IOSurface` の輪で、Flutter は書き終わった面を GPU 上でサンプルするだけである。画素を CPU から Flutter へ渡さない。

デコードからレンダーまでは、OpenGL と D3D11 を使わない。Flutter への表示に限って、その OS の埋め込みが要求する API への共有を許す。Linux は DMA-BUF を Flutter の EGL が読む。Windows は D3D12 から D3D11（ANGLE）への共有ハンドルである。これは取り込みの移植ではない。

## 常時動くもの

1. 文書。層、イン、アウト、キー、親子、Undo。親子は描く前に数値へ焼く。GPU は親子を知らない。
2. ハードウェアデコードを、OS の GPU ハンドルのまま、同じ GPU メモリのテクスチャにする。
3. ThorVG が、層テクスチャ L へ図形、文字、Lottie を描く。L を合成が現在の書き先へ重ねる。
4. z 順に層を回り、層ごとに経路を選ぶ。変形、透明度、ブレンド、薄いガラス。
5. スクラブは `frame(comp, t, target)` を 1 回呼ぶ。キャッシュに無い動画は、この呼出の予算に入れない。

ガウシアンとデータモッシュはスパイク。別の窓は開かない。

## 契約

```text
frame(comp, t, target)
```

`comp` は文書。`t` は時刻。`target` は、コンポジションの解像度で確保した A、B、L、深度である。ウィンドウの大きさでは作り直さない。コンポジションの解像度が変わったときだけ作り直す。生成は `frame` の外である。この呼出は、全レイヤーの毎回の直接評価ではない。再評価の範囲は、上の「範囲」に従う。

`frame` はコマンドを積む。ThorVG は自分のキューへサブミットする。サブミットは、描き終わりを意味しない。キューが別なら、実行順はサブミット順ではない。

連続した図形の層は、一つのキャンバスにまとめてから一度サブミットし、そのあと L を `current` へ重ねる。動画や読む合成が間に入ったら、そこで区切る。L の枚数は、試験 B の前に固定しない。キューが同じなら一枚でよい。キューが別なら、L を二枚にして交互に使ってよい。塊ごとに、ThorVG が書き終える待ちと、合成が読み終える待ちがある。待ちの方法と時間は、試験 B が記録する。

デコードしたサーフェスのインポートは、サーフェスのハンドルをキーにしてキャッシュする。生成は `frame` の外で行う。デコーダのプールは小さいので、キャッシュへ残すフレームは、自前のテクスチャへ GPU 上でコピーしてからサーフェスを返す。このコピーは接着ではない。デコーダのプールを返すための、目的を書いた GPU 内部コピーである。デコードの行に数える。

戻り値で絵を運ばない。`Vec<u8>` の RGBA、エンコードしたファイル、別プロセスの窓は、絵の受け渡しにしない。

## フレームの中

固定するのは、種類の順番ではない。確保と、現在の書き先である。層は z 順に混ざる。文字の上に動画、その上に乗算、その上に図形、があり得る。

A と B は対称な作業バッファである。どちらも ThorVG 専用ではない。現在の書き先を `current`、もう一方を `other` とする。開始時の `current` は A。

```text
current ∈ {A, B}
連続した ThorVG は L にまとめて描き、サブミットしてから current に重ねる
quad と source-over は current に描く
全画面の読む合成は、current をサンプルして other へ全画面で書き、入れ替える。事前のコピーはしない
局所の読む合成は、`current` を入力にする。矩形の外を残す最小の経路は、測って決める。A を固定して解かない。あとも `current` は完全な一枚である。経路が決まるまでは、全画面の読む合成で描く
```

L を `current` の target にしない。ThorVG は target を上書きし得る。図形のあとに乗算があり、そのあとに Lottie があるとき、Lottie は再び L に描き、そのときの `current` へ重ねる。`current` が B なら、重ね先は B である。

| 層 | 経路 |
|---|---|
| 動画、画像 | インポート済みテクスチャを、`current` へ四角で描く。YUV は、その四角のシェーダがプレーンをサンプルする。変換だけのパスは足さない。8bit、BT.709、リミテッド |
| 図形、文字、Lottie | 連続する層は一つの ThorVG にまとめる。境目でサブミットし、L を `current` へ重ねる |
| source-over | `current` へ、One / OneMinusSrcAlpha で描く。書き先を読まない |
| 描き先を読む合成 | 乗算、スクリーン、オーバーレイ、差分、薄いガラス。全画面なら `current` をサンプルして `other` へ書き、入れ替える。局所は、経路が決まるまでこれと同じ全画面で描く。入力は、そのときの `current` |
| ガウシアン（スパイク） | 合格した色と深度へ、ラスタで描く |

全画面で書いたうえで、さらに全画面コピーはしない。メモリの往復が二回になる。読む合成が合成の 1.0ms を超えたら、枚数とミリ秒を残す。枚数の上限は、測る前に置かない。

source-over の書き先は A に固定しない。全画面の読む合成のあと、`current` は入れ替わっている。続く層も、局所の読む合成も、その `current` を読む。

その日のガラスは、速いガラスだけである。現在の色を画面空間で 1 回サンプルする。ぼかしは入れない。参考画の厚い透明体は、見た目のスパイクである。方式と fps は、そのとき測って決める。

最後に、コンポジションの背景色の上に A を重ね、アルファを 1 にしてから、レンダラーが持つ `IOSurface` の輪へ出す。輪は `CVPixelBufferPool` で、上限は 3 枚である。`on_submitted_work_done` が返った面だけを Flutter に渡す。Flutter に渡した `CVPixelBuffer` は、Flutter が離すまでプールから払い出されない。これを使用中の判定にする。空きが無いフレームは出さずに飛ばす。出力の輪のテクスチャキャッシュは `IOSurface` をキーにし、`CVPixelBuffer` を保持しない。デコード側は、`CVPixelBuffer` を GPU の完了まで保持する。保持しないのは出力の輪だけである。Linux と Windows も、埋め込みの解放通知か同じ輪で、同じ規則を守る。マップして CPU へ読まない。画面に出るのは、少なくとも 1 フレーム遅れる。見える fps は、レンダラーと Flutter のラスタのうち遅いほうである。

## スクラブ

順方向の再生は、ハードウェアデコードのまま次のサーフェスをインポートする。予算は 1.0ms。

スクラブは、GPU 上のデコード済みキャッシュをサンプルする。キャッシュの範囲ではデコードしない。持つのは NV12 のプレーンである。1080p の 1 枚は約 3MB で、全部の動画層で共有する上限は 1GB である。層が二枚なら、それぞれ約 2.7 秒である。捨てるときは、再生ヘッドから遠いフレームから捨てる。先読みは、そのストリームの並べ替えの深さに 1 を足した枚数以上である。2 枚固定にはしない。

キャッシュに無い時刻は、先にデコードしてから自前のテクスチャへ GPU コピーし、サーフェスをプールへ返す。このフレームは 8.3ms の合否に入れない。終わったあとの再生と、同じ範囲のスクラブが予算に入る。

全 I フレームのプロキシは、その日の必須にしない。キャッシュで足りない長さは、スパイクのあとで足す。

## 同期

サーフェスをいつ読んでよいか、いつ返すかは、OS ごとに書く。

| OS | 同期 |
|---|---|
| Linux（VAAPI） | `DmaBufLease` とフェンス。タイル配置は `VK_EXT_image_drm_format_modifier` と modifier の一致。取り込みは `wgpu-external-frame` |
| Linux（Vulkan Video） | 同じ `VkDevice` の `VkImage`。同期は FFmpeg のフレームが持つタイムラインセマフォ |
| macOS の取り込み | `CVMetalTextureCache`。渡す `MTLDevice` は、wgpu が使っているものから取る。`CVPixelBuffer` は `on_submitted_work_done` まで保持する。`wgpu-external-frame` は経由しない |
| macOS の表示 | レンダラー所有の `IOSurface` 輪。書き終わった面だけ Flutter がサンプルする |
| Windows | D3D12VA は wgpu と同じ `ID3D12Device`。出力は HAL の生テクスチャとして包む。同期は FFmpeg のフレームが持つフェンス。共有 HANDLE は使わない |

## 使用技術

### wgpu

バックエンドはプラットフォームごとに一つ。

| OS | バックエンド |
|---|---|
| Linux | Vulkan |
| macOS | Metal |
| Windows | D3D12 |

OpenGL は取り込み先にしない。

可搬な外部メモリ API は、2026-10-04 時点で wgpu#2320 が開いたままである。`ExternalTexture` は wgpu-core に入っている（PR 7823、2025-07）。HAL と Naga が揃った可搬 API ではない。NV12 の機能はある。macOS のバックエンドは Metal で、Metal にマルチプレーンのテクスチャ形式が無い。NV12 を一枚のテクスチャとしては扱わない。プレーンごとに取る。取り込みクレートは、その日も使う。

### wgpu-external-frame 0.1.1

GPU がすでに持っているフレームを、CPU を通さず `wgpu::Texture` にする。2026-10-04 に crates.io の 0.1.1 を確認した。

このクレートを使うのは、Linux の VAAPI だけである。DMA-BUF を、`VK_EXT_external_memory_dma_buf` と `VK_EXT_image_drm_format_modifier` で取る。

macOS のデコードは `CVMetalTextureCache`、Windows のデコードは同じ `ID3D12Device` の生テクスチャ、Linux の Vulkan Video は同じ `VkDevice` の `VkImage` である。

`EGL_LINUX_DMA_BUF_EXT` は、デコードの取り込みには使わない。Flutter へ表示するとき、Linux ではこの経路で DMA-BUF を EGL が読む。

使うのは `DmaBufFrame` だけである。`IoSurfaceFrame` と `SharedHandleFrame` は使わない。

同じ役割の別クレートに `wgpu-native-texture-interop` がある。Linux / Android と macOS / iOS は実装済み。Windows の Vulkan 経路は実装済み。Windows の D3D12 はビルドでき、実行時は未了、と書かれている。計画が名指しするのは `wgpu-external-frame` 0.1.1。

YUV はプレーンごとにテクスチャへ入れ、フラグメントシェーダで RGB にする。この変換は GPU 上の 1 ホップで、CPU コピーではない。

### デコード

FFmpeg を、分離とハードウェアデコードにだけ使う。`libavfilter` には合成させない。

| OS | デコーダ | メモリ |
|---|---|---|
| macOS | VideoToolbox | `CVPixelBuffer` / `IOSurface`。最初の一時間はここだけ |
| Linux、VAAPI があるとき | VAAPI | DMA-BUF。modifier を一致させる |
| Linux、NVIDIA のプロプライエタリドライバ | Vulkan Video | `AVVulkanDeviceContext.act_dev` に、wgpu の生の `VkDevice` を渡す。video の拡張とデコードキューを、wgpu-hal で開く。DMA-BUF は要らない |
| Windows | D3D12VA | `AVD3D12VADeviceContext.device` に、wgpu の `ID3D12Device` を渡す |

NVIDIA のプロプライエタリドライバに、実用できる VAAPI は無い。Linux の穴は Vulkan Video で塞ぐ。

Windows で D3D11VA の `BIND_DECODER` 配列を `CreateSharedHandle` する経路は、使わない。通るかはドライバ次第である。D3D12VA にデバイスを渡すと、その一段は消える。NV12 への GPU コピーが残るなら、デコードの行に数える。

### ThorVG

図形、文字、Lottie、ぼかし、ドロップシャドウ。呼ぶのは C API。crates.io の `thorvg`（0.5 系）は、作者が本番前と書いている。Rust バインディングは使わない。

`WgCanvas::target` は、2026-10-04 にソースで確認した。`ColorSpace` が `ABGR8888S` でなければ `NonSupport`。`type = 1` のとき描き先は `WGPUTexture`。キャンバスは内部で描いてから target へ解決する。既存のピクセルが残るとは書かれていない。

試験 B の記録項目は、下の試験 B の表が正である。ここには重ねて書かない。描き先の色空間は `ABGR8888S` で、それ以外は `NonSupport` である。合成はレンダーパスで L をサンプルする。compute の storage にはしない。

Lottie のイージングは、Lottie の JSON を ThorVG が評価する。式が要るときだけ JerryScript（約 200KB）を足す。常時は足さない。

公表されている 120fps は CPU 経路である。Thor Janitor は 2048×1152 で、数万オブジェクトに DropShadow と Blur をかけて 120fps 以上。Godot の Web デモは、Lottie 数百個で 120fps 以上。CPU 比較では、5,000 個の半透明プリミティブ、2560×1440、Apple M2 Pro で、ThorVG 1.1 が Skia 148 の約 2.3 倍、と ThorVG が公表している。WebGPU 経路の同じ数値は、この文書の時点ではない。WebGPU は OpenGL バックエンドより平均約 1.8 倍、という内部計測がある（Apple M1、ThorVG のベンチマークアプリ）。

ThorVG の 2.0ms の行には、CPU の前処理と、頂点のアップロードが混ざる。

Skia（`skia-safe` 0.153、Skottie、Ganesh / Graphite）は採用しない。機能は足りる。バイナリが大きい。

### 合成

Motolii が書くシェーダは、ここだけに近い。入力はテクスチャ。各層の変形、透明度、ブレンドをユニフォームで渡す。ユニフォームのアップロードは、毎フレームあってよい。ピクセルの読み戻しではない。

`ff-render` 0.16 は wgpu の動画合成である。`RenderGraph::process_gpu` は RGBA のバイト列を上げ、`Vec<u8>` で下ろす。`Compositor::composite` は `wgpu::Texture` を返せる。`composite_to_rgba` は読み戻しである。この計画の依存には入れない。

`arniko-mustang` は Exosphere の UI 効果である。Vello の scene と wgpu 27 で、ぼかしと変形を GPU に出す。文書の zero-copy は、その scene を GPU に置くという意味である。専門 renderer を差し替える口ではない。すりガラスを製品にしている。依存には入れない。

`flutter_wgpu_texture` は、提示だけが A1 と同じ責務である。macOS は Flutter が `CVPixelBuffer` を割り当て、Rust がそこへ描く。A1 は描く側が 3 枚の輪を持ち、完了のあとだけ渡す。所有が逆なので、A1 をこれで置換しない。Windows の DXGI 共有と、Linux の DMA-BUF から EGL への提示は、表示を移植するとき比べる。Web は Rust が無く、この経路ではない。

ThorVG 1.1 の WebGPU テクスチャ描き先は、試験 B で使った。外部の GPU へベクトルを描くことは、上流の口と一致している。

モーショングラフィックスの全体を、この接着で組んだ既製品は、この確認では見つかっていない。部分はそれぞれ別の製品にある。

ガラスの前に一度だけ、消せる責務を探す。これが基盤探しの最後である。終わったら、部品探しは止める。次は Glass Beauty である。対象は Camera、picking、culling、GPU の allocation、テクスチャの相互運用、提示、シェーダの hot reload。名前を集めない。各責務を、次の四問だけで切る。

1. Motolii が持つ device と resource を受け取れるか。
2. scene graph、frame loop、提示まで奪わないか。
3. GPU から CPU への画素経路を要求しないか。
4. その責務だけ抜き出せるか。

見る範囲は、責務の核だけである。Camera は計算と操作。picking は ray と BVH。culling は frustum と visibility。allocation は resource allocator。相互運用と提示は native handle と同期。hot reload はシェーダの監視と再コンパイル。

結果は三つだけである。`ADOPT` は、そのまま小部品として使う。`EXTRACT` は、実装かアルゴリズムだけ借りる。`KEEP` は、Motolii の薄い自前の方が小さい。

ここまでで決まっているもの。salsa は `ADOPT`。`flutter_wgpu_texture` の macOS は `KEEP` で、Windows と Linux の提示は移植時の参考である。`ff-render` と Mustang は、合成器としては `KEEP` である。

棚卸し（2026-10-04）。これで基盤探しは終わる。同じ問いで再開しない。

| 責務 | 判定 | 理由 |
|---|---|---|
| Camera | `KEEP` | 射影と look-at は、既にある glam の数行である。`bevy_dolly` は Bevy の描画と窓を連れてくる。操作の rig が実際に要るとき見る先は `dolly` 本体だけで、今は足さない |
| picking | `ADOPT` | `parry3d` の `Bvh::cast_ray` は、呼び出し側の形状を受け取る。描画ループも画素の読み戻しも持たない。GPU の ID バッファ読み戻しは採らない。要るときまで依存は足さない |
| culling | `KEEP` | frustum の平面テストは、自前の方が小さい。多数のメッシュを省くときは、picking と同じ `parry3d` の BVH を使い、別の culling 庫は足さない |
| allocation | `KEEP` | wgpu 29 の Vulkan 側が、すでに `gpu-allocator` を使う。もう一度持つと、wgpu の device の外にメモリの持ち主が増える |
| 相互運用と提示 | `KEEP` | macOS は、A1 で測った輪と `on_submitted_work_done` が薄い。Windows の DXGI handle と Linux の DMA-BUF は、移植するとき `flutter_wgpu_texture` から手順だけ EXTRACT する |
| hot reload | `KEEP` | 監視は `notify`、WGSL の再コンパイルは既にある naga。`hotglsl` は GLSL から SPIR-V なので責務が違う。シェーダ枠は採らない |

この探索は、ガラスの見た目ではない。

### ガラス

速いガラスは、今描いた色を画面空間で 1 回読む。その日の合否は、これだけである。合成の 1.0ms に含める。見た目のスパイクとガウシアンへ進む前に、「範囲」の節を守る。独自のシーングラフ、カメラ、dirty、キャッシュは持たない。

参考画は、これでは出ない。確定したのは、それだけである。青と橙は、後ろのクリーム色を歪めたものではない。

見た目のスパイクは、参考画を基準にする。同じ GPU メモリ。画素の読み戻しは 0。物理の計算を忠実にはやらない。人が、厚い色付きの透明体だと感じる、いちばん安い描き方を探す。

ガラスの画面空間の屈折は、既にあるやり方に従う。シーンを先に描き、面の法線で一回サンプルし、Schlick と Beer–Lambert を掛ける。レイマーチはしない。ガウシアンのラスタは `wgpu-3dgs-viewer` 0.7。0.8 は wgpu 30 なので採らない。`Viewer::render` は色を黒で消すので使わない。前処理とソートのあと、`render_with_pass` で今の絵へ Load する。カメラはこちらの view と projection を渡す。

欲しい見え方は、次である。

- メッシュがある
- 色は物体が持つ。厚みで変わる
- 吸収がある
- 反射と環境がある
- Fresnel がある
- 縁に分散がある
- 屈折がある
- 強いハイライトがある
- リアルタイムで動く

最初に試すのは、ラスタと画面空間である。フレームの枠は、まず 8.3ms である。超えたら、項目ごとに何ミリ秒使ったかを残す。枠を緩めるのは、その表を見てからである。

二次レイは、この描き方では参考画に届かないと分かるまで、入れない。3DGRT の 52fps は、RTX 6000 Ada、1920×1080 の論文の値である。このソフトの fps にはしない。

Filament のエンジンはリンクしない。環境のキューブマップを一度だけ GPU へ送ることは、画素の読み戻しではない。

### ガウシアン（スパイク）

その日の合否には入れない。これは点群ではない。3D ガウシアンのラスタである。レイトレの一次レイではない。

方式は 3DGUT。歪んだカメラとローリングシャッターを、ラスタのまま扱える。CVPR 2025。

公表値。1920×1080、RTX 6000 Ada。3DGUT は 265fps 超。同じ比較の 3DGRT（レイトレ）は 52fps。Vulkan 版 VK3DGUT（`nvpro-samples/vk_gaussian_splatting`）は、表示時間を含めて測っている。メッシュ挿入もエフェクトも無い。

macOS のバックエンドは Metal で、VK3DGUT は Vulkan である。同じ GPU メモリへ描ける実装を、この文書は名指しできない。描けないプラットフォームでは、その層を出さない。

NVIDIA は、本番の CUDA 枠として gsplat（3DGUT 対応）を勧めている。gsplat は Python / CUDA で、この GPU メモリへのゼロコピーにならない。

3DGRT と 3DGRUT の二次レイは、ガラスの見た目がラスタで届かないと分かるまで、入れない。論文の 52fps は、RTX 6000 Ada、1920×1080 の値である。

### データモッシュ（スパイク）

その日の合否には入れない。GPU のグラフが成立することとは独立である。未完でも、レンダラーは失敗していない。

書き換えは CPU で行う。対象は圧縮された H.264 である。ピクセルの読み戻しではない。書き換えたバイト列を、上のハードウェアデコードに戻す。

`h264bitstream` が NAL の読み書きを持つ。公開 API は `h264_new`、`find_nal_unit`、`read_nal_unit`、`write_nal_unit`、`rbsp_to_nal`、`nal_to_rbsp`。行う改竄は、I フレーム（IDR）を外し、P フレームを重ねる、という既存の手順。

IDR を欠いた列を、ハードウェアデコーダが受け付けるかは OS と GPU で違う。VideoToolbox はエラーを返すことがある。`frame_num` や POC が壊れていると、受け付けないデコーダがある。スパイクの合否に、機械ごとの見た目の一致は入れない。

`ffedit`（FFglitch 0.10.2）と `ffmosh` は、ビットストリーム編集の API を持つ。対象コーデックは MPEG-2、MPEG-4 Part 2、MJPEG、PNG。`ffmosh` は H.264 を対象外と書いている。H.264 の動きベクトルを JSON で書き戻す経路は、この計画に無い。

Artsen の H.264 ツールと `datamosh-gui` は、手順の実例である。実行系としては使わない。

### 文書

Motolii が書く。層、イン、アウト、プロパティのキー、親子、Undo。書き込みは Intent だけ。z 順は層の順である。種類では分けない。

親子は、GPU に渡す前に子の変形へ焼く。図形アニメの補間は Lottie 側に残る。レイヤー変形の補間は、文書が時刻でサンプルし、ユニフォームにする。

### タイムライン

タイムラインは、今の Flutter を使う。ほぼ出来ている。スクラブは、その UI が `t` を変える。egui は足さない。

Flutter が描くのは、タイムラインと操作である。フレームの画素は描かない。プレビューは、レンダラーが渡した面をサンプルする。今の絵の経路（読み戻してウィジェットへ渡す）は、延ばさない。

8.3ms の行に、Flutter のラスタは入れない。観測として、Flutter のラスタ時間と、画面に出た fps は残す。行が全部合格でも、画面が 60fps に見えることはあり得る。スクラブ中は、再生ヘッドも毎フレーム動くので、Flutter も 120Hz で描き直す。

## 最初の一時間

六本を同時に始めない。合格させる OS は macOS だけである。三つの OS を一時間に入れない。作品にはしない。1 枚出て、ピクセルが CPU へ読まれていなければ合格。

| 試験 | 中身 | 合格 |
|---|---|---|
| A0 | VideoToolbox のフレームを取り込み、素の `CAMetalLayer` へ出す | 取り込みが画面に出る。Flutter はまだ絡めない |
| A1 | 同じ面を、Flutter の外部テクスチャで出す | 今の窓に出る。輪の面を、Flutter が使用中に上書きしない |
| B | L へ ThorVG が描き、合成がそれを A0 の面へ重ねる | 上の三候補のどれか。キューが同じか、待ちの方法と時間、L は一枚か二枚か。既存内容が残るか。形式と usage。サンプル形式が一致するか。半透明の白を黒の上に描き、縁が暗くならないか |

試験 B の記録（macOS、ThorVG 1.1.2、2026-10-04）。候補 (2)。`MTLDevice` の registry は同じ。キューは別。待ちは `tvg_canvas_sync` で、最初のフレームは 0.130ms。L は一枚。既存内容は残らない。白 50% は 128,128,128,128 で、乗算済みである。画面では、動画の上に橙の矩形と、その半透明の矩形が出た。

試験 A1 の記録（macOS、2026-10-04）。`MOTOLII_A1` のとき、今の Flutter 窓が外部テクスチャで同じ絵を出した。動画、橙の矩形、半透明の矩形は B と同じである。古い ProbeHost は入れない。輪は `CVPixelBufferPool` の 3 枚で、割り当て上限も 3。キャッシュの鍵は IOSurface で、出力の `CVPixelBuffer` は保持しない。Flutter へ渡すのは `on_submitted_work_done` のあとだけである。起動後、プール満杯のスキップは出ていない。Flutter が面を返しているので、使用中の面は上書きしていない。GPU から CPU への画素の読み戻しは、この経路に無い。

`device.poll` は A1 の合格条件ではない。この実験では、`CAMetalLayer` へ present しない経路で完了コールバックを進めるために必要だった。120fps の本番ループでは、これが CPU 側の同期点になっていないかを別に測る。

実装の注意。寸法は最初のデコード枠まで 0 である。その前に ThorVG のテクスチャを作ると落ちる。完了待ちは、present が無いとコールバックだけでは返らない。どちらも、通った実行では起きていない。失敗の記録ではない。

A0 が通ってから A1 に入る。失敗が取り込みか Flutter かを、混ぜない。A1 の Swift のプラグイン、Dart の面、Rust の FFI は、担当 2 が持つ。最初の一時間の合格は A0 と B である。A0、B、A1 は macOS で絵が出た。

読み戻しが無いことは、二つのことで示す。Metal フレームキャプチャに、CPU から見えるバッファへの blit が無いこと。作品の経路に `getBytes`、`IOSurfaceLock`、`CVPixelBufferLockBaseAddress`、`map_async` が無いこと。統合メモリでは、後者はキャプチャに残らない。L の既存内容は、既知の色で塗ってから ThorVG に描かせ、画面で見る。試験とタイムスタンプのための読み戻しは許す。作品の経路では許さない。

A0 と B が macOS で合格してから、ファイルを分けて並列にする。同じファイルを二本が編集しない。Linux と Windows のデコードは、同じ契約の移植である。表示は移植では済まない。デコードキューは描画キューと分け、FFmpeg と wgpu が同じキューへ同時にサブミットしない。

| 担当 | 持つもの | 終わった状態 |
|---|---|---|
| 1. 文書 | 層、キー、Undo、親子の焼き込み、z 順 | `frame` が読む `comp` が、CPU の画像を持たない |
| 2. デバイス | A、B、L、深度、輪のトレイト、macOS の実装 | 輪の持ち主はここ。A0 は `CAMetalLayer`。A1 の Flutter 側もここ |
| 6. 表示 | 同じトレイトの Linux と Windows の実装ファイル | デコードには使わない。Flutter がサンプルする共有だけ。EGL と D3D11 共有はここ |
| 3. デコード | macOS は VideoToolbox。続きは表のデコーダ | 試験 A0 が層として残る。キャッシュは自前のテクスチャ |
| 4. ThorVG | C API と L | 試験 B の表の項目が記録され、Lottie が L に描かれる |
| 5. 合成 | 現在の書き先、読む合成は一回の書き、薄いガラス | z 順が種類をまたいで保たれる。読み戻しは 0 |

スパイクは、空いた担当が触る。最初の一時間の合格は A0 と B である。その日の macOS の合否は、担当 1 から 5、A0、A1、B である。担当 6 は、Linux と Windows の表示である。

| スパイク | 終わった状態 |
|---|---|
| ガラスの見た目 | 参考画の透明体が、同じ GPU メモリで動く。まず 8.3ms を試し、超えた項目のミリ秒を残す。読み戻しは 0 |
| ガウシアン | 合格した色と深度へラスタが描ける。描けない OS では層を出さない |
| データモッシュ | 書き換えたバイト列が、その OS のデコードに戻る。見た目の一致は合否に入れない |

受け入れは、キャッシュ内のスクラブで絵が動き、ピクセルが CPU に現れず、下の行ごとに時間が見えること。全体の fps だけでは受け入れない。テストが緑であることは、その代わりにならない。

## 予算

1080p。目標値であり、計測値ではない。判定は、CPU の列と GPU の列のうち遅いほうである。二つの列を足して枠と比べない。

枠は 8.3ms（120fps）である。下の行は、その日の本体の目標である。ガラスの見た目は、この表の合成 1.0ms に押し込めない。先に 8.3ms の枠へ入れて試し、超えた項目の時間を残してから、枠を緩めるかを決める。16.6ms は、まだ契約ではない。

| 行 | どこで測るか | 目標 |
|---|---|---|
| 文書のサンプル | CPU | 0.3ms 未満 |
| ThorVG の前処理とアップロード | CPU | 2.0ms 未満。WebGPU では未計測 |
| ThorVG の描画 | GPU が働いた時間。待ちは含めない | 2.0ms の行とは別に出す。未計測 |
| 完了待ち | 壁時計。止まっている側の列 | CPU が完了を待つ時間は CPU の列 |
| デコードとインポート | 順方向と、キャッシュヒットだけ。壁時計。待ちを含める。完了待ちの行には入れない | 1.0ms 未満 |
| 冷たいシーク | 測るが、合否に入れない | 数十から数百ミリ秒があり得る |
| 合成と速いガラス | GPU。読む合成の書きを含む | 1.0ms 未満。コピーを別枠にしない |
| プレビューへの present | GPU が働いた時間。待ちは上の行 | 0.5ms 未満 |
| Flutter のラスタと、画面の fps | 観測。8.3ms の合否には入れない | 数値の目標は置かない |

デコードとインポートの行は例外で、壁時計で測り、待ちを含める。完了待ちの行には入れない。コピーが 0 でも、デコードの完了を待って 2ms 空いたら、この行は不合格である。

待ちは壁時計で測り、止まっている側の列に数える。CPU が完了を待つ時間は CPU の列である。タイムスタンプクエリは、GPU が働いた時間だけを測る。パスの途中のクエリは、バックエンドによって使えない。ThorVG の内部パスは、外から区切らない。

クエリの結果を CPU で読むのは、ピクセルの読み戻しではない。計測のために許す。

ThorVG の 2.0ms が最初に外れるなら、その行である。

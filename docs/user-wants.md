# したいことの語彙 — チュートリアルの見出しから採る

## なぜ採るのか

**実装に入る前に、1本作り切るまでに触る意味を、全部言葉にしておくため。**

意味が言葉になっていない所へ実装が入ると、私がその場で意味を作る。
今日1日で見た失敗(2D/3Dのモード、継承という新機構、振り直しボタン)は全部この形だった。
**語彙の穴が、私の作り話の入り口になる。**

私が機能から並べると、私の知っている物の裏返しにしかならない。
だから外から採る。

## 何を採り、何を採らないか

| 採る | 採らない |
|---|---|
| **したいこと**(動詞) | 機能名 |
| その意味が実在する証拠(誰かが金を払っている、何度も出てくる) | **解き方** —— Motolii の解き方は自分で決める |
| 頻度 | 網羅 |

**他所の解き方は「その意味が本当に在る」の証拠としてだけ使う。**
解き方を写すと、その道具の仕方なしごと写る。

## どこで止めるか

**新しい資料を1つ読んで、新しい動詞が0本だったら止める。**

そして1本ごとに問う —— **それは、3分の MV を1本作り切る間に出てくるか。**
出てこないなら大義の側([concept](concept.md) 目的の節)。後で採る。

## 出す物

この文書に行が増える。[gap](wiki/gap.md) に差が増える。**文書は増やさない。**
資料の要約はしない。1件1行で語彙に足すだけ。

---

機能名から並べると、私が知っている物の裏返しになる。
**利用者が口に出す言葉**は、チュートリアルの見出しに落ちている。
「〜したい」「〜の作り方」がそれで、本文は**その道具でそれをやる仕方なし**が書いてある。

採り方: 見出しから**したいこと**を抜き、本文から**何に変換させられているか**を抜く。
不満の体系は [ae-pain-points](ae-pain-points.md)。ここは欲求の側。

## 採れた分(第一回)

| したいこと | AE では何に変換させられるか | Motolii では |
|---|---|---|
| 文字を1文字ずつ出したい | テキストアニメーター + 範囲セレクター(専用の下位言語) | 番号の帯を時刻へ落とす |
| 手書き風に、書き順で出したい | **ペンツールで文字の中心を1本ずつなぞる** + 線 + パスのトリミング | 未決。**なぞらせない**形が要る |
| 図形を等間隔に繰り返したい | リピーター(図形専用の別機構) | 増やして番号でずらす |
| 音に合わせたい | **音をキーフレームの列に焼く** | 音の帯を属性へ落とす |
| 緩急をつけたい | グラフエディタ(別の面へ行く) | 区間の形を掴む |
| 立体に見せたい | **レイヤーを3Dに変換**してカメラを足す | 最初から空間に居る |
| 重くなったのを軽くしたい | プリコンポーズ → プリレンダー/プロキシ | グループをフリーズ |
| 同じ動きを他にも使いたい | プリセットに保存、または式 | 形を写す |
| 素材を差し替えたい | ⌥ドラッグで置換 | ⌥クリックで置換 |
| 動く物に貼り付けたい | トラッキング → **位置をキーフレームの列に焼く** | 未決 |
| 背景を消したい | キーイング / ロトスコープ | 未決 |
| 色を揃えたい | 調整レイヤーを1枚かぶせる | グループにエフェクト |
| 光らせたい・汚したい | エフェクトを掛ける | 同じ(Vism) |

## 読み取れたこと

**AE の「仕方なし」は、ほぼ全部が変換だった。**

音をキーフレームへ。文字をアウトラインへ。レイヤーを3Dへ。コンポをプリコンポへ。
形をなぞったパスへ。**元の意味のまま扱えないので、別の形に焼いてから扱う。**

焼くと3つ失う。

- **元へ戻れない** —— 焼いた後で元を直しても、焼いた物は追随しない
- **意味が消える** —— 焼いたキーの列は、もう「音」ではない。ただの数字
- **手順を覚える羽目になる** —— 焼く順番が正しくないとやり直しになる(→ 根底2)

これは機能の不足ではなく、**意味を意味のまま持てないこと**の症状。
Motolii の持ち物が「編集の意味」だけなのは、ここへの答えになっている。

## まだ採れていない

見出しにならない意味が抜けている。**探す・見比べる・やめる・戻す・渡す。**
チュートリアルは完成までの一本道を書くので、**迷いが記録されない**。
ここは外部資料では採れない。作りながら採る。

## 第二回 — 見出しにならない意味(英語圏の生の声とスクリプト市場)

チュートリアルは完成までの一本道しか書かない。**迷い・整理・比較・受け渡し**は
見出しにならない。それらは**掲示板の不満**と、**売れているスクリプトの名前**に落ちている。
第三者スクリプトが商品として成立していること自体が、
**ホストがその意味を持たなかった**という記録である。

| したいこと | 何で埋められているか | AE がそうさせる原因 |
|---|---|---|
| **案を番号で刻みたい** | Version Raptor 等の版上げスクリプト | 版という概念がホストに無い |
| **どこが違うか知りたい** | CompSolidate(同一コンポを見つけ、違うキー/層を指摘) | 2つを見比べる道が無い |
| **状態をいくつか持って切り替えたい** | Photoshop の Layer Comps を求める要望 | 1つの作品に1つの状態しか持てない |
| **複製を独立させたい** | Replicator(独立した複製を作る) | **プリコンポの複製は中身を共有してしまう** |
| **探せるように片付けたい** | Tidy / Organize Project Assets Pro | 素材が増えると見つからない |
| **緩急を見ながら決めたい** | 各種イージングスクリプト | グラフエディタに即時の反映が無い |
| **手を動かさずに動かしたい** | 各種エフェクター/式 | 駆動の口が無く、式へ追い出される |

## 読み取れたこと(第二回)

**1. 仕方なしが、仕方なしを生んでいる。**

版を1つ刻む手順は「プリコンポを探す → 複製する → ⌥ドラッグで戻して差し替える」の3手。
そのうえ**複製したプリコンポは中身を共有する**ので、独立させる別のスクリプトが要る。
プリコンポという仕方なしの上に、版のスクリプトと独立化のスクリプトが積まれている。

Motolii ではグループが層で、**層の複製は独立している**。この3つは同時に消える。

**2. 抜けていた動詞は「作る」ではなく「持ち歩く」側だった。**

探す・見比べる・刻む・片付ける・渡す。
どれも絵を1画素も変えないが、**実作業の時間の多くはここに居る**。
Motolii はまだ1つも持っていない。

**3. 「見比べる」が最も重い未決。**

2案を並べて、どこが違うかを見る。今の説明書のどこにも書けない。
根底6(偶然も値)は「同じ種なら同じ絵」まで保証するが、
**2つの結果を並べて置く**話は別に要る。

## 第三回 — 他所の道具が名前を付けている意味

日本語のチュートリアルは「作る」しか書かない。英語圏の掲示板と、
AE の外の道具(C4D・Houdini・Figma・Blender)には、**AE が名前を付けなかった意味**に
名前が付いている。名前が付いている = その意味が実在する証拠。

### 増やす・散らす

| したいこと | どこで名前が付いているか |
|---|---|
| **ここは強く、あそこは弱く効かせたい** | C4D の Field / Falloff。効かせる範囲を場所で決める |
| 順に現れさせたい | Step Effector(番号順にずらす) |
| **制御できる散らばりが欲しい** | 「controlled randomness」。偶然だが、狙って動かせる |
| **繋げて増やすか、切って増やすかを選びたい** | Blender の Link と Append。前者は元を直すと全部直り、後者は独立する |

### まとめる・片付ける

| したいこと | どこで |
|---|---|
| **1枚にせずに、層をまとめて片付けたい** | AE への長年の要望「group layers without pre-composing」 |
| **効果を掛ける範囲から、この層だけ外したい** | 同「exclude a layer from the adjustment layer」 |
| 名前を付けて、後で見つけたい | 層に名前を付けるのが良い作法、と繰り返し語られる |

### 案を持つ・見比べる

| したいこと | どこで |
|---|---|
| **1つの作品の中に案を複数持って切り替えたい** | C4D の Take System(1ファイルに複数の状態) |
| 案をまとめて書き出して見比べたい | 同(バッチで全案をレンダー) |
| 枝に分けて同時に試したい | Figma の Branching |
| **どこが変わったか印を付けてほしい** | Figma の Compare。要望として何度も出る |
| 前の版に戻したい | Version History |

### 作りかたの段

| したいこと | どこで |
|---|---|
| **止め絵で決めてから動かしたい** | styleframes。動く前に色・字・配置を固める |
| **まず直線で当たりを取り、あとで緩急を付けたい** | blocking → easing の二段。実務の標準 |
| 作品全体で同じ緩急を使いたい | ease profile を先に決めて共有する |
| 短い試しで確かめてから本番に入りたい | test snippet |
| 拍と区切りに印を打ちたい | markers で beat と section を tag する ——**既に在る** |

## 読み取れたこと(第三回)

**1. 「1枚にせずにまとめたい」は AE への長年の要望だった。**
グループの設計(何も与えなければ境界にならない)は、当てずっぽうではなく
**要望そのものの形**だった。「調整レイヤーからこの層だけ外したい」も、
グループの外に置けば済む。

**2. 効き具合は、1つの数ではなく場所で変わる。**
帯を属性へ落とす時、効き具合は取っ手1つで決めていた。
実際に要るのは**場所によって変わる効き具合**(C4D の Field)。
セルルック MV の「カメラからの距離で線の太さ」も同じ物だった。

**3. 増やし方に2種類ある。** 繋げて増やす(元を直すと全部直る)と、切って増やす(独立)。
AE はこの区別に名前が無く、プリコンポの複製が中身を共有する事故になっている。
**Motolii は複製の時に選ばせる必要がある。**

**4. 「まず直線、あとで緩急」が実務の順。**
Ease を別の面に置き、既にあるキーの区間に後から掛ける形は、この順に合っている。

**5. 濾された物。** 承認フロー、コメントの集約、外部レビューは
**1本作り切る間に出てこない**ので採らない(大義側)。
「ある瞬間に印を付けて後で戻る」だけが残ったが、これはマーカーとして既に在る。

**収束していない。** 第三回で新しい動詞が14本出た。まだ読む価値がある。

## 第四回 — 第一の利用者に一番近い所(ボカロMV・AviUtl)と、見る側

### 音と歌詞

| したいこと | どこで |
|---|---|
| **歌詞をまとめて入れて、時刻に割り付けたい** | ボカロMV制作記「いちいち歌詞を1文字ずつ入力する必要がなくなりました」 |
| **波形を見ながら叩いてタイミングを置きたい** | 歌詞入れツール「音ゲー感覚でタイミングをセット」 |
| **自動で当たりを付けて、人が仕上げたい** | 同「AIで自動推定(叩き台)→人間が仕上げる」 |

### 見る

| したいこと | どこで |
|---|---|
| **前後のコマを薄く重ねて見たい** | オニオンスキン。タイミング・間隔・軌跡を確かめる |
| **同じ場所で拭き分けて比べたい** | Nuke の A/B wipe。並べずに重ねて比べる |

### 取っておく

| したいこと | どこで |
|---|---|
| 設定を取っておいて使い回したい | AviUtl のエイリアス |

## 読み取れたこと(第四回)

**1. 「見比べる」は2つに割れる。**

- **同じ物を時間で比べる**(前後のコマを重ねる) → **見る側**。作品を1画素も変えない
- **違う案を比べる**(Take・版) → **持つ側**。作品が状態を複数持つ

前者は根底5(見るのと作るのは別)の下に置ける。**Document を触らずに済む。**
後者だけが作品の形に関わる。gap では分けて数える。

**2. 既定値は「意見」を持ってはいけない。抜け出す道は安くする。**

ボカロMV界隈の「ダサい表現とその代替案」は、ほぼ全部が**既定値のまま使った物**だった —— 
既定フォント、原色の赤、直線移動、内蔵の集中線・フレア・水面。
代替案の多くは「別のを使う」「薄っすらかける」「短くする」「やめる」。

ただしここから「既定を強く見栄えよくする」を導くのは間違い。
**既定は、利用者が『まだ決めていない』ことが見て分かる値でなければならない。**

- 直線の補間は正しい既定。2つのキーが言ったこと以外を何もしない。
  実務の順も **blocking → easing** で、**まず直線で当たりを取る**。
  既定が緩急を持っていたら、当たり取りが最初から汚れる
- 強い集中線・強いシャドー・派手なフレアは悪い既定。
  道具が決めた表現が混ざり、利用者は**弱める作業**から始めることになる

つまり**量は控えめに、意見は持たない**。

そして「直線移動がダサい」の本体は、既定ではなく**既定から抜け出す値段**だった。
AE も AviUtl も、緩急を付けるのに別の面(グラフエディタ)へ行く必要がある。
だから既定のまま出荷される。
**掴めばその場で乗るなら、素直な既定は罠にならない。**

**3. 第一の利用者は、映像の人ではなく音楽の人。**

「DAWの使い方と音楽理論を覚えるので精一杯なのに、どうやって動画を作れというのか」。
絵コンテを描けないまま作る人が、実際に作っている。
**本業が別に在る人が覚えられること**が要求水準になる。根底3(段階的に見せる)の根拠。

**まだ収束していない。** 第四回で新しい動詞が6本と、物差しが1つ。

## 第五回 — 終わりぎわ(出す)と、待つ

### 出す

| したいこと | どこで |
|---|---|
| **見た通りの色で出したい** | 「書き出すと色が変わる」。作業色空間・アルファの解釈でずれる |
| **1回で出したい** | AE は H.264 を直接選べず、別アプリ(Media Encoder)を経由させる |
| 背景を透明のまま出したい | アルファ付きの書き出し |
| 上げた先で劣化するので、上げてから確かめたい | YouTube 側で再エンコードされる |

### 待つ

| したいこと | どこで |
|---|---|
| **待たずに、今すぐ動いて見たい** | RAM プレビュー。メモリが足りないと再生できない |
| **最後まで通して見たい** | 「最初の数秒しか再生できない」 |
| 粗くていいから滑らかに見たい | 解像度を下げるのが定番の逃げ道 |

対処法として語られるのが**メモリ配分・キャッシュ削除・解像度**。
どれも**道具の内部事情**で、利用者は「見たい」としか言っていない。

## 突き合わせ(採った物どうしの矛盾を潰す)

**A. 「粗くていいから滑らかに見たい」と、preview は export と一致すべき。**
矛盾しない。**粗さと速さは見る側の設定で、作品に入らない**(根底5)。
視点を動かしても出力が変わらないのと同じ種類。
→ 根底5を「構図だけでなく、質と速さも見る側」に広げる。

**B. 「見た通りの色で出したい」と、視点と書き出しの分離。**
矛盾しない。**分けるのは構図、一致させるのは絵**。
どこから覗くかは作品に入らないが、色は1画素も変わってはいけない。

**C. 「自動で当たりを付けてほしい」と、根底6(偶然も値・決定的)。**
矛盾しない。**推定は Document の外に置く。** 自動が置くのは普通のキーで、
置かれた後は人が触る物。**推定結果を意味として持たない**なら、決定性は保たれる。
→ 自動は道具であって、意味ではない。

**D. 「繋げて増やす/切って増やす」と、「層の複製は独立」。** ここだけ**未解決**。
複製の時に選ばせる必要がある。裁定待ち。

**まだ収束していない。** 第五回で新しい動詞が7本。ただし出所が薄くなってきた。

## 第六回 — 縦型と、Motolii との突き合わせ

### 縦型・短尺

| したいこと | どこで |
|---|---|
| **同じ作品を、別の画面比でも出したい** | 横のMVの縦版を作る。手で変換するのは難しいと繰り返し語られる |
| **隠れる所を避けて置きたい** | SNS の UI が画面下と右を覆う。セーフエリア |

前者は Motolii では**別の話に落ちる** —— 書き出しの枠は作品の値なので、
**縦版は「枠が違うもう1つの案」**。案を複数持てれば、それで足りる。

# 総まとめ — 採れた意味を、口で分ける

6回で約45の動詞。重複を潰し、**どの口に落ちるか**で並べ替える。
これが実装の順番の材料になる。

## 駆動の口(無い。直列)

音・拍・番号・場所・距離が値を動かす。**これが無いと下の全部が手作業になる。**

- 音に合わせたい / 波形を見ながら叩いてタイミングを置きたい
- 順に現れさせたい / 1文字ずつ出したい / 等間隔に繰り返したい
- **ここは強く、あそこは弱く効かせたい**(場所で効き具合が変わる)
- 制御できる散らばりが欲しい
- カメラからの距離で値を変えたい
- 手を動かさずに動かしたい

## グループ(無い。直列)

- **1枚にせずに、層をまとめて片付けたい**(AE への長年の要望)
- 効果を掛ける範囲から、この層だけ外したい
- 色を揃えたい
- 軽くしたい(フリーズは在る)
- 繋げて増やすか、切って増やすかを選びたい ← **未裁定**

## 案を持つ(無い)

- 1つの作品の中に案を複数持って切り替えたい
- **同じ作品を別の画面比でも出したい**(= 枠が違う案)
- 版を刻んで戻りたい / 枝に分けて試したい
- どこが変わったか知りたい

## 見る(無い。作品を変えない)

- 前後のコマを薄く重ねて見たい
- 同じ場所で拭き分けて比べたい
- 粗くていいから滑らかに見たい
- 待たずに、最後まで通して見たい

## 素材と文字(口は在る)

- 歌詞をまとめて入れて時刻に割り付けたい
- 手書き風に、書き順で出したい ← **なぞらせない形が未決**
- 名前を付けて探したい / 片付けたい
- 設定を取っておいて使い回したい

## 効果(口は在る。並列)

光らせる・汚す・ぼかす・トゥーン・集中線・反転・色を揃える。
**書く物ではなく置く物**(ISF/GLSL は既に読める)。

## 出す(在るが穴)

- 見た通りの色で出したい / 1回で出したい / 透明のまま出したい
- 上げた先での劣化を、先に見当付けたい

## 残りの3つも「普通」で決まった

**動く物に貼り付けたい** —— 普通の合成ソフト(Nuke・Fusion)は、**追従の結果を独立した物として残し、
そこへ繋ぐ**。トラッカーが持つデータへ層を接続する。消費者向け(CapCut・Premiere)は
「解析は一押しで自動」。**どちらも「解析して、結果を持つ」**。
→ Motolii では**追従は帯になる**。位置の帯を属性へ落とす。解析はやり直せる。新しい機構は無い。

**背景を消したい** —— 普通は2つに分かれる。**鍵で抜くのはエフェクト**(Ultra Key、3D Keyer)で、
層に掛けるとアルファが出る。焼かない。**形で抜くのはマスク**で、動く物にはマスクに追従を付ける。
→ どちらも既にある口。エフェクトは Vism、形はマスク + 追従の帯。**新しい概念はゼロ。**

**手書き風に書き順で出したい** —— **普通は、なぞる。** Illustrator でも、文字をパスにして
線を引き、パスのトリムで伸ばす。書き順を知っている道具は存在しない。
→ 「なぞらせない形が要る」と書いたのは、**私が普通を外れた要求をしていた**。
文字を線に分解するのは Motolii の仕事ではない。**パスを引き、TRIM で伸ばす**。
なぞる苦痛を減らすなら、**パスを引く道具を良くする**。それだけが普通の範囲。

**「焼かない」を教条にして測っていたのが間違いだった。** 3つのうち2つはそもそも
焼く話ではなく、残る1つは**利用者が描く**のであって道具が焼くのではない。

## 第七回 — 一次資料(作り終えた人の言葉)

作り方の記事ではなく、**自分の作業を振り返って書いた物**。ここが一番強い。

### 引用と、そこから出る意味

**「パーツの数は68個ですが、動きをつけるとさらに何倍にもなるので
モーションの設定に時間がかかりました」**
→ 増やすことより、**増えた物それぞれに動きを付ける**のが重い。駆動の口の根拠。

**「背景ごとにオブジェクトの色調を変えていますが、
それぞれのパーツごとに書き出さなくてはいけないので結構たいへんです」**
→ **まとまりに色を掛ける道が無いので、パーツごとに書き出している。**
グループ+エフェクトが、そのまま答えになっている。

**「備え付けのエフェクトであったら一番楽だったんですけど、、、、。
なかったですね。無料のやつもなさそうでしたし、作ったほうが早かったです」**
→ 内蔵に無く、無料にも無く、**自分で作った**。裁定273「LLM が単独で書ける道路」の根拠。

**「レイヤーを見越した制作はできませんでした。あとから整理して、
もっと早くやっておけばよかったと反省です」**
→ **構造を先に見越せない。** 見越しを要求する道具は、必ずこの反省を生む。
根底2(順序を要求しない)が守るのはここ。あとから片付けるのが安くなければならない。

**「映像制作してたら、方向性が当初と変わった」
「絵コンテを作ってたら追加のイラストのアイデアが出てきた」——「わりかしよくあること」**
→ **工程は一方向に流れない。** 前へ戻るのが普通の状態。

**「エンコード時間が...1分で終わるものもあれば、12時間以上かかることも」**
→ 出すのを待つ。どれくらい待つのか先に知りたい。

**「動画で使用されることを念頭に置いてイラストを描く」「キャラと背景を別レイヤーで」**
→ **絵を層のまま持ち込みたい。** 描く側が層を分けて渡している。

## 読み取れたこと(第七回)

**1. 一次資料は、設計の答え合わせになる。**
「パーツごとに書き出す」も「レイヤーを見越せない」も、
**今日決めた形(グループ、通過、あとから入れ替え)がそのまま答えになっている**。
先に設計してから資料を読んだので、当てはまり方が偶然ではないと分かる。

**2. 工程は一方向でない、が最大の発見。**
チュートリアルも制作フロー記事も「STEP 1→5」で書くが、
**作った人は「途中で方向が変わるのはわりかしよくあること」と書く。**
一本道を前提にした道具は、この普通の状態を事故として扱う。
→ 前へ戻るのが安いこと。案を持てること。片付けが後からできること。

**3. 新しい動詞は3本。** 絵を層のまま持ち込む / どれくらい待つか知る / 後から片付ける。
**5本目・6本目より減った。**

## 第八回 — 職業の一次資料(第七回と突き合わせる)

第七回で読んだのは**趣味の記録**。第八回は職業の記録。
どちらが正しいという話ではない。**二つを並べると、道具が隠している所が出る。**

**技量で手順が変わること自体が、道具の欠陥の証拠。**
同じ「したいこと」に別々の手順が生まれているなら、それは能力の差ではなく道の差で、
初めての人にとって**在るのに届かない物は、無いのと同じ**(→ [根底8](ideal.md))。
趣味の記録は劣った資料ではなく、**利用者が止まった地点の記録**である。

### 引用

**「作画制作はAnimateでやっていて、そうしてできあがった素材を
After Effectsでまとめて出力するといった流れ」**(Waboku)
→ **道具は「まとめる場所」であって「作る場所」ではない。**
絵は Photoshop と Animate、統合が AE。スタジオ側の記述も同じで、
Illustrator で絵、C4D/Blender で立体、**まとめは AE**。

**「全部パソコンでできたら楽なので、何回か"鉛筆っぽいことができないかな"と
思って試したんですけど結局デジタルっぽくなってしまうので、今だに手描きで線を描いている」**(Waboku)
→ **「それっぽく」を道具がやると偽物になる。** 職業の作り手は、そこで手作業へ戻る。

**「細かく描くほど、スタッフさんに自分の考えている意図が伝わりやすくなる」——絵コンテ200枚**(Waboku)
→ 規模が桁違い。案と版の話は、趣味の規模で設計すると足りなくなる。

**"messy source files" / "unclear comp structure" が現場の常態**(スタジオ側)
→ **持ち込む素材は汚い**のが普通。片付けの話は趣味者の不注意ではなく、職業の常態。

### 第七回の findings を、技量で当て直す

| 第七回の findings | 職業側でも成立するか |
|---|---|
| 構造を先に見越せない | **成立。むしろ深刻**(規模が大きい。"unclear comp structure"が現場の痛点) |
| まとまりに色を掛けたい | **成立**。趣味は「パーツごとに書き出す」で回避、職業は金を払って回避。意味は同じ |
| 内蔵に無いので自分で作った | **成立**。職業はプラグインを買う。**内蔵で足りない**のは同じ |
| 工程が一方向でない | **成立**(feedback rounds、revisions) |
| エンコードに12時間 | **弱まる**。職業はプロキシとレンダーファームで回避。**趣味特有** |

### 読み取れたこと(第八回)

**1. 道具の役目は「まとめる」。**
職業の側で2つの独立した記述が、どちらも「素材は外で作り、合成ソフトでまとめる」と言う。
**持ち込む口とまとめる力が主役**で、内蔵エフェクトの数は主役ではない。
裁定473(Motolii は何も持たない)と同じ方向。

**2. 「それっぽく」は道具がやってはいけない。**
鉛筆風を試して戻った職業作家の証言は、**手書き風は利用者が描く**という
第六回の裁定(普通で測った結果)を裏から支える。
道具が代わりに「らしく」やると、そこが一番先に嘘に見える。

**3. 消えたのは「待ち時間の回避策」だけ。残り4件は水準を上げても成立する。**

**4. そして、二つを並べたこと自体が一番の収穫だった。**
「まとまりに色を掛けたい」に、趣味は**パーツごとに書き出す**、職業は**プラグインを買う**。
同じ意味に道が2本あり、**どちらも道具が用意した道ではない**。
これが AE が不親切だという事の中身で、Motolii が反面教師にすべき所。
→ 根底8「技量で手順が変わるなら、道具が隠している」

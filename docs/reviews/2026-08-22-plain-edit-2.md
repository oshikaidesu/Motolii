# 歌詞動画を1本、普通に作ってみる(コード読みでの通し)

`next/` を実際には動かさず、`Shell::update` に渡る `Message` の列を実コード
(`shell/motolii-shell/src/lib.rs`、`ui/*/src/*.rs`、`shell/motolii-shell/tests/suite/*.rs`
の実演)で辿り、「歌詞動画を最後まで作るとしたら何をすることになるか」を
最初から書き出しまで追った。詰まった所(Split の shell 未結線・波形の shell
未結線・テキストの一括編集・Matte・TextRange アニメーター等)は既知の壁として
飛ばし、迂回して先へ進んだ。欠陥探しではなく、通しでやった時の手触りの記録。

## 1. 何を何回やったか

- New Project 1回、曲(音声)の Import Media 1回。
- 歌詞の行数ぶん(仮に30行前後)、次のワンセットを丸ごと繰り返す:
  Browser の Text カードでレイヤー作成(`CreateFromCard`)→ Content 入力
  (`TextFieldInput`→`TextFieldSubmit` の2手)→ タイムラインで
  EdgeIn/EdgeOut ドラッグして表示区間を曲に合わせる → Opacity のキーフレームを
  4回前後(フェードイン開始/山/フェードアウト開始/終端)打つ。
- サビの位置は波形が見えない(shell 未結線)ので、曲を再生しながら耳で
  概算する作業を各サビ候補で数回。
- 色は Fill の R/G/B を `ChannelInput`→`ChannelSubmit` の2手×3チャンネルで
  決める — これを歌詞の色を変えたい**全レイヤーぶん**繰り返す(色を決める
  だけで1レイヤーあたり実質6メッセージ)。
- 書き出しは最後に1回(Cmd+E → Quality 選択 → 書き出し先選択
  → Export 実行)。

## 2. 「これ、さっきのと同じでは?」と思った所

- 1行目のテキストレイヤーを作る手順と、2行目・3行目…の手順が寸分違わず
  同じ形になる。`duplicate_layer`(`lib.rs:2031`)は `self.session.selection`
  (単一)しか見ないので、複数行をまとめて複製する経路が無く、毎回フルセットを
  最初からやり直す感覚になる。
- Fill 色を決める R/G/B の `ChannelInput`+`ChannelSubmit` という同じ形の
  2手を、チャンネルを変えて3回繰り返す。「色を1つ決める」という単位の作業が、
  同じ手つきの反復3回に分解されている。
- キーフレームの1個目は「Key click」という専用操作(`transform.rs` の
  `toggled_key_track`)で打つのに、2個目以降は「値を書き換えるだけ」で
  自動的に追加される(`commit_inspector_field`、AE 作法)。操作としては
  地続き(どちらも「この時刻にこの値を置く」)なのに、最初の1回だけ違う
  ボタンを押す必要があるという段差がある。

## 3. 一度も変えなかった値

- Line Height / Tracking / Justify(TEXT section) — 既定のまま。
- Stroke color — 一度も `None` から昇格させなかった(縁取りが要らなかった)。
- Blend Mode — 全レイヤー Normal のまま(`CycleBlendMode` に触れなかった)。
- Export Quality — 既定の `Normal`(Lossless に変えなかった)。
- Export Range — 既定の `Whole`。
- Font Family — 一度も明示的に選ばなかった(`motolii-font-catalog` の既定
  解決に任せっぱなし)。

## 4. 分かれている意味が分からなかった区別

- `Session::selection`(単一)と `Session::selected_layers`(複数)という
  2つの選択状態が並存していて、テキストの内容/色/サイズを書く経路
  (`TextFieldSubmit` 等)は前者だけを見て、Group化・Split は後者を見る、
  という使い分け(`motolii-shell-state/src/lib.rs` の doc 自認)。作業中、
  今どちらの「選択」が効いているのか区別がつかなかった。
- `Intent::SetTextDocument`(文書まるごと差し替え)と `Intent::SetTrack`
  (1プロパティのキーフレーム更新)という粒度の全く違う2つの書き込み単位が、
  体感としてはどちらも「Inspector の欄をいじる」という同じ種類の操作の裏に
  混在している。歌詞の文字を直す操作と、位置を動かす操作が、なぜ内部で
  別の重さの書き込みになっているのか区別の理由が分からなかった。
- Mask を足す(`Intent::AddMask` 専用の1操作)と Effect を足す
  (`ApplyEffectFromCard` 経由)が別々の入口・別々の内部 Intent になっている。
  どちらも「レイヤーに何かを足す」という同じ種類の操作に見えるのに、なぜ
  違う仕組みなのか分からなかった。

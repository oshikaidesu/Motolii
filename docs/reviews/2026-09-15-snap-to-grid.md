# 格子へ吸い付く — 無作為に「意図」を与える

2026-09-15。利用者(Müller-Brockmann『Grid Systems』の表紙を見て)「時として人間はグリッドを得る事で整いを得る。無造作に配置をしたリピーターに対してもこれを行うことで、本当に無作為であるのにグリッドによる整えの画が付与された場合、意図したもの、という観点が付与されるのではないか」→「お願いします、面白い試みになるかも」。

前に話した Stage の吸い付き(編集の補助、[宿題](2026-09-15-stage-snapping-homework.md))を、作品の中の関係にした物。

## 読み

- ぴったり揃うと、見る人は理由を探す(数 px ずれた揃いはミスに見える)。揃いは完全でないと意図にならない
- 格子の線が見えると、規則が見える(表紙は線まで出して「この規則に従った」を宣言している)
- 置き場所の選び方が無作為でも、選択肢が升目に限られていれば結果は構成に見える(Müller-Brockmann の升目 = フィールド)
- 物同士が揃い合う「磁石の整列」(秩序が物の間から)とは別。こちらは宣言された枠に揃う(秩序が上から)

## 先例

| 先例 | 形 |
|---|---|
| Müller-Brockmann のモジュラーグリッド | 列・行・溝・余白で升目を作り、物は升目の単位で置き、大きさも升目の倍数 |
| C4D MoGraph の Quantize | 写しの位置・回転を刻みに丸める |
| Illustrator / Photoshop の Snap to Grid | 物の辺を格子へ |
| CSS Grid の自動配置 | 物は必ずどこかのセルに入る |

## 法(提案)

1. **格子は Display = Grid の Group が宣言する**(既存の列・行・Gap・Padding・線の fr)。子が全部流れの外でも升目は解く(taffy は子の無い箱を葉として解くので、大きさ 0 の見えない子で格子の計算を走らせる)
2. **Grid の Group の子に `Snap to Grid`(0..1)**。流れの外の子(Absolute)と、Repeater の写し 1 枚ずつの箱の左上を、一番近い升目の角へその強さで寄せる。寄せるのは画面の変換だけ(書類の値・写しの配置はそのまま)
3. **`Snap Size`**: Off(大きさはそのまま)/ Fields(右下も一番近い升目の終わりへ、大きさを升目の倍数に)
4. 強さに鍵を打てば、散った物が升目へ滑り込み、また散る。寄せる先は書いた位置から決まるので、位置が止まっている間は連続
5. **格子の線は `Trace` = Grid**(つなぐ線の口): Grid の Group の升目の辺を端から端まで。Trim Paths で描き起こせる

## 見本

`grid_intent.js`(表紙の比率、4 列 × 8 行、灰の四角・赤い四角・赤い丸を Repeater で散らし、字を傾けて投げる。2 秒で赤い格子が描き起こされ、全部が升目へ吸い付いて字がまっすぐになる、4.4 秒でまた散る): 跳び 0・尖り 0。

## 残り

- 吸い付く先は一番近い角だけ(升目を跨いで重なっても避けない)。重なりを避けるなら間合いの押し合いと合わせる
- 写しの位置が動いている間に強さが 0 でないと、近い角が入れ替わる瞬間に跳ぶ
- 文字の Snap Size は伸びるので使わない(文字の大きさを升目に合わせるなら行の高さの格子 = baseline grid が要る)

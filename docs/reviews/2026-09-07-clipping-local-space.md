# クリッピングは下地の局所座標で絵だけを合わせる

利用者裁定(2026-09-07): クリッピングマスクでオブジェクトを畳まない。**畳みを許容するのはビューのみ**。普通の場面(点群の中に立つ人の切り抜きへ歌詞映像をクリップし、カメラがその周りを回る)が普通に出ること。

## 直す前の実態

[2026-09-05](2026-09-05-timeline-clipping.md) の実装は、下地とクリップ層をそれぞれ**画面座標**で comp 大の板に焼いてから source-atop し、結果を 2D の板(z=0・回転 0)として下地の順序位置へ置いていた。Document は無傷だが、描画では下地の z と回転が捨てられ、点群の粒が全部後ろに回る。加えて通り抜けの配置効果(Repeat)を下地にすると、登録が最後の複製 1 つに上書きされ、他の複製の上ではクリップ層が消えていた。

## 編集の意味(変更なし)

- Document は `clip_to_below: bool` だけ。projection・Position Z・Rotation・flatten には触らない。
- 下地は同じ親の直下で最初の非クリップ層。下地が無ければ描かない。下地の半透明を二重に濃くしない。

## 描く側(変更)

- クリップ層を**下地の局所座標**(素材の画素、効果の余白込み)へ描き、下地の alpha で source-atop する。出来た 1 枚を下地の**元の配置**(z・回転・world_transform)で置く。
- 下地は普通の層のまま描かれるので、点群・他の 3D 層との前後は深度で解ける。カメラが回っても特別な事はしない。
- クリップ層は下地に**貼り付いたデカール**になる。下地が斜めを向けば一緒に傾く(Photoshop は 2D なので区別が無く、矛盾しない)。
- 通り抜けの配置効果を下地にした時は、**複製ごと**にその複製の局所座標で切り抜く(画面上の重なりの意味、Photoshop と同じ)。複製が画面上で重なる所では半透明のクリップ層が二重に描かれる。「素材に 1 回掛けて N 個置く」(9/6 の上の効果の規則)にするには、配置前の変換を resolve から持ち越す必要があり、宿題。
- 下地に texture が無い(点群・モデル)時は描かず `layer_failures` に理由を残す(以前は panic)。

## 変えない制限

Add ブレンドのクリップ上層は借用 mix が無いので明示エラー。Lottie は unsupported として報告。グループ全体・Null の入口無効化は据え置き。

## 検収

`crates/motolii-render` の `clipping_contract` 2 本: 9/5 の画素契約の移植(下地 α128 維持・下地の見え方・逃げない・backdrop・hidden・orphan・Lottie)と、点群を下地の前後に置いて「前の粒は下地を隠し、後ろの粒は下地に隠れ、下地の projection と flatten は不変」。render crate 22 本と `ui/native` 22 本は通過。

一時 test で 640×360、点群 6,000 点(z ±250)、人の切り抜き 160×320、歌詞映像 640×160、カメラ orbit −40°〜+40° の 6 コマを出し、クリップ有無を並べて確認した(絵は保存せず、test も消した)。観察: orbit の符号で人の見かけの大きさが大きく非対称になる。クリップ無しでも同じなのでカメラ側の既存挙動であり、本件の範囲外。

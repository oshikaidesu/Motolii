# 間合いの法 — 物が自分の距離を宣言し、関係の変化は時間の側で

2026-09-14 利用者裁定。きっかけは渋谷の俯瞰の Exclusions(格子の枠を群れが占める)が「フレームごとに動いて連続性の意味が無い」「このような画はプログラムでいつでも出せる」「大事なのは箱でありグリッドではない」。続けて「箱である意味とは、オブジェクトが自分の距離、パディングを宣言できる部分。相互関係がモーショングラフィックスの奥行き」「Motolii は区間イージングといい、間に意味を見出していたのかもしれない」「法の相談は CSS はどうしているかで解ける、静的解析、距離の話なので安く解ける」。

前提: [箱と流し込みの法](2026-09-14-layout-law.md)、[ドッグフーディング](2026-09-14-dogfooding-video-css.md)、ゴーストの裁定(2026-09-07「層を別の時刻で見た行」)、区間イージング(2026-07-10)。

## 読み

- 座標は「どこに居るか」しか言えない。箱は「周りとどれだけ離れていたいか」を物が言える。位置はその宣言同士の結果
- 見る人が読むのは物と物の距離の変化(ゲシュタルトの近接・共通運命)。AE ではこの関係が作る人の頭の中にしか無く、書類に残らない
- 格子や Flex は行き先を出す解き方の 1 つ。作る人が決めるのは、行き先へどう移るか(溜め・遅れ・譲り合い)

## CSS はどうしているか

| CSS | 読み |
|---|---|
| `margin`・`padding`・`gap` | 距離は箱が宣言する(外・中身・兄弟) |
| 並べる計算 | その瞬間の宣言だけから解く(静的、前の状態を持たない) |
| `transition-duration`・`transition-timing-function`、FLIP | 並びの結果が変わった時の移り方は別の層 |
| `flex-shrink` | 詰まった時に誰がどれだけ譲るかの比 |

先例(容器の外): d3-force の `forceCollide`(物ごとの半径で押し合う)。

## 法

1. **間合いは物が宣言する**。`Margin`(外との距離)をすべての物に。容器の子なら CSS の margin として並べる計算へ
2. **その瞬間の宣言だけで静的に解く**。容器の外で浮いている兄弟同士は、それぞれの位置(鍵・親)から出発し、間合いの箱の重なりを決まった回数だけ押し戻す。前のコマを見ないので、どのコマへ飛んでも同じ絵
3. **誰が譲るかも宣言**。`Flex Shrink`(CSS の語)。0 は譲らない。押し戻しは両者の比で分ける
4. **関係の変化の見え方(間)は時間の側で、状態を持たずに**。`Transition Duration`・`Transition Easing`(CSS の語)。解いた行き先を少し前の時刻でも解き、イージングの区間の重みで混ぜる: 位置(t) = Σ (E(uₖ₊₁) − E(uₖ)) · 行き先(t − D·uₖ)。行き先が一度に変わると、位置は D の間に E の形で移る(CSS の transition と同じ見え方)。時刻はコマに丸める(解析の塊と同じコマを読む)。ゴーストの `t − d` と区間イージングを行き先の履歴へ掛けた形

## 裁定(2026-09-14)

- 容器の外の物同士も押し合う(法 2 の後半、CSS の外、先例 d3-force)(利用者「ok」)
- 移り方は状態を持たない「少し前の行き先を混ぜる」(法 4)(利用者「ok」)

## 夜間の提案(2026-09-14、連続性の物差しで決めた。朝に取り消せる)

利用者「連続性が保たれているかどうか。動きにガクつきはないか。充分に補完されているか」。

1. **移り方が混ぜるのは位置・拡縮・大きさ・中心**。Fill の伸び・Group の箱(背景・切り抜き)も混ぜる。位置だけ混ぜると、枠の大きさが変わるコマで箱の角が 1 コマ跳ぶ(渋谷の格子で 80 → 8)
2. **標本はコマごとに 1 つ**(120 コマまで)。16 に間引くと遡る時刻の丸めが時刻ごとに変わり、重みの形が揺れる(1122 → 80)
3. **解析の入力も遡る**。host は Blob の塊を、移り方が遡るコマ数(`transition_reach`)だけ前まで置く。置かないと前の時刻の並びは塊を避けない並びになり、今の並びだけが 1/n 混ざって震える(1964 → 1122 の後の揺れの正体)
4. 渋谷の格子(`Exclusions`)は `Transition Duration` 1.0 s・Ease In Out で跳び 0・尖り 0。0.6 s は尖り 161(行き先が 0.6 s より速く入れ替わり、動き出しの加速度が 14 px/コマ² に届く)。grid_squash は 0.35 s で 0 / 0(0.2 s は尖り 64)

見え方(渋谷): 格子は常に移る途中で、カードが群れの空いた所へ漂う塊になる。格子の形は見えにくくなる。面白いかは利用者の判定。

### 夜間の提案 2(2026-09-15): 遅れと配り、容器の中身

5. **`Transition Delay`**(CSS の transition-delay)。解いた行き先を遅れ + 区間の重みで混ぜる: 位置(t) = Σ wₖ · 行き先(t − 遅れ − D·uₖ)。遅れがコマの途中なら前後のコマへ重みを分ける
6. **容器の `Stagger`・`Stagger From`**(Start / Center / End / Edges、GSAP の stagger の amount と from)。子の遅れ = Stagger × 起点からの距離 / 容器の最大の距離。距離は**窓より前(t − Stagger − Duration)に並んでいた場所**で測る(GSAP が今居る場所で測るのと同じ)。動いている途中の位置で測ると、動くほど遅れが変わって前後に揺れた(夜間の実験)。行き先が Stagger + Duration より短い間隔で変わると、配り直しの瞬間に跳ぶ
7. **自分の移り方を持たない並ぶ子は、容器の移り方を借りる**。容器の箱が移る途中は、その見えている箱の中で並ぶ(CSS で幅が移る間、中身は毎コマ並び直すのと同じ。揃え・伸びは箱の大きさに線形なので、同じ重みで混ぜれば一致する)。借りないと、セルの中の文字だけが先に跳んだ
8. 解析の入力は、移り方の長い順 2 つの和 + 遅れ 2 つ分だけ前まで置く

見本 `stagger_reflow.js`(格子の列数が 6 → 4 → 8 → 6 に Hold で変わり、中央から外へ滑る): 跳び 0・尖り 0(借りる前は文字が 54 跳び)。

## 0. 先に結論 — 今日の実証と公式が一致した所

| 公式の指示(Fable 5.1 の移行ガイド) | 今日どうだったか |
|---|---|
| **一番難しい未解決の問題から始める。** まず問題を切らせ、質問させ、それから実行 | 朝は簡単な写し 20 本を大量に(手は減らず、絵も動かず)。夕方の「核は何か」の相談が一番効いた |
| **手順を書くな、目的と制約を書け。** 前世代向けの手順書きの prompt / skill は出力の質を**下げる**。A/B で足場を外せ | 束の指示「CSS の keyframes と ease を正確に写せ」→ 71 個の鍵。関係の側の指示に変えたら鍵 24 → 5 |
| **理由を渡せ。** 「誰のために・何が出来るようになるために・だから何を」 | 独白(Motley、うごメモ、失われた世代)の後に指摘が当たり始めた、と利用者 |
| **進捗の主張は tool の結果と突き合わせる。未検証はそう言う** | 「2 宣言になる」と確かめる前に言った(かっこつけ)。証拠の絵と画素比較は効いた |
| **検証は文脈の無い別の sub-agent に。自己批評より強い** | 束 1 の絵を綺麗な binary で描き直して画素差 0 を出したのはこれ |
| **委任は非同期に。待たずに他を進める** | 4 束の直列 + 調査の並走。build は 1 レーン(CPU の取り合い) |
| **記憶の面を与える。1 課題 1 file、要約 1 行、訂正も確認も、なぜかも** | 記憶の索引 + 独白の書き起こし。逸れた時に戻る場所 |
| **effort は下げても良い。低 effort でも前世代の xhigh を超える。高 effort の日常作業は考え込む** | 調査 agent は effort を下げても足りた。build レーンは高いままで良い |
| **止まる癖 2 つ: 「次に X をやる」で tool を呼ばず終わる、要らない許可を求める** | 物理レーンの agent が build の知らせを待って止まった → 「前で回せ」で復帰 |
| **境界を明示する。問題の記述や独白の時は評価が成果物、直すな** | 相談モードの時に build レーンを走らせ続けた(止められた) |

**公式の文(そのまま使える)** — 「When you have enough information to act, act. Do not re-derive facts already established… give a recommendation, not an exhaustive survey.」「Before reporting progress, audit each claim against a tool result from this session.」「I'm working on [the larger task] for [who it's for]. With that in mind: [request].」「Establish a method for checking your own work as you build; run it every [interval], verifying against the specification with sub-agents.」「Don't add features, refactor, or introduce abstractions beyond what the task requires.」

# LLM 最大能力活用ガイド — Anthropic 公式ソース 2026年9月

## 1. Claude Code ベストプラクティス

**原則:** 文脈ウィンドウ管理が全ての制約 — 満杯 80% で性能低下。

- **検証可能にする:** テスト / ビルド / スクリーンショット比較で自動ループ化 (`/goal` / Stop hook / subagent の逆張りレビュー)
- **計画→実装 分離:** plan mode で探索と実行を分ける；スコープが明確な場合は計画スキップ
- **CLAUDE.md 精選:** 200 行以下；Claude が読めるコード＆自明な慣例は除く；矛盾排除
- **多並走:** worktree / subagent / 非対話モード (`-p`) で文脈を隔離；ファンアウト / pipelines で並列化
- **compaction 戦略:** `/compact` と `/rewind` で文脈圧縮；subagent は調査用で家計保全

**出典:** https://code.claude.com/docs/en/best-practices.md

## 2. Skills と Agent Skills 標準

**構造:** SKILL.md frontmatter → progressive disclosure (説明は常時, 本体は呼び出し時のみ読む)

- **SKILL.md 形式:** 説明 + `disable-model-invocation` / `allowed-tools` / `context: fork` で粒度制御；`$ARGUMENTS` 置換対応
- **Agent Skills 標準:** agentskills.io open standard — `name`, `description`, `allowed-tools`, `metadata` のみ再配布可；Claude Code 固有フィールドは封装
- **第三者配布:** plugin / `.claude/skills/` に埋込; 動的文脈注入で `!`git diff HEAD`` etc. を事前実行
- **`/skill-doctor`:** 使用状況 & 文脈コスト報告（一般提供）；`claude plugin eval` は早期アクセス（enablement 変数が必要）

**出典:** https://code.claude.com/docs/en/skills.md

## 3. メモリ & 長期ワーク

**二層:** CLAUDE.md (手書き永続) + auto memory (Claude 自動 / 機械ローカル / 200行50KB キャップ)

- **CLAUDE.md:** プロジェクト / ユーザー / 組織スコープ；ルール＆慣例のみ；path-scoped rules で `.claude/rules/` に分割; import `@path` で再利用
- **Auto memory:** session 継続時に機械学習。`feedback_*`, `project_*`, `reference_*` 型；worktree 横断共有；Subagent は別 directory
- **Workflows (ultracode):** 多 subagent orchestration を JavaScript で codify；`agent()`, `pipeline()`, `parallel()` で 1000 agent/run 迄；中止 resumable
- **Agent SDK:** Python / TypeScript ライブラリ (非 Managed Agents)；Build-in tools + hooks + MCP + subagent；自ホスト型

## 5. 研究品質プロンプト & 文脈工学

**Context Engineering 原則 (Claude 5 向け最新):**
- **判断＞規則:** 予言的ガード除去 → Fable/Opus は判断空間大；CLAUDE.md 削減 80%OK
- **Just-in-time:** 軽量識別子 (path / query) → runtime 動的ロード；フォルダ階層を信号化
- **Progressive disclosure:** skill / defer tool で遅延ロード；system prompt は最小限
- **Compaction:** 会話要約で architectural decision / 未解決問保持；redundant output 削除
- **Structured notes:** agent が external NOTES.md で persistent memory；context window の外へ

**Research-quality:** extended thinking 有効化；citation 求める；「質問を促す」設定；複数角度で検証 (subagent 逆張りレビュー)

## 3. Agent Skills 開放標準(agentskills.io)

- Spec: `skill-name/SKILL.md` 必須、任意で `scripts/` `references/` `assets/`。frontmatter は `name`(≤64、小文字英数とハイフン、親 dir 名と一致)と `description`(≤1024、何を・いつ)が必須。任意 `license`、`compatibility`(≤500)、`metadata`(string→string)、`allowed-tools`(実験的)。検証は `skills-ref validate ./my-skill`。
- 段階開示: metadata(~100 tokens)は常駐 → 本文は発動時に全文(<5,000 tokens・500 行未満推奨)→ resources は必要時のみ。参照は SKILL.md から 1 段まで。
- 対応 client(agentskills.io 掲載 ≈45): Claude Code、Claude、ChatGPT & Codex、Cursor、Gemini CLI、GitHub Copilot、VS Code、OpenCode、OpenHands、Goose、Junie、Amp、Kiro、Factory、Roo Code、Mistral Vibe ほか。Kimi Code は掲載外だが公式 docs が `.agents/skills` / `~/.agents/skills` を読むと明記(標準への言及は無し)。Claude Code は標準を拡張(`disable-model-invocation`、`context: fork`、`` !`cmd` ``)し、配布時は標準 6 項目に絞れと明記。

## 4. 各社に共通する「最大能力」の作法

- 検証できる的を渡す — Anthropic: "Give Claude a check it can run: tests, a build, a screenshot to compare." 段階は prompt 内 → `/goal` → Stop hook → 別 subagent が反証。OpenAI: prompt に goal・context・constraints・completion criteria、"define completion before starting"、`/goal` に Outcome・Constraints・Verification。
- テストが真実 — Anthropic: "If you can't verify it, don't ship it." Codex prompting: "After the fix, run lint + the smallest relevant test suite." skill の eval: "a prompt → a captured run (trace + artifacts) → a small set of checks → a score you can compare over time"(`codex exec --json` で採点)。
- 小さく読める単位で進める — Anthropic harness: 1 feature ずつ、`claude-progress.txt`、"use git to revert bad code changes"。Codex: worktree で分け `codex review` で差分を審査。Cursor/Codex の cloud も同じ型。
- 調査と実行を分ける — Claude Code: Explore(read-only)/ Plan / general-purpose、"use subagents to investigate X"、`/batch` は 5〜30 の subagent を worktree ごとに。Codex: `explorer` / `worker`、"Keep the main agent focused on requirements, decisions, and final outputs." Anthropic harness-design: "Separating the agent doing the work from the agent judging it proves to be a strong lever."
- Context 衛生 — Anthropic: "find the smallest possible set of high-signal tokens"、`/clear` を task 間で、2 回直して駄目なら `/clear`、CLAUDE.md は 200 行未満。OpenAI: "Use compaction as a default long-run primitive, not an emergency fallback"、skill 一覧は 2% / 8,000 文字、description は "routing logic (not marketing copy)"。
- 参照を渡す — Claude: "Give URLs for documentation"、`@file`。Codex: "In the CLI, mention paths explicitly." 両社の docs は URL 末尾に `.md` で Markdown、`/llms.txt` 索引あり(llmstxt.org の提案。2024-09 初出、2026-08-10 更新)。

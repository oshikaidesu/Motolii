# 普通にモーショングラフィックスを1本作ってみる(コード読解のみ・実行はせず)

`next/` のコードを読んで、「矩形を置く→動かす→効果を付ける→書き出す」を実際にやるとどの関数をどう通るかを辿った記録。GUIは動かしていない(ビルドは裏で走らせたが完了を待たずに読解で完結させた)。止まった所(打点の腕が配線されていない等)は追及せず、通る経路の方へ進んだ。

## 1. 何を何回やったか

- 起動: 1回。`Shell::default_document()` が最初から 640×360 / 30fps / 300frame の Composition を持っているので、コンポジションを作る手順は無い(すでにある)。
- 図形を置く: 1回。Browser の Create タブの Rectangle カードを押す → `create_from_card` が `AddLayer + SetMeta + SetAttrs + SetShapes` の4 Intent を1回の `apply_all` にまとめる(1 undo)。
- 動かす: Position 行の Key ボタンを1回押して0フレーム目に打点(`toggle_inspector_key` → `Intent::SetTrack` 1回)。playhead を2秒目までスクラブ(1回)。Position の X欄に打鍵して Enter、Y欄に打鍵して Enter — これで `Intent::SetTrack` がさらに2回発行される(X用・Y用で別々)。
- 効果を付ける: Effects タブの Glow カードを1回押す → `apply_effect_to_selected_layer` が `Intent::SetEffects` を1回発行。パラメータ(Threshold/Intensity/Radius)は触らない。
- 書き出す: Export ウィンドウを開く(1回)、保存先を選ぶ(1回)、Export ボタンを押す(1回)→ `start_export` が同期で1回だけ FFmpeg 経路を回す。

## 2. 「これ、さっきのと同じでは?」と思った所

- Position を動かす経路が2つある。Inspector の数値欄に打鍵して Enter する経路は X と Y が別 `TransformField` なので `Intent::SetTrack` が2回(2 undo)出る。一方 Stage 上の gizmo を掴んで離す経路(`gizmo.rs` の `GizmoValue::Position([f64;2])`)は X/Y をまとめて1回の `Intent::SetTrack` で確定する(1 undo)。「1操作=1undo」を各所で謳っている規律なのに、同じ「位置を動かす」という1つの意図に対して数え方が経路によって割れている。
- `timeline_pane::write::Message::ToggleKeyframeAtPlayhead`(「今の playhead にキーを足す/消す」)が定義され、match 腕まで実装されているが、リポジトリ全体を grep してもこれを生成する呼び出し元がゼロ — ボタンにもキーマップ(`motolii-keymap`)にも配線されていない。同じ意味の打点操作は Inspector 側の `KeyPressed`→`toggle_inspector_key` として実際に配線されて動くので、同じ役割の書き口が2つ実装されていて、片方だけが実際に押せる状態だった。

## 3. 一度も変えなかった値

- Composition の 640×360 / 30fps / 300frame(`default_document` の既定値)。
- 新規図形に付く塗り色 `[80, 160, 220, 255]`(Solid の既定色をそのまま差し色として流用しているもの)。
- Glow の3パラメータ(Threshold=1.0 / Intensity=0.75 / Radius=1.0)。track を一度も張らなかったので engine 側の既定値がそのまま効いている。
- Export の品質(Normal)・範囲(Whole)・コンテナ/コーデック(MP4 / H.264 — そもそも選択肢が無く固定)。

## 4. 分かれている意味が分からなかった区別

マスクの形(`Intent::AddMask` に渡す shape)は `KeyframeTrack<Value::Path>` として持たれていて時間で打点できる作りになっている。一方 Shape レイヤーの形そのもの(`Intent::SetShapes` が積む `VectorShape`/`ShapeNode`)は track を持たない一枚岩の `Vec` で、時間で動かす経路が無い。どちらも「パスを持つ図形の記述」という同じ種類の物に見えるのに、片方だけ時間軸に乗る作りになっている理由は、読んだ範囲のコメントからは分からなかった。

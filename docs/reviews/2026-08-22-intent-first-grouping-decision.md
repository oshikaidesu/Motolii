# 裁定174 — 意図優先の原則: グループ化は「グループを作る」動詞だけで露出する(親ポインタ UI は作らない)

日付: 2026-08-22(朝) / 状態: **決定** / 起点: 利用者裁定「親を設定する UI は考えるべきなのか。普通にグループレイヤーを作るだけにしておきたい。**Motolii はユーザーの意図を最優先にするべき**」

## 1. 原則(正典へ)

**ユーザーに見せる動詞は意図を語り、機構は語らない。** parent ポインタは変換階層の機構(裁定173 H1 — 実装済み・維持)だが、それを直接編集させる UI(AE の Parent 列・pick-whip・親ドロップダウン)は**作らない**。ユーザーの意図は「これらをまとめたい」であり、その動詞は**グループ化**である。

## 2. 採択

- **H3(親選択 UI)は廃止** → **G1(グループ化動詞)へ置換**: 複数選択 → ⌘G で `LayerSource::Group` 層が生まれ、選択層の parent がそれに向く(1 gesture = 1 undo)。⌘⇧G(Ungroup)で解除(子の world 位置は保存 — 解除で絵が動かない)。入口は shortcut+メニュー(MB-2 Layer 束)+将来の右クリック(S6 併存)
- map 処置: **957(Parent column)= 不採用**(理由: 機構露出・本裁定)。455-457/468-470(Group/Ungroup 系)= G1 の消化対象
- 将来の再訪条件: グループなしの拘束的 parenting(AE 型)が実ユースケースで要求された時のみ — その時も入口は意図動詞(例: 「追従させる」)で設計し、ポインタ編集は出さない

## 3. G1 の oracle 型

- ⌘G: N 層選択→ Group 層 1+parent N 本が1 undo で入る・ツリー(H2)に即時反映・変換は不変(グループ層は単位変換で生まれる)
- ⌘⇧G: 子の world 位置が保存される数値証明(親変換を子ローカルへ焼き込み)
- 空選択・単一選択・入れ子グループの各縁

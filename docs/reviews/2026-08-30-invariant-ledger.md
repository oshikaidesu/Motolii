# 「普通」の深い層は不変量で測る(不変量台帳)

- 日付: 2026-08-30
- 発端: 利用者「**キーフレームの位置は変更できますか? レイヤーは複数選択出来ますか?
  親(レイヤー)を動かした時、子(キーフレーム)は追従できていますか? そういう普通は、
  どう測れば検出できるかな**」
- 位置づけ: [ギャップ地図](../ui-inherited-grammar-gap.md)(反射の在庫)と
  [品質バー](../ui-quality-bar.md)(合否規則)の**3本目**。両者が取りこぼす層を持つ

## なぜ既存の2本では取りこぼすか

- **ギャップ地図**は「**触れるか**」の在庫 — Space再生・Cmd+K・D&D。**1操作で完結する反射**
- **品質バー**は「**その1操作が正しく応えるか**」— Q0触達性・Q3報酬・Q5単一の真実
- どちらも**1操作を見る**。ところが利用者が挙げた3つは、
  **操作した後に関係が壊れていないか**の話で、1操作を見ても分からない

実例: 帯を動かす操作は Q0(掴める)も Q3(動いて見える)も Q5(全面が同じ)も**全部通る**。
それでも**キーフレームが置き去りになってアニメーションが壊れる**。
2026-08-30 の夜、監督は反射の検分を回したが**この3つは全部素通りした**。

## 測り方 — 不変量は「編集を通した後の等式」

> **不変量 = ある編集をした後も成り立っているべき等式。**
> 反射が「触れるか」を問うのに対し、不変量は「**触った後も辻褄が合っているか**」を問う。

**機械で測れる。**窓は要らない — `Document` 水準の property test で足りる:
`編集前の状態 → 編集 → 編集後の状態` を組み、等式を assert する。
1操作のUIテストより**安くて網羅的**。

## 現在地(2026-08-30 実測)

| 不変量 | 状態 | 根拠 |
|---|---|---|
| **層を動かしたらキーフレームも一緒に動く** | ❌ **壊れている** | Move の確定は `LayerTiming{start, ..orig}` だけ(`probe/src/timeline_widget.rs:416-419`)。キー時刻は comp 絶対なので置き去りになる |
| **キーフレームの時刻を変えられる** | ❌ **できない** | `hit_test`(`timeline_widget.rs`)はキーに当たるが `self.selected` に入れるだけ。ドラッグして動かす経路も `SetKeyTime` 相当も無い |
| **層を複数選べる** | ❌ **できない** | `Selection(Arc<Mutex<Option<LayerId>>>)`(`probe/src/session.rs:11`)— 型が1つしか持てない |
| 層を割ったら両方が中身を保つ | ✅ | Split が attrs/tracks/effects を写す(2026-08-30) |
| 1ジェスチャ = 1 undo | ✅ | `apply_all` を1回(Split・ギズモ・スクラブ) |
| ドラッグ中の見た目 = 離した後の結果 | ✅ | transient overlay(Q4) |

## 足すべき不変量(未検証。次に測る)

- 層を消したら、それを参照している物(親子・マット元・エフェクトの層参照)が壊れない
- undo/redo を往復したら完全に元へ戻る(値だけでなく選択・時刻も)
- 層を割った後、両方に undo を1回ずつかけると元の1本に戻る
- 素材の尺が変わっても、置いてある帯の意味が壊れない
- 親を動かしたら子(グループの中身)も動く

## 運転への反映

**UI発注のTARGETに、反射と合否だけでなく不変量を書く。**
「掴めて動く」で終わらせず、「動かした後に**何が保たれるか**」を1行足す。

## 実測(2026-08-30 夜): キーマップが窓で効いていない

`Cmd+K` / 矢印 / `Cmd+A` のどれも**窓で反応しない**(タイムコードが動かない、選択が変わらない)。
`cargo build` は緑、`keymap.rs` の「キー→意図」の対応 test も緑、
レーンは `blitz-dom/src/events/driver.rs:194-201` と
`dioxus-native-dom/src/dioxus_document.rs:339-359` を読んで
「ルートの `onkeydown` は届くはず」と報告していたが、**窓では届いていない**。

**「読んで届くはず」は実証ではない。**`autofocus` が Cargo feature で既定 off だった前例と同型
(2026-08-29)。次に見るべきは:
- そもそも `#app` に focus が無いのではないか(ルート要素が focusable か)
- `osascript` の `keystroke` がこのアプリに届いているか(CGEvent 側で試す)
- `text_editing` のガードが常時 true になっていないか

**この欠陥は不変量では捕まらない。**`Document` 水準では正しく、**入力が届くかは窓でしか分からない**。
不変量が反射を補うのと同じく、**反射の検分も不変量を補う** — どちらか一方では足りない。

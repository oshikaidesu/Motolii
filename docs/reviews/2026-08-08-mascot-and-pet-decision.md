# マスコット「カササギ」確定と、ペット機能の延期

状態: **決定**(造形・配色・動き)／ペット機能は**延期**

日付: 2026-08-08

## 決定

Motoliiのマスコットを、**8×8ドット・2色のカササギ**に確定する。名前の由来 *motley*(色や出自の違うものが寄せ集まって一つになっている状態、および道化の継ぎはぎ衣装。[README.md](../../README.md))から動物を逆算し、光るものを集める・白黒のまだらという性質でカササギを選んだ。

確定するのは次の3点に限る。

1. **造形** — 下記スプライト定義のbitmap
2. **配色** — 2色。背景の明暗で体色だけを反転する
3. **動き** — 立つ／沈む／浮くの3フレームと、目1pxの塗り潰し

**ペット機能(常駐して状態を示す、拾ってくる等)は本決定に含めない。**理由は§5に置く。

## 1. スプライト定義

`K`=体色、`C`=モチーフカラー、`.`=透明。1文字=1px、8×8。

### 立つ(基本姿勢)

```
.KKK....
KKCKKK..
.KKKKKK.
.CCKKKKK
.CCCKKKK
..CCKKKK
..C.C.KK
.......K
```

`r1`の`C`が目(体色の中に抜いた1px)、`r1`の左端`K`が嘴、`r3`〜`r6`左側の`C`が腹、`r6`の`C`2つが脚、右下へ流れる`K`が尾。

### 沈む(呼吸の第2フレーム)

```
........
.KKK....
KKCKKK..
.KKKKKK.
.CCKKKKK
.CCCKKKK
..CCKKKK
.......K
```

体だけが1px下がり、1pxしかない脚が体に吸収される。尾の先端(`r7`)は接地したまま動かさない。

### 浮く(跳躍の空中フレーム)

`立つ`から脚(`r6`の`C`2つ)を削除したbitmapを、**描画時に全体1px上へ置く**。bitmap自体は8×8に収まるが、配置に-1pxのoffsetを持つ唯一のフレームである。

### まばたき

`立つ`の`r1`の目1pxを`C`から`K`に変える。差分はこの1pxだけ。

```
.KKK....
KKKKKK..
.KKKKKK.
.CCKKKKK
.CCCKKKK
..CCKKKK
..C.C.KK
.......K
```

### 拾う(将来のペット機能用。造形のみ確定、用途は延期)

```
..KKK...
.KKKKK..
.KCKKKK.
KCCKKKKK
.CCCKKKK
..CCKKKK
..C.C.KK
C......K
```

頭を下げ、嘴の先(`r7`左端)に1pxの光り物を置く。

## 2. 配色

2色だけを使う。モチーフカラーは背景によらず固定し、**体色のみ反転**する。

| 役割 | ダーク背景 | ライト背景 |
|---|---|---|
| 体色(`K`) | `#EDEAE0` | `#0F0F0F` |
| モチーフカラー(`C`。腹・脚・目・光り物) | `#3ED9A4` | `#3ED9A4` |

反転を選んだ理由: 生成りの体はライト背景で飛び、実寸16pxではモチーフカラーの数点しか残らないことを確認した。カササギは実際に白黒の鳥なので、体色の反転は題材上の嘘にならない。単一アセット化のために生成りを暗くする案もあったが、ダーク既定([UI配色](../ui-visual-language.md))での軽さを優先し、2アセットを持つ運用を採る。

`#3ED9A4`は**仮の値**であり、Ableton風パネル色の実画面上での効き、および項目種別色との衝突は未検証(§6)。

## 3. アニメーション

フレーム資産は`立つ`／`沈む`／`浮く`の3枚のみ。

| ループ | 構成 | 周期 |
|---|---|---|
| 呼吸 | 立つ ↔ 沈む | 1.6s |
| まばたき | 目1pxの塗り潰し | 3.4s間隔・0.17s。等間隔は機械に見えるため実装では間隔に揺らぎを入れる |
| 跳ねる | 立つ → 沈む → 浮く | 0.9s(概ね 0.54 / 0.135 / 0.225) |

- **呼吸は上下方向とする。**胸が横に1px膨らむ案を試作したが、重心が左右へ動くため呼吸ではなく「よろけ」に見えた。左右非対称の膨張は採らない
- **歩行は採らず跳躍とする。**カササギは実際に歩かず両脚で跳ぶ。加えて跳躍は同一bitmapの脚削除と1px offsetだけで作れるため、歩行に必要な脚位置の差分アセットが不要になる
- 呼吸の`沈む`は跳躍の予備動作と同一フレームであり、共用する
- 呼吸・まばたきは純粋な装飾なので`prefers-reduced-motion`で停止する。データ由来の動き(再生・スクラブ)を止めない規律([UI視覚言語](../ui-visual-language.md))とは別扱いになる

## 4. 造形上の判断根拠

後続で同じ議論を繰り返さないために、効いた判断だけを残す。

- **2点の錯覚** — 人は点2つを顔として読む。ただし本件は横向き1目のまま、嘴と尾で生物性を確保した。正面2目案は試作したが、左右対称が置物に寄ること、目の1段下に置いた嘴が鼻に見えることから採らなかった
- **嘴の位置** — 嘴が鼻に見えるかどうかは大きさではなく段で決まる。鳥の嘴は目と同じ高さから出る
- **太らせると種が曖昧になる** — 丸めるほど輪郭から種の情報が消え、同時に可愛さの条件を満たす。抽象化と可愛さが同方向を向く
- **白は背景に抜ける** — 明色領域が輪郭に接すると、同系の背景では「欠け」に見える。明色は体色に四方を囲まれる位置にだけ置く

## 5. 既存規律との衝突(ペット機能を延期する理由)

[UI相互作用言語](../ui-interaction-language.md)に既決の規律がある。

> 親しみやすさを、ポップな配色、派手なmotion、マスコット的装飾、ケレン味のある専用演出で代替しない。装飾を外しても、対象・結果・戻し方が分かることをユーザーファーストの基準にする。

マスコットを**ブランド資産**として持つことはこれに抵触しない。抵触するのは、検討中に出た「ペットがレンダー進捗・エラー・BPM同期を示す」という案である。これはマスコットを情報チャネルに昇格させるもので、規律が禁じている代替そのものになる。

したがってペット機能は延期し、実装検討に入る前に次を満たすことを条件とする。

1. ペットが表示する状態は、**すべてペット無しでも読める**こと(ペットは冗長な副チャネルに留まる)
2. ペットを非表示にしても、対象・結果・戻し方の判別が一切劣化しないこと
3. 常駐場所がUI密度の予算を侵さないこと

この3条件を満たせない状態表示(エラー、失敗理由、進捗の唯一の表示)はペットに載せない。

## 7. 注記: Clawd参照について

検討中、Claude Codeのマスコット「Clawd」を「種が確定しないまま識別だけできる」抽象化の例として参照した。ただしその起源はAnthropicの公式文書に記述がなく、確認できたのは二次情報のみである([色変更のissue](https://github.com/anthropics/claude-code/issues/13755))。

[レビュー規律1](README.md)に従い、**この参照は設計根拠にしない**。本件で採用した判断(§4)は、いずれもMotolii側の実物比較で確認したものに限る。

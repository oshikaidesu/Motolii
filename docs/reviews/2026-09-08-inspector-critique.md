# Inspector — 「揃っているのに、触りたくならない」(利用者提示、2026-09-08)

状態: **観察 + 問い**(利用者の原文。採用案ではなく、AE から離れて解法を探すための問い)。
Inspector に触る前に読む。対応する実装・裁定は decision-index から辿る。

---

今の Inspector は、値を収めるための秩序はありますが、人が触って編集するための寸法と手掛かりが弱いです。「揃っているのに、触りたくならない」という感覚には、複数の原因が重なっていそうです。

コードは読まず、現在の画面から整理しました。「観察」は画面で確認できたこと、「仮説」は操作検証が必要なことです。最後の列は採用案ではなく、AE から離れて解法を探すための問いです。

言語化しづらい印象も、切り捨てずに検証対象にできます。ただし、以下は上の問題から受ける主観的な印象で、別々の欠陥として水増しするものではありません。

| 感覚の言葉 | この画面で、その感覚を生む候補 | 比較で確かめること |
|---|---|---|
| 窮屈なのに間延びしている | 縦は圧縮され、横はラベルと操作の間が空く | 同じパネル面積で、操作部分へ面積を移すと改善するか |
| 硬い | 横罫線の反復と、すべてを同じ行に収める構成 | 関連する操作を一つの面として扱うと変わるか |
| 触る前に読む必要がある | 意味の違いをほぼラベルと数値が担う | 初見で「どこをどう触るか」を説明なしに理解できるか |
| 細かい作業を強いられそう | 小さな配置図、右端の小スイッチ、接近した列 | 素早い往復操作で、狙い直しや押し間違いが減るか |
| 自分で操っている感じが薄い | 状態を表示する表の外観が中心 | 値を調整している最中、視線と手の動きが自然につながるか |

新しい解法を探るうえで、最初に疑いたいのは **「Inspector は、プロパティ名と値を縦に並べた表であるべきか」** です。

守るべきなのは、対象を把握できること、狙った結果に調整できること、精密にも扱えること、試して戻せること。現在の行構造や AE の構成は、そのための候補の一つとして扱うのがよいと思います。

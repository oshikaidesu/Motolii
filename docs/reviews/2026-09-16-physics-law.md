## 1 行

**物は箱に住み、行き先へ向かい、場に従い、留め具にぶら下がる。**

数値の欄は 3 つ(重さ・硬さ・ばらつき)だけで、残りは絵の上のハンドルと、文脈からの既定と、さいころ。

## なぜこの形か(日常の物理から)

人は日常で、摩擦係数も質量も操作していない。していることは、置く・積む・押す・落とす・放る・振る・吊るす・引く。そこで気にしているのは 3 つだけ。

1. **行き先** — どこに在ってほしいか
2. **届き方** — 山なりか、まっすぐか
3. **当たり** — 着いた後・触れた後どうなるか

キャッチボールがそのまま。投げる人は速さも角度も計算せず、相手のグローブ(行き先)を見て、山なりかまっすぐか(届き方)を選ぶだけ。受け手が捕るか弾くか(当たり)で終わり方が決まる。

**なぜ本物の物理は変数が多いのか**(利用者の問い)

- 物理の変数は**原因**の目録で、見え方の目録ではない。あらゆる材質と縮尺を 1 式で書くために原因の数が要る
- 見える数はもっと少ない。質量・剛性・減衰の 3 つを動かしても、目に見えるのは揺れの周期と収まりの速さの 2 つで、質量は縮尺と打ち消し合って消える(iOS の `spring(duration:bounce:)` が 3 を 2 にできた理由)。**減らすのは嘘ではなく、見える軸を座標に選び直すこと**
- 物理は前へしか解けないので、着地点を指定できない。だから初速や角度をいじって当たるまで繰り返す。あの変数の半分は「狙い」の代用品。行き先を先に与えると丸ごと消える
- 残るのは本当にどうでもいい差(床の埃、指の癖)。ここは**さいころ**に隠す

## 決めた形 — 4 つの置き場

意味の住所を 1 つずつに決める。同じ意味を 2 か所に置かない。

| # | 置き場 | 持つ意味 | 触り方 | 先例 |
|---|---|---|---|---|
| 1 | **箱**(Display group) | 壁(内で跳ねるか、抜けるか)と間合い(押し合う距離) | 箱の欄 | CSS の `overflow` と `margin` |
| 2 | **物**(層の効果 1 枚) | 行き先へ向かう・着く・当たる | 絵の上の 3 ハンドル | Angry Birds、ビリヤードの撞点 |
| 3 | **場**(それ自身が 1 つの層) | 風・引き寄せ・反発・渦・波 | 矢印 1 本と届く輪 | Cavalry の Field |
| 4 | **留め具**(付いて置く) | ぶら下がる・付いて行く・連なる | 相手を指す | CSS の `anchor()`、既にある Position Anchor |

**これで 1 層 1 効果の制約が解ける。** 今まで Bounce → Push Apart → Bounce が組めなかったのは、3 つを全部「物の効果」に置いていたから。壁と押し合いは箱(1)、場は自分の層(3)、留め具は配置(4)に移るので、物に載る効果は「物理」1 枚で足りる。

**これで CPU と GPU の二重も解ける。** 壁(Overflow = Bounce)と押し合い(Margin)は既に書類の箱の法として在る。意味は箱に 1 つだけ置き、**解くのは GPU、CPU は同じ法の遅い実装**とする(既に試験で 1px 以内に一致している)。法が 2 つあるのではなく、解き手が 2 つある。

## 2 の中身 — 3 つのハンドル

物に「物理」を 1 枚載せると、絵の上にハンドルが出る。数値の欄は出ない。

```
        ◎ 行き先(どこへ・いつ。他の物の上に置けばその物が相手)
       ・
     ・     ← 触る前に点線の軌跡が見える
    ・
   ●━○ 撞点(着いた後どっちへ)
    ╲
     ○ 引き(向き = 山なり ↔ まっすぐ、長さ = 飛び出しの鋭さ)
```

| ハンドル | 決まること | 触らないと |
|---|---|---|
| 行き先 | 着く場所と時刻。物の上に置くとその物が相手になる | 今の配置のまま(置くだけ) |
| 引き | 弧の高さと、飛び出しの鋭さ(強く引くほど鋭く出て、着く前に減速) | 素直に落ちる・素直に寄る |
| 撞点 | 着いた後・当たった後にどっちへ行くか(ビリヤードの押し・引き) | 着いて少し揺れて止まる |

日常の動作がこれで言える:

| 動作 | 行き先 | 引き |
|---|---|---|
| 置く | 置きたい場所 | 引かない |
| 落とす | 真下 | 引かない |
| 放る | 狙う場所 | 引く |
| 押す | 隣の物 | 軽く引く |
| 揺らす(のれん) | 自分の元の位置 | 引いて離す |
| 詰める | 箱 | 引かない(中で押し合って収まる) |

## 手触りの 3 軸と、さいころ

| 軸 | 意味 | 既定 |
|---|---|---|
| **重さ** | 動かしにくさ・押し負けにくさ。跳ねも抑える(下記の嘘) | 物の大きさ(面積)から |
| **硬さ** | エネルギーの返し方。返す ↔ 吸う ↔ 引きずる | 中くらい |
| **ばらつき** | 整列 ↔ 生っぽさ | 0 |

軸は**物ごと**に持つ(2026-09-16 利用者)。箱は持たない。

### 硬さの線(2026-09-16 利用者「soft hard 以外により soft として粘性なども線上に」)

| 位置 | 返し方 | 見え方 | 例 |
|---|---|---|---|
| 0 | 返す | 跳ねる、形は変わらない、揺れが速く細かい | 鋼・ゴム |
| 中 | 吸う | 少し潰れる、揺れが大きくゆっくり、すぐ収まる | 布・スポンジ |
| 1 | 引きずる | 跳ねない、遅れて付いてくる、伸びる、隣とくっつく | 蜜・スライム |

跳ね返り・変形・遅れの 3 つが同じ向きに単調に動くので 1 本で足りる。副産物が 2 つ:

- **C(繋がりの型)の硬さと同じ線**。鎖 = 0 寄り、布 = 中、垂れて戻らない物 = 1 寄り。軸を 2 本持たずに済む
- **粘りの端で「くっつく」が出る**。箱の間合い(margin)を、粘る物ほど詰める・離れないと読めば、押し合いの法をそのまま使える

**1 つ嘘をつく**: 本物の物理では跳ね返りは重さと無関係だが、人の見立てでは重い物はドンと落ちて跳ねない。なので重さが跳ねを抑える。これで「石」(硬いが跳ねない)を別の軸にせずに済む。

さいころ(種)は数を見せない。「振り直す」ボタンだけ。種は物の id から作るので、プレビューと書き出しと再起動で必ず同じ絵になる。1 つだけ手で上書きできる口は残す(「この写しだけ傾けたい」を潰さない)。

## 値は全部、流動的

利用者「質量が突然軽くなるのはモーショングラフィックス特有の動きだ」。**物理の変数は素材の定数だが、モーショングラフィックスの変数は演出**。だから 3 軸もハンドルも、他の値と同じに扱う — 鍵(キーフレーム)も、他の物からの引き込みも、場からの引き込みも刺さる。

- 時間で変わる: 4 秒で重さが 1 → 0 になり、落ちていた物が浮き上がる
- 場所で変わる: 「上へ行くほど軽い」場を 1 つ置くと全員が従う(場が力でなく軸を動かす)

**壊れない理由**: 行き先と時刻を先に決めているので、途中で軸が変わっても両端が固定された道の形が変わるだけで、跳ばない。前へ解く本物の物理なら、質量を途中で変えた瞬間に破綻する。押し合いも毎コマ箱から解き直していて状態を持たない。

流動的にしない物:

| 物 | なぜ | どうするか |
|---|---|---|
| さいころ(種) | 毎コマ変えるとチラつくだけ | 固定。動かすのは「ばらつき」の方 |
| どの箱に住むか | 壁が入れ替わると必ず跳ぶ | ショットの切れ目でだけ |
| 誰とぶつかるか | 手で組を切り替えると跳ぶ | 近さで自動 |

跳ねる「回数」のような数えられる物は持たない。減っていく包み(エンベロープ)として持てば連続になる。回数は見た目の結果であって、値ではない。

## 時間の扱い — 決めた

**時刻の純関数(嘘)**。理由は 3 つ。

1. 軸を流動的にしたいから(積み上げでは途中の変更で破綻する)
2. 行き先と時刻が先に決まるので、積み上げる必要がない
3. スクラブ・巻き戻し・書き出しが必ず一致する(Cavalry は cache を焼いて凌いでいる)

押し合いだけは毎コマ内で繰り返す(今の `"ROUNDS"`)。これはコマ間に状態を持たないので純関数のまま。

## 重力は置ける値(2026-09-16 利用者「重力を自由に決めれるのもモーショングラフィックスの良い点だ」)

重力は文脈の定数ではなく、**箱が既定で 1 本持っている場の矢印**とする。

| 誰が持つ | 何を決める |
|---|---|
| 箱 | 下の向きと強さ(矢印 1 本)。0 にすれば無重力 |
| 物 | 重さ = その重力がどれだけ効くか(軸の 1 本) |
| 場(層) | 足し込む。点へ引く・渦・風 |

これで**重力・風・引き寄せ・渦が 1 つの口**になる。違うのは形だけ: 平行(重力・風)、点(引き寄せ・反発)、渦、線(道に沿う)。Cavalry が Gravity(Solver の欄)と Field(節点)に分けていた所を 1 本に畳める。

重力も流動的にする。1 つ触って全体が動く一番強い形になる。

- 4 秒で下が 90° 回る → 箱の中身が全部転がり直す。触ったのは箱 1 つ
- 拍で重力が反転する → 全員が浮いて、また落ちる
- 重力の向きを別の物へ向ける → その物が引力の中心になる

**向きの基準**: 重力は**箱の向きに従い、カメラには従わない**。箱を傾ければ中身は滑り、カメラを傾けても何も起きない。上の 3D の節で「上は世界の上」と書いたが、正しくは「箱の上」。世界は一番外の箱。

**行き先を持つ物との関係**: 行き先を持たない物は場に素直に従う(落ちる・流される)。行き先を持つ物は、場が**弧の形を変えるだけ**で、着く場所と時刻は動かない。だから重力を途中で変えても狙った着地は崩れない。

## 境目を作らない — 既存の概念を連続体にする(2026-09-16 利用者)

利用者「既存の概念を連続体にすることでユーザはモードを切り替える境界を作らず自由な表現を生み出せないか? 理解も容易くならないか?」。**通る**。場の `Shape`(平行 / 点 / 渦の 3 択)を 2 本の連続した目盛りに畳んだ(実装済み、`vism/field.wgsl`)。

| 目盛り | 端から端へ |
|---|---|
| **Turn** | 0° 引き寄せ → 90° 渦 → 180° 押し出し。途中は**渦を巻きながら寄る**(3 択では出せなかった絵) |
| **Spread** | 0 元から(点の場)→ 1 一様な向き(重力・風)。元が無限に遠い極限が重力、という関係そのもの |

得た物は 3 つ。

- **モードの境目が無い**ので、目盛りに鍵を打てる(切り替えは飛ぶが、目盛りは繋がる)
- **名前の無い間**が使える(螺旋、寄りながら流れる)。3 択では作者が選んだ 3 点しか使えない
- **説明が短い**。「向きと広がり」の 2 語で、重力・引力・斥力・渦・風が言える

同じ読みは他にも当たる: 硬さ(返す ↔ 吸う ↔ 引きずる)は既に連続体。残っているのは、**壁 ↔ 当たり ↔ 素通り**(今は箱の 3 択の欄)、**2D / 3D の札**(これは利用者裁定で自動化しない)。

## 壁は既定にしない(2026-09-16 利用者)

利用者「実際のモーショングラフィックスで壁って使うかなぁ。毎回壁の設定をするのが困る。落ちてる感だけが欲しいのかもしれません。ここも関係性かも、お互いの箱にぶつかるとかの方がよく使う」。

- **既定は物同士の当たり**(箱と箱がぶつかる)。これも関係で、実際よく使うのはこちら。間合いは各物の `Margin`(書類に既にある法)
- **壁は箱の欄に在るが、既定は無し**(`Overflow = Bounce` を箱が頼んだ時だけ)。CSS も同じで、普通の流れでは要素は箱から落ちず、互いに押し合うだけ
- **「落ちてる感」は床ではなく行き先で出す**。落ちる絵で欲しいのは落ちて**所定の位置に収まる**こと。行き先はレイアウトが既定で持ち、重力は届き方(弧と勢い)だけを決める。だから床も壁も要らない

## レイアウトが環境(2026-09-16 利用者)

利用者「ユーザはもう既にレイアウト構図という形で、壁や地面を無意識下で設定しているのではないか? グラフィックとして」。**通る**。人は箱を並べた時点で、床も壁も余白も決めている。物理はその上に足す物で、別の世界を作る物ではない。

- **行き先はレイアウト**。落ちてくる先は箱が既に決めた所。効果が言うのは「どう届くか」だけ(`vism/arrive.wgsl`: From / Distance / Arrive / Bounce / Stagger / Spin、鍵 0 本)
- **家もレイアウト**。場は配置からの逸れで、**Hold** が家との紐の長さ(0 = 家を離れて箱の底まで、1 = 離れない。間は膨らんで戻る)。これで収まりが構造として保証される
- **当たりの箱も並べた結果から取る**。Fill で伸びた升目は輪郭が伸びるので、伸び(`Slot.stretch`)を掛けないと当たりが元の形の大きさのままになる(不具合として直した)

**直した穴**: 物は層を組む**前**に揃えて解くようにした(箱・輪郭・場は解いた配置から取れる)。解いたずれは書類へ渡し、箱を読む所(`box_seen_from`)が足すので、つなぐ線と札が動いた相手に付いて行く(1 コマ遅れ)。輪郭の平滑化は lyon(曲がりに合わせて点を割る)。

**当たりは「効果を通した後の透過」**(2026-09-16 利用者「根本から解決する。将来的にはアルファで抜きたいためです。クロマキー以外のエフェクトで抜くようにもしたいから」):

- 抜き方を物理は知らない。解析の段で層を 1 枚ずつ組んで**描かれた透過**を読み、その形を当たりにする(クロマキー・マット・アルファ、今後どの効果でも同じ)。その間は物理を解かない(世界が 1 枚で組み直されるため)
- 輪郭は**辺を辿って**取る(`media::outline_from_mask`、Moore 近傍)。方向ごとの最遠点(`silhouette_from_mask`、3D の族)だと星の谷が消えて凸包になる
- 凹みが効くよう Rapier の**凸分解**で持つ
- 棚に **Chroma Key**(`vism/chroma_key.fs`): 色差で近さを測り、内側は抜く・外側は残す・間はなめらか、縁の色かぶりを引く(先例: Keylight、Ultra Key)
- 代償: キーの載った絵・動画は 1 コマにつき 1 回読み戻す(解析の段。既に塊の追跡が同じ事をしている)

**残る穴**: 並べる箱の**子どうし**を結ぶ線が描かれない(道は解けているのに絵に出ない。物理とは別の、書類か描画の穴)。

**見つかった穴**: つなぐ線(Connect From / To)は書類側(CPU)で解くので、GPU のブロックで動いた端に付いて来ない。札は FollowPass で付いて行くが、線の端はまだ。当面は糸も同じ `Hang` で吊って合わせている(組み合わせの拍を揃えるため `Beat` の欄を足した)。

## 解き手は借りる(2026-09-16 利用者「物理演算を 1 から作るんじゃなくてこれも外部に揃ったやつがあるだろ」)

**その通りで、ここは自作すべきでない所だった。** slop も bias も焼きなましも、既製品が持っている物の劣化版。

採った物: **Rapier**([rapier.rs](https://rapier.rs/)、dimforge、Apache-2.0、Rust)。積み上げの warm start・摩擦・joint・**状態の保存(snapshot)**・任意の決定性を持つ。先例: Cavalry は Box2D(Rapier はその Rust 版に snapshot が付いた物)。

| ここが持つ物 | Rapier が持つ物 |
|---|---|
| 意図(箱・物・場・留め具)と felt な軸、連続体の目盛り | 接触・摩擦・反発・積み上げ・joint・眠り |
| 意図 → 重力・力・壁への**訳** | 解き方 |
| 描く側へ渡す道(motion、読み戻さない) | — |

- **時間は列になった**(利用者「前のコマの力を覚えるべきです」)。1 コマ進める度に世界を進め、飛んだら組み直して解き直す(240 コマまで)。狙い(着地・吊り)は今まで通り時刻の純関数
- 箱に蓋はしない(物は上から入って来る)。丸い箱は厚い円弧 48 枚で囲い、上は注ぎ口として開ける
- 消した物: `vism/room.wgsl`(自作の押し合い・詰め・収め)と、GPU の場の展開

結果: 物同士がめり込まなくなり(自作では 123px 重なっていた)、互いに乗って積み上がる。落ち着いた後の震え 4.2px/コマ。

**ディレイとの違い**(利用者の問い「これ確かディレイとかのエフェクトの時にもやったけど物理だとまた違うのか?」): ディレイが覚えるのは**出来上がった絵**で、鎖は直近 N コマだけ。物理が覚えるのは**答えそのもの**で、0 コマ目から効く。だから飛ばすと違う絵になり、Cavalry は `.sdcache` に焼いている。

## 手触りは 1 本の軸(実装、2026-09-16)

書類に 2 つの欄を足した(提案): **Hardness**(0 返す ↔ 0.5 吸う ↔ 1 引きずる)と **Heaviness**(重さ、0 なら動かない)。人は摩擦係数を操作しないので、解き手の欄(摩擦・反発・減衰)はこの 1 本から作る。

| Hardness | 摩擦 | 反発 | 減衰 | 見え方 |
|---|---|---|---|---|
| 0 | 0.15 | 0.55 | 低い | 跳ねて転がる |
| 0.5 | 0.68 | 0 | 中 | 当たって止まる |
| 1 | 1.2 | 0 | 高い | 引きずって崩れない |

場の欄からは、解き手に移った物(Tumble)を落とした。残るのは意図だけ: Turn / Spread / Angle / Strength / Reach / Hold。見本 `matter.js`(24 行)。

## 可視のモード(実装、2026-09-16)

利用者「画の引力やハンドルも可視できるモードがいるべきだ。Tracery が人気なのは画の説明力、情報量を手軽に増やせるモードが欲しかったからだと思います」。

**Physics Trace**(Track Overlay の族に 1 枚)。箱・印・札の欄はそのまま使い、物理だけの物を足した:

- 箱と印は**解き手が持っている物**から取る(下の層ではなく。箱の中の子は「下の層」に出て来ない)
- **触れ合いの線**: 今まさに接触している組を結ぶ(Rapier の contact pair)
- **場**: 届く輪(点線)と、向きの矢
- 絵を組む途中で解き手を 1 歩進めてから読む(そうしないと 1 コマ遅れる・空になる)
- 可視の層とつなぐ線は、物理の物にしない(見せるための層は画の中身ではない)

見本 `trace.js`。

## 震えの直し方(2026-09-16、利用者「まだまだガッタガタやぞ。これはコリジョンのめり込みかな」)

当たっていた。先行資料の定石をそのまま外していた。

| 定石 | 出典 | 外していた所 |
|---|---|---|
| 重なりを 0 にしようとすると必ず震える。少しめり込ませる(slop) | [Catto, Modeling and Solving Constraints, GDC 2009](https://box2d.org/files/ErinCatto_ModelingAndSolvingConstraints_GDC2009.pdf)、[Onarheim, Understanding Collision Constraint Solvers](https://erikonarheim.com/posts/understanding-collision-constraint-solvers/) | 毎回、深さを全部押し戻していた |
| 深さの一部だけ直す(Baumgarte の bias) | 同上 | 相手ごとの直しを全部足していた(行き過ぎ) |
| 回数では買えない、刻みの方が効く | [Macklin ほか, Small Steps in Physics Simulation, SCA 2019](https://mmacklin.com/smallsteps.pdf) | 96 回まで増やしていた(増やすほど暴れる) |
| 積み上げの安定は warm start(前のコマの力を覚える)で稼ぐ | 同上・Catto | **こちらは持てない**(時刻の純関数)。だから収束の速さではなく、入力に対する滑らかさを選ぶ |

直した形: めり込みは大きさの 3% まで許す、直しは相手の数で割って 0.25 倍、回数は 16。場は元の近くで距離に芯を持たせる(N 体計算の softening)。家に留めてある物(Hold)は時間で積み上げず距離だけの場にする(積み上げると紐で頭打ちになり、元が離れた時に一気に戻る)。

測り方も直した。**画素の平均差では物ごとの震えは見えない**。物ごとの位置をコマ順に読み(`examples/zz_jitter.rs`、`Engine::block_states`)、1 コマの動きとコマ間の差を見る。

| 見本 | 直す前 | 直した後 |
|---|---|---|
| pour / pile | 300〜500px/コマ | **0.00px**(完全静止) |
| magnet | 152px | 2.7px |
| swirl | 110px | 17px |
| bulge | 605px | 25px(元が動いているので動くのが正しい) |

## 物理の 3 つの家族

| 家族 | 行き先 | 置き場 | 例 |
|---|---|---|---|
| A 投げる型 | ある | 物(2) | 落ちる・跳ねる・置く・詰める・押す・積む |
| B 場の型 | ない | 場(3) | 風・引き寄せ・反発・渦・爆発・波 |
| C 繋がりの型 | 留め具が持つ | 留め具(4) | 紐・鎖・布・のれん・後ろに付く札 |

3 つは重ねられる。1 つの物が、行き先を持ち、風の中にいて、紐で吊られている。今のブロックが効果の順につながる形と同じ。

流体・煙・破砕・ラグドールはやらない(Cavalry も持たず、Sync にも要らない)。ただし B の口に乗るので、後から外の拡張として足せる。天井は作らない。

## 3D は遊びに答えがある(2026-09-16 利用者)

先例: BotW の弓と爆弾、PUBG / Fortnite の手榴弾の弧、Worms 3D、ゴルフ、ビリヤード。共通の形は 4 つ。

- **行き先は、光線が当たった面に吸い付く**。箱の床、相手の物の面。奥行きは行き先が持つ
- **引きは、いつも画面の面**。手つきは 2 次元のまま、奥行きを引かせない(遊びが奥行きを引かせないのは、見えないから)
- **弧は世界で解いて、投影して描く**。着地に輪を出す(遊びが必ず出している)
- **上は箱の上**(重力)。画面の上ではない。世界は一番外の箱(下の節)

これで [前の文書](2026-09-15-physics-gesture.md) の「3D で引く面はどこか」は消える。引く面は画面、着く面は当たった面。

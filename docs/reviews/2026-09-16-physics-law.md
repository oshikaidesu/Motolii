## 1 行

**物は箱に住み、行き先へ向かい、場に従い、留め具にぶら下がる。**

数値の欄は 3 つ(重さ・硬さ・ばらつき)だけで、残りは絵の上のハンドルと、文脈からの既定と、さいころ。

## なぜこの形か(日常の物理から)

人は日常で、摩擦係数も質量も操作していない。していることは、置く・積む・押す・落とす・放る・振る・吊るす・引く。そこで気にしているのは 3 つだけ。

1. **行き先** — どこに在ってほしいか
2. **届き方** — 山なりか、まっすぐか
3. **当たり** — 着いた後・触れた後どうなるか

キャッチボールがそのまま。投げる人は速さも角度も計算せず、相手のグローブ(行き先)を見て、山なりかまっすぐか(届き方)を選ぶだけ。受け手が捕るか弾くか(当たり)で終わり方が決まる。

**なぜ本物の物理は変数が多いのか**(利用者の問い)

- 物理の変数は**原因**の目録で、見え方の目録ではない。あらゆる材質と縮尺を 1 式で書くために原因の数が要る
- 見える数はもっと少ない。質量・剛性・減衰の 3 つを動かしても、目に見えるのは揺れの周期と収まりの速さの 2 つで、質量は縮尺と打ち消し合って消える(iOS の `spring(duration:bounce:)` が 3 を 2 にできた理由)。**減らすのは嘘ではなく、見える軸を座標に選び直すこと**
- 物理は前へしか解けないので、着地点を指定できない。だから初速や角度をいじって当たるまで繰り返す。あの変数の半分は「狙い」の代用品。行き先を先に与えると丸ごと消える
- 残るのは本当にどうでもいい差(床の埃、指の癖)。ここは**さいころ**に隠す

## 決めた形 — 4 つの置き場

意味の住所を 1 つずつに決める。同じ意味を 2 か所に置かない。

| # | 置き場 | 持つ意味 | 触り方 | 先例 |
|---|---|---|---|---|
| 1 | **箱**(Display group) | 壁(内で跳ねるか、抜けるか)と間合い(押し合う距離) | 箱の欄 | CSS の `overflow` と `margin` |
| 2 | **物**(層の効果 1 枚) | 行き先へ向かう・着く・当たる | 絵の上の 3 ハンドル | Angry Birds、ビリヤードの撞点 |
| 3 | **場**(それ自身が 1 つの層) | 風・引き寄せ・反発・渦・波 | 矢印 1 本と届く輪 | Cavalry の Field |
| 4 | **留め具**(付いて置く) | ぶら下がる・付いて行く・連なる | 相手を指す | CSS の `anchor()`、既にある Position Anchor |

**これで 1 層 1 効果の制約が解ける。** 今まで Bounce → Push Apart → Bounce が組めなかったのは、3 つを全部「物の効果」に置いていたから。壁と押し合いは箱(1)、場は自分の層(3)、留め具は配置(4)に移るので、物に載る効果は「物理」1 枚で足りる。

**これで CPU と GPU の二重も解ける。** 壁(Overflow = Bounce)と押し合い(Margin)は既に書類の箱の法として在る。意味は箱に 1 つだけ置き、**解くのは GPU、CPU は同じ法の遅い実装**とする(既に試験で 1px 以内に一致している)。法が 2 つあるのではなく、解き手が 2 つある。

## 2 の中身 — 3 つのハンドル

物に「物理」を 1 枚載せると、絵の上にハンドルが出る。数値の欄は出ない。

```
        ◎ 行き先(どこへ・いつ。他の物の上に置けばその物が相手)
       ・
     ・     ← 触る前に点線の軌跡が見える
    ・
   ●━○ 撞点(着いた後どっちへ)
    ╲
     ○ 引き(向き = 山なり ↔ まっすぐ、長さ = 飛び出しの鋭さ)
```

| ハンドル | 決まること | 触らないと |
|---|---|---|
| 行き先 | 着く場所と時刻。物の上に置くとその物が相手になる | 今の配置のまま(置くだけ) |
| 引き | 弧の高さと、飛び出しの鋭さ(強く引くほど鋭く出て、着く前に減速) | 素直に落ちる・素直に寄る |
| 撞点 | 着いた後・当たった後にどっちへ行くか(ビリヤードの押し・引き) | 着いて少し揺れて止まる |

日常の動作がこれで言える:

| 動作 | 行き先 | 引き |
|---|---|---|
| 置く | 置きたい場所 | 引かない |
| 落とす | 真下 | 引かない |
| 放る | 狙う場所 | 引く |
| 押す | 隣の物 | 軽く引く |
| 揺らす(のれん) | 自分の元の位置 | 引いて離す |
| 詰める | 箱 | 引かない(中で押し合って収まる) |

## 手触りの 3 軸と、さいころ

| 軸 | 意味 | 既定 |
|---|---|---|
| **重さ** | 動かしにくさ・押し負けにくさ。跳ねも抑える(下記の嘘) | 物の大きさ(面積)から |
| **硬さ** | エネルギーの返し方。返す ↔ 吸う ↔ 引きずる | 中くらい |
| **ばらつき** | 整列 ↔ 生っぽさ | 0 |

軸は**物ごと**に持つ(2026-09-16 利用者)。箱は持たない。

### 硬さの線(2026-09-16 利用者「soft hard 以外により soft として粘性なども線上に」)

| 位置 | 返し方 | 見え方 | 例 |
|---|---|---|---|
| 0 | 返す | 跳ねる、形は変わらない、揺れが速く細かい | 鋼・ゴム |
| 中 | 吸う | 少し潰れる、揺れが大きくゆっくり、すぐ収まる | 布・スポンジ |
| 1 | 引きずる | 跳ねない、遅れて付いてくる、伸びる、隣とくっつく | 蜜・スライム |

跳ね返り・変形・遅れの 3 つが同じ向きに単調に動くので 1 本で足りる。副産物が 2 つ:

- **C(繋がりの型)の硬さと同じ線**。鎖 = 0 寄り、布 = 中、垂れて戻らない物 = 1 寄り。軸を 2 本持たずに済む
- **粘りの端で「くっつく」が出る**。箱の間合い(margin)を、粘る物ほど詰める・離れないと読めば、押し合いの法をそのまま使える

**1 つ嘘をつく**: 本物の物理では跳ね返りは重さと無関係だが、人の見立てでは重い物はドンと落ちて跳ねない。なので重さが跳ねを抑える。これで「石」(硬いが跳ねない)を別の軸にせずに済む。

さいころ(種)は数を見せない。「振り直す」ボタンだけ。種は物の id から作るので、プレビューと書き出しと再起動で必ず同じ絵になる。1 つだけ手で上書きできる口は残す(「この写しだけ傾けたい」を潰さない)。

## 値は全部、流動的

利用者「質量が突然軽くなるのはモーショングラフィックス特有の動きだ」。**物理の変数は素材の定数だが、モーショングラフィックスの変数は演出**。だから 3 軸もハンドルも、他の値と同じに扱う — 鍵(キーフレーム)も、他の物からの引き込みも、場からの引き込みも刺さる。

- 時間で変わる: 4 秒で重さが 1 → 0 になり、落ちていた物が浮き上がる
- 場所で変わる: 「上へ行くほど軽い」場を 1 つ置くと全員が従う(場が力でなく軸を動かす)

**壊れない理由**: 行き先と時刻を先に決めているので、途中で軸が変わっても両端が固定された道の形が変わるだけで、跳ばない。前へ解く本物の物理なら、質量を途中で変えた瞬間に破綻する。押し合いも毎コマ箱から解き直していて状態を持たない。

流動的にしない物:

| 物 | なぜ | どうするか |
|---|---|---|
| さいころ(種) | 毎コマ変えるとチラつくだけ | 固定。動かすのは「ばらつき」の方 |
| どの箱に住むか | 壁が入れ替わると必ず跳ぶ | ショットの切れ目でだけ |
| 誰とぶつかるか | 手で組を切り替えると跳ぶ | 近さで自動 |

跳ねる「回数」のような数えられる物は持たない。減っていく包み(エンベロープ)として持てば連続になる。回数は見た目の結果であって、値ではない。

## 時間の扱い — 決めた

**時刻の純関数(嘘)**。理由は 3 つ。

1. 軸を流動的にしたいから(積み上げでは途中の変更で破綻する)
2. 行き先と時刻が先に決まるので、積み上げる必要がない
3. スクラブ・巻き戻し・書き出しが必ず一致する(Cavalry は cache を焼いて凌いでいる)

押し合いだけは毎コマ内で繰り返す(今の `"ROUNDS"`)。これはコマ間に状態を持たないので純関数のまま。

## 物理の 3 つの家族

| 家族 | 行き先 | 置き場 | 例 |
|---|---|---|---|
| A 投げる型 | ある | 物(2) | 落ちる・跳ねる・置く・詰める・押す・積む |
| B 場の型 | ない | 場(3) | 風・引き寄せ・反発・渦・爆発・波 |
| C 繋がりの型 | 留め具が持つ | 留め具(4) | 紐・鎖・布・のれん・後ろに付く札 |

3 つは重ねられる。1 つの物が、行き先を持ち、風の中にいて、紐で吊られている。今のブロックが効果の順につながる形と同じ。

流体・煙・破砕・ラグドールはやらない(Cavalry も持たず、Sync にも要らない)。ただし B の口に乗るので、後から外の拡張として足せる。天井は作らない。

## 最小の意図で最大の画(Sync で数える)

| 画 | 手 |
|---|---|
| 2 つの円が近づいて重なる | 行き先 2 つ |
| 文字が重なった所に付く | 留め具 1 つ(既に動いている) |
| 升目に詰まる | 箱 1 つ(間合い) |
| 物が波打って揃う | 場 1 つ |

数値を打つ操作は 0。触るのは、行き先・箱・場・留め具の 4 種類だけ。

## 3D は遊びに答えがある(2026-09-16 利用者)

先例: BotW の弓と爆弾、PUBG / Fortnite の手榴弾の弧、Worms 3D、ゴルフ、ビリヤード。共通の形は 4 つ。

- **行き先は、光線が当たった面に吸い付く**。箱の床、相手の物の面。奥行きは行き先が持つ
- **引きは、いつも画面の面**。手つきは 2 次元のまま、奥行きを引かせない(遊びが奥行きを引かせないのは、見えないから)
- **弧は世界で解いて、投影して描く**。着地に輪を出す(遊びが必ず出している)
- **上は世界の上**(重力)。画面の上ではない

これで [前の文書](2026-09-15-physics-gesture.md) の「3D で引く面はどこか」は消える。引く面は画面、着く面は当たった面。

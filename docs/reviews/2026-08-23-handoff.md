## 0. 最初に読む — main はいま赤い

**`motolii-export` / `motolii-inspector-pane` / `motolii-timeline-pane` / `motolii-shell` /
`motolii-engine` のテストがコンパイルできない。** `motolii-store`/`motolii-eval` は緑。

`E0560`/`E0609`(`EffectInstance` に `enabled` フィールドが無い)と

- 壊れる箇所は実装レーンが**網羅列挙済み**(下記 §3)。設計の穴ではなく単なる追随待ち

**次セッションの第1手は REWIRE の回収**(§3)。

## 2. 後半の経路 — 「畳めるもの」はどう見つかったか

**この節が本文書の中心。** 結論(裁定213〜216)だけ移すと次のセッションで同じ回り道をする。

### (a) 台帳では見つからないと分かった

ペルソナ第2周が **量の壁**を3つ出した — Timeline に縦スクロールが無い・複数選択への一括編集が無い・
複製が単一のみ。**3件とも `normal-map.tsv` に対応行が無い**(「Timeline はスクロールできること」と
書く製品仕様が世の中に無いため)。→ **裁定207**: 台帳は動詞の在庫であって規模の要件を持たない。
台帳消化率は完成度の指標にならない。

### (b) 前提を減らしたら重なった

第3周は**裁定も台帳も仮説も渡さず**、「普通に1本作れ」と4つの問い
(何を何回やったか / さっきのと同じでは? / 一度も変えなかった値 / 分かれている意味が分からなかった区別)
だけを渡した。第2周までの詰め込んだ発注では出なかった物が出た。

**3本が独立に同じ物を指した**:

- 同じ「位置を動かす」が Inspector 経由で **2 undo**、gizmo 経由で **1 undo**
- `ToggleKeyframeAtPlayhead` が実装済みで**呼び手ゼロ**、生きているのは Inspector 側だけ
- New Layer(メニュー)と Browser の Solid カードが**別関数で同一の Intent 列と同一の定数**を書いている
- Freeze(Group 専用・専用 Intent)と Lock(任意レイヤー・attrs)が同じ「触れないようにする」の二機構

そして B1 が健全な対照を書いた — **Copy/Paste/Duplicate は3動詞1実装で気持ちがいい**。
export の5関数も実体1本で問題ない。→ **多対一は健全、一対多が病気**。

### (c) 抽象化は「機構の統一」ではなく「規則1本」から来た

利用者の裁定でここが折れた。**接続子を加算にする**(裁定213)と、型付き port も provider→consumer の
対応表も要らなくなる。旧世界 vism が Kit を型で繋ごうとして 169 本の docs を書き、Host integration 層が
立つ前に世界が終わった、その設計量が**丸ごと消える**。

境界は**発明せずに型から出た**: `Value` の `Bool`/`Enum`/`LayerId` は doc に自分で「補間は Hold」
(「0.5番目の選択肢は存在しない」)と書いており、**加算が無意味な型と完全に一致**した。

続けて**映る物は全て時間軸に乗る**(裁定214)。AE はレイヤースイッチにストップウォッチを付けず、
Ableton は on/off までオートメーションできる。Ableton 側を採ると、「これはキーフレームが打てて、
これは打てない」という**個別判断が消える**。

**どちらも例外を1つずつ裁くのをやめる形**なので、判断の総量そのものが減る。
旧世界の死因が量なら、効くのはこの向き。

### (d) 根幹は「根幹が無いこと」だった

利用者の総括:

> motolii そのものの根幹はない。motolii に意味は無いため、説いても答えは出ない。
> **コンセプトすら委託している**。しかしそれはパッチワーク思想という、それ自体が根幹となっている。

→ **裁定215**。ここから成果物が3つ出た(§4)。

## 8. 数え方の軸(利用者との対話で出た、覚えておくと効く物)

「値によって変数の数がコロコロ変わる」問題は、**2本の軸を1本に潰していた**のが原因。

| 軸 | 何を指すか | 先例 |
|---|---|---|
| **instance** | 頂点 N 個の何番目か | rerun のコンポーネントバッチ |
| **成分** | 1つの値の x か y か z か | Lottie の `split-position`(**採用済**・`resolve_position`/`POSITION_X`/`POSITION_Y`) |

この2次元で見ると規則的になる: `F64` = 1×1 / `Vec2` = 1×2 / `Color` = 1×4 / `Path` = N×2。
実装は**成分軸のみ**(既存の split 規約を流用・新語を作っていない)、instance 軸は
「今は 1 に固定・将来の拡張点」と doc に明記されている。

**アリティは値の性質ではなく補間の性質**(`Vec2` がひとまとまりなのは空間の曲線として補間したいから。
割るとモーションパスが失われる = AE の Separate Dimensions の代償。Lottie が両形を持つ理由)。
だから**変調はアリティを見なくてよい**。

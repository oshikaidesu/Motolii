# 裁定177 — 意図統合の原則: map の運転単位は「意図束」・統合できる操作は統合する・1意図=1つの家

日付: 2026-08-22(延長戦) / 状態: **決定** / 起点: 利用者裁定「意図でまとめる。操作意図で統合できる部分は統合してしまいたい — **AE の悪い部分は意図が散らばって視線があちこちに行くこと**だったから」

## 1. 原則

1. **map の運転単位を行から「意図束」へ**: 束= 1つの操作意図(パラメータ付き動詞)。4製品由来のカテゴリ(出典側の整理)は保持するが、消化・発注・集計は束で行う
2. **統合は積極方針**: 複数行が1つの意図で語れるなら統合してしまう(MA の L4 縮約を提案から方針へ格上げ — `set_work_area{in?,out?}`・`apply_ease(scope,side)` の型)。freq は束単位で再計算
3. **1意図=1つの家(視線の一点性)**: 統合された意図は UI 上も一箇所に住む。S3(視覚動線)の操作版 — 意図の散在=視線の散在、という AE の反面教師を構造で禁止する。S6(併存)とは両立: 入口(shortcut/menu)は複数でよいが、**意図の家(設定・状態・操作面)は一箇所**

## 2. 運転

- 起案レーンが採用予定+保留+拡張の全行を意図束へ割り付け(各行ちょうど1束)・束ごとに 意図動詞署名/行id列/状態rollup/大きさ/L8基盤共有 を持つ草案を作る
- **束の命名と形は利用者が直す**(なんとなく=直観が最上流 — 草案は機械的に、確定は利用者の一瞥で)
- 確定後: `normal-map.tsv` へ bundle 列を追加し、check 系で「採用予定行の束無し=違反」を機械化。以後の発注書は束を名指す

# 普通の編集を1本やってみた記録(2026-08-22)

`next/`(motolii、iced+rerun store+re_renderer+FFmpegの薄いラッパー)で、素材を並べて・切って・文字を載せて・書き出す、という普通の編集を1本やった。手順は実 Message/Intent の経路をコードで辿り(`Shell::update`各腕・`Document::apply_all`・pane crate の `write.rs`/`split.rs`/`create_from_card`)、`ffmpeg`で作った実テスト動画を使って`Shell::admit`の経路も確認した。詰まった所(Split・Effect追加)は迂回せず、そこで止めて先へ進んだ。

## 1. 何を何回やったか

- **素材を置く**: `ffmpeg`で作った5秒のテスト動画(`testsrc`+`sine`、640x360/30fps)をOS drop相当の経路(`Message::AdmitPaths`→`Shell::admit`)で1回投入。`admit`は投入した瞬間に**台帳登録**(`Intent::AdmitAsset`、ハッシュ計算のみ)と**timeline配置**(`ffprobe`実行→`Intent::AddLayer`+`SetMeta{LayerSource::Media}`、playhead位置に自動配置)を1回の`apply_all`でまとめて行う——「取り込む」と「置く」は分けて考えていたが、コード上は1動作だった。
- **層を追加する動詞**を数え直すと、実は同じ3点セット(`AddLayer`+`SetMeta`+`SetAttrs{label_color}`→1 `apply_all`)が入口違いで6回登場する: Layer メニュー「New Layer」(`Message::AddLayer`、常にSolid)、Browser Create タブの5枚のカード(Rectangle/Ellipse/Solid/Null/Text、`CreateFromCard`)。Solidに関しては前者と後者が**別々の関数**(`lib.rs`の`Message::AddLayer`腕 と `create_from_card`のSolid腕)で、色(80,160,220)もサイズ(240×135)も同じ値を別の場所に書いている。
- **切る(Split)**: `motolii_timeline_pane::split::split_plan`をコード上で辿った——playheadでlayerを割ると、元layerの`duration`を縮め、複製layerを`source_in`(speed込み写像)から起こし、keyframe/mask/effect/text documentを全部複製先へコピーする、という中身は追えたが、**実際に動かすことはできなかった**: メニュー・ショートカット(`Cmd+B`)・右クリックのどこにもこの動詞への入口がなく(`motolii-menubar/src/context.rs`が「Split: 存在しない」と自己申告している)、シェルを経由して呼ぶ手段が無い。ここで1回止まった。
- **文字を載せる**: Browserの Create タブの「Text」カードをダブルクリックする経路(`CreateFromCard{kind: Text}`)を1回辿った——Layer メニューには文字レイヤーを作る項目が無く、唯一の入口がここだった。作成直後に`Intent::SetTextDocument`(既定文字列・サイズ100pt・黒・左揃え)も同じ1操作に含まれる。文字入力は`Inspector`の`TextFieldInput(Content, "…")`→`TextFieldSubmit`で1往復。フォントは`motolii-font-catalog`の既定フォント(Helvetica系列を優先するリスト)が自動で選ばれるので、何もしなくても画に出る。
- **書き出す**: Export窓を開く(`ToggleExportDialog`、別OS windowで開く——Settingsと同じ形)→出力先を選ぶ(実`rfd`保存ダイアログ、`.mp4`固定)→Export実行(`Shell::start_export`→`motolii_export::export_with_cancel`)を1回。フォーマットはMP4/H.264固定、品質はCRF18/qp0losslessの二択のみで、どちらも選ぶ余地はあるが増減できない。

## 2. 「これ、さっきのと同じでは?」と思った所

- **New Layer(メニュー)とBrowserのSolidカード**。ラベルも辿る動詞名も違うのに、書いているIntentの列も定数(色・寸法)も一言一句同じ。なぜ2つの関数に分けて書いてあるのか、コード上の理由(履歴的経緯以外)は見当たらなかった。
- **Copy/Paste/Duplicate**。3つの別動詞に見えるが、中身は`LayerSnapshot::capture`+`instantiate`という1組のペアの使い回しだった(Duplicateはクリップボードに触れず即captureして即instantiateするだけ)。こちらは逆に「同じで良い」ケース——見た目は3動詞、実装は1つ、というのが健全に感じた分、New Layer側の「見た目が違って実装が同じなのに関数が2つ」との対比が余計に目についた。
- **Import(File>Import Media…)とOS drop**。メニュー経由かdrag&drop経由か、体験としては別物のつもりだったが、両方とも最終的に同じ`Message::AdmitPaths`→`Shell::admit`に合流する。これは「同じで当然」に近い側で、違和感はなかった。
- **exportの複数関数**(`export`/`export_with_cancel`/`export_with_progress`/`export_range`/`export_range_with_cancel`)。名前を見た瞬間は「5通りのexportがあるのか」と身構えたが、全部`export_range_with_progress`という1つのループへの薄い呼び出し口で、実体は1本だった。

## 3. 一度も変えなかった値

- 新規レイヤー(Solid/Rectangle/Ellipse)の既定色 `rgba(80,160,220,255)` と既定サイズ `240×135`——New Layerを何回押しても、Browserのどのカードから作っても同じ値。変える設定項目がどこにもない。
- テキストの既定スタイル: サイズ`100.0pt`・塗り`黒`・左揃え。フォントも自動選択(候補順位`Helvetica > Arial > Helvetica Neue > Liberation Sans > DejaVu Sans > Noto Sans > Verdana`固定)で、これも触らずに文字が出た。
- 書き出しのコンテナ/コーデック `MP4 / H.264`——選択肢自体が無く、この1点で固定。色空間タグも常に`bt709`limited-range(`-colorspace bt709 -color_range tv`等)で、素材が実際どんな色空間でもここに揃えられる。
- import側のファイル形式フィルタ(video: mp4/mov/mkv/webm/avi/m4v、image: jpg/jpeg/png/gif/webp/bmp/svg、audio: wav/mp3/aac/flac/ogg/m4a)——ダイアログのフィルタ自体を選ぶ操作は無く、常にこの3群固定。

## 4. 分かれている意味が分からなかった区別

- **Freeze(Group専用)とLock(任意layer)**。どちらも「書き込みを拒否する」効果に見えるのに、Freezeは`Intent::Freeze`/`Unfreeze`という専用の口を持ちGroup層にしか効かず、Lockは`LayerAttrs.locked`という別フィールドで任意のlayerに効く。両方とも「触れないようにする」機構なのに、なぜ2つの別実装(別Intent、別チェック関数)に分かれているのか、ドキュメントを読んでも「Groupだから特別扱い」以上の理由は見えなかった。
- **CreateFromCardのRectangleとEllipse**。Browser上では別カード(見た目も名前も違う)なのに、Document側の`LayerSource`はどちらも同じ`Shape`variantで、区別は中身の`PathSource::Rectangle`/`Ellipse`だけにある。UIの区別の重さと、データ表現側の区別の軽さが釣り合っていない感覚があった。
- **Split(`motolii-timeline-pane`に実装済み)と、それを呼ぶ入口が存在しないこと**。ロジックは書かれ、専用のテスト(`split_fence.rs`)まであるのに、シェル側のどのメニュー・ショートカットにも配線されていない。「実装されている」と「触れる」が別の状態として明確に分かれて存在しており、この2つの状態の間に何があるのか(単に手が回っていないだけなのか、意図的な保留なのか)はコードのdocコメント(「次波の統合を待つ」)だけでは判断がつかなかった。

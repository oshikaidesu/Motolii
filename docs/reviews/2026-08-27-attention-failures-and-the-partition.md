# 注意の失敗と、世界の分断(2026-08-27)

判定語: **採用**(利用者裁定により実施済み)。この文書は事後記録であり、提案ではない。

## 何が起きた日か

朝の依頼は「タイムラインが変、普通のソフトじゃない」だった。原因を1つ見つけ、
並列調査で27件の UX 欠陥を洗い出し、そこから**発注に入ろうとして丸一日を失った**。
失ったのは能力ではなく注意で、同じ形の失敗が1日に5回起きた。利用者が5回とも
先に気づいて軌道を戻している。

最終的に到達した結論は利用者の言葉で、**「膨れた物から省くのではなく、最小を建てて
そこから再スタートする」**。実施した結果が `app/`(15 crate・441 crate グラフ・
テスト9ファイル)である。

## 失敗の一覧(すべて実測)

| # | 起きたこと | 利用者の合図 | 根本 |
|---|---|---|---|
| 1 | runbook の「warm target を CoW で配る = 22.7秒」に従い 220GB を4本コピーしかけた(実測285秒/本) | 「なんか遅くね」 | 数字に賞味期限があることを疑わなかった |
| 2 | 遅いので「コピーを細くする」→失敗→「種ビルドを打つ」と迂回を重ねた | 「その場しのぎをするな」 | 枠を疑わず症状に合わせて自分を曲げた |
| 3 | `git add -A` が新 workspace の生成物 **17,615 個**を commit へ入れた | 「遅くね」(push が2分で切れた) | `.gitignore` が path 列挙で、新しい場所を知らない |
| 4 | `[patch]` と `default-features` をメンバーの Cargo.toml に書き、cargo に黙って無視された | (ビルドエラーで発覚) | 「書いたから効いている」を確かめなかった |
| 5 | 製品 front が `probes/` に居るまま CI の視界の外で27件の欠陥を通していた | 「makepad に入ってから無視されている」 | 決定(裁定251)の帰結が実行されていない |

**どれも間違ったアルゴリズムを書いた話ではない。**「見るべき所を見ていなかった」
だけである。だから対策は賢さではなく、視界の大きさに向ける。

## 診断: 決定は下されたが、帰結が実行されていない

同じ形が3つ見つかった。

- **iced を降りると決めた**(裁定251)→ 死んだコードも 220GB のビルド成果物も残った
- **front を製品にすると決めた**(裁定251/252)→ probe の身分だけ残り、CI が見なかった
- **手順書に「warm target を配れ」と書いた** → target が育った後も手順は更新されなかった

堆積の正体はこれである。そして**なぜ終わらないか**も分かった。帰結の実行はメタ作業で、
機能を1つも増やさない。だから毎回後回しになる。皮肉なことに
[メタ作業がセッションを食ってはいけない](../../AGENTS.md)という規律が、この後回しを
正当化する側に回っていた。利用者が「報酬は移りました、整備が今回のタスクです」と
宣言してセッションを買い戻したのが、実行の唯一の入口だった。

## なぜ規模がエージェントに強く効くか

人間は巨大なリポで働くうちに「この辺は死んでいる、無視していい」というフィルタが
身につく。何ヶ月もそこに住むからである。**エージェントはそれを毎セッション、
文書を読んでゼロから組み立て直す。しかもその文書が古い。**

失敗#1がまさにそれで、「22.7秒」は2026-08-10の世界の話だった。「あれ、target って
もっと育ってなかったか」という体の記憶が無い。だから**リポの大きさは人間より
エージェントに効く**。利用者の診断「注意を引く部分が多すぎる」は、この非対称に
対する処方だった。

逆に、利用者が持っていてエージェントが持たない物も同じ日にはっきりした。**連続性**である。
「タイムラインが変」も「skia が出てくるのも違和感」も「いままで走っていたのに」も、
以前の姿を知らないと言えない。「遅くね」は3回言われて3回とも本物の不具合だった
(220GB コピー・巨大 target のメタデータ走査・17,615ファイルの誤コミット)。

## 対策1: 世界を分断した

`app/` が生きている全部を持つ。`crates/`(初代)・`next/`(二代目 iced UI)・`spikes/`は
**消していない。生きた世界が読まないだけ**である。作業する = `app/` に居る、という状態に
すれば grep もビルドも `git add -A` も生きたコードしか見ない。

命名について: `crates/` も `next/` も「いつ来たか」で名付けたため、次が来るたび名前が
嘘になった(`next/README.md` の「front は iced のみ」を裁定251 が覆したのが実例)。
`app/` は「何であるか」で名乗る。front が Makepad から替わっても製品は製品である。

## 対策2: 段差が消えたので、段差の番人を捨てた

**利用者の指摘**: あの規律群(iced の Elm 式・投影の検査・台帳の柵)は、
**バックとフロントの段差**を無くすためにあった。段差があるからフロントの表示と
store の中身が食い違い得た。裁定251 以降その段差は構造で消えている。

- **ゼロコピー** — front は共有 Surface へ直接描く。運ぶ途中で食い違う場所が無い
- **ホットリロード** — 宣言がそのまま動いている UI。「ビルドして確かめる」の間が無い
- **`--remote`** — 窓を実際に叩いて、出た絵を見られる

守る物が無い証拠が3つ、同じ日に出た。

1. `CompositorError::PresentableWriteNotWired` — エラー文が自分で「rerun の
   `ViewBuilder::new_with_external_resolved` が着くまで」と書いていた。裁定256 で着いて
   おり、構築する側は既に無かった。**起こり得ない事態を検査していた**
2. 上と対になるテストは、すぐ隣のテストと**同じ呼び出しに正反対を要求**していた。
   どちらかが必ず赤で、1日そのままだった(誰も走らせていなかったため)
3. 台帳の柵3本は、**ファイルを動かしただけで落ちた**。製品の正しさは1ミリも
   動いていないのに

そして最も重い1件: front のテスト `lane_height_fits_all_lanes_and_keeps_property_height_fixed`
は、**朝に利用者が「変だ」と言った欠陥を仕様として固定**していた。緑のまま、修正を妨げる
向きに柵が立っていた。

### 残す基準

**窓を叩いても見えない嘘だけ。** 85ファイル → 9ファイル。

- 保存して読み直すと壊れている(往復)
- ドキュメントの整合
- 時間とフレームの演算(境界の off-by-one)
- **ゼロコピーが黙って CPU フォールバックへ落ちている** — 絵は同じに見えるので目で
  判別できない。この1件のためだけにテストが要る

見れば分かる物は窓で見る。足りなければホットリロードで何度でも足せる。
**残ったテスト自体が「これだけは目で見えない」という実質的な台帳**になる。

## 今後の教訓(引き金の形で書く)

主題別の索引では届かない。**「驚いた」は主題ではなく瞬間**だからである。以下は内部状態で
発火する形にしてある。

1. **観測が文書と桁で食い違ったら、遅さではなくモデルが違う。** 補正して進まず、導出を
   やり直す。実例: 22.7秒 → 285秒(12倍)
2. **同種の行動の2回目に入ったら、それは補正であって解決ではない。** コピー → 細いコピー
   → 種ビルドは全部「warm target を手に入れる」の変奏だった
3. **重い操作の前に、その出力を次に何へ使うか一行で言う。** 言えないならまだ要らない作業
4. **枠を先に見せて安く直させる。** 285秒払ってから直されるのと、宣言1行で止められるのは
   利用者の消耗が桁で違う。エージェントの幾何学は、宣言しないと利用者から見えない
5. **監督者は自分に規律を課す。** subagent へは「止まる許可」「oracle 必須」を書きながら
   自分は無規律で走った。規律は発注先だけの物ではない
6. **効く場所は1つ。** `[patch]` と `default-features` は workspace root にしか効かない。
   メンバーへ書くと cargo は黙って無視する
7. **列挙をやめて名前で切る。** `.gitignore` の path 列挙は「まだ無い場所」を知らないので、
   事故を場所の数だけ繰り返す(2026-08-10 に一度、今日もう一度)

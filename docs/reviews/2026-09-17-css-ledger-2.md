# CSS 2024–2026 文字組みの法 — 台帳 D の続き

## 見立て

- 日本語のリリックに直に効く 4 本: `text-autospace`・`text-spacing-trim`・`hanging-punctuation`・`ruby-*`。前 2 本は shaping の feature を on にするだけで大半が済む
- 台帳で「無」だった `text-box-trim` が 2026-08 に Baseline。字面の箱を並べる法の入力にする優先を上げる
- `reading-flow` は a11y の道具だが、Motolii では「番号の付け方の enum」に写る。Stagger の順番と同じ係
- `line-clamp` の N と `initial-letter` の行数は数値の軸なのでキーが打てる。時刻の純関数で状態は要らない
- 相談は 2 つ: `ruby-overhang`(隣とのかぶりの許可)、`text-wrap: pretty`(段落全体の探索をどこまで持つか)

# CSS 2024–2026 の追補 — 形・箱と、時間

2026-09-17 調査。[台帳 2026-09-14](2026-09-14-css-ledger.md) の B・C・E に無い行だけ。出典は利用者向け文書(MDN・Chrome for Developers・WebKit blog)を先に読んだ。

篩: **a** = 意味を持たない(道具・法であって出来上がりの見た目ではない) / **b** = どの素材にも掛かる(写真・文字・他人のシェーダー) / **c** = 時刻の純関数に写せる。○ △ ×。

## 時間の法の芯 — 時計はどこにあるか

CSS の動きは 3 種類の時計で動く。

1. **壁時計 + イベント**(transition、`@starting-style`、`allow-discrete`、popover)。「状態 A → 状態 B」に変わった**瞬間**を検出し、そこから duration を数える。純関数に書き直すと `f(t) = lerp(A, B, ease((t − t_event) / d))` — 純関数だが **t_event は状態機械から漏れる**。動画では t_event = 層の in/out 点、またはキーの時刻なので、漏れは消える。`allow-discrete` の「50% で切替」は step のキーと同じで、これも時刻の関数。
2. **状態の差分**(View Transitions)。時計は 1 と同じだが、from/to が「宣言された値」ではなく**撮った画 2 枚**。純関数に写すには、時刻 t での並び(layout)を 2 回解いて補間する = Motolii の「状態を持たない Transition」そのもの。漏れは「古い画を**いつ**撮ったか」= 前フレームの記憶。Motolii では前の時刻の並びをもう 1 度解けば記憶は要らない(コストは layout ×2、taffy ならμs)。
3. **スカラーの進み**(scroll-driven)。時計が時刻ではなく s∈[0,1]。`animation-range` は s の写像 `s' = (s − a) / (b − a)`。**最初から純関数**で、状態機械は無い。動画では s = 時刻・カメラの位置・音量・別の物の位置、どれでも良い。これが 3 つの中で一番 Motolii に近く、「時刻の代わりに何を読むか」の口 1 つで済む。

結論: 時間の CSS で Motolii が拒むべきは**イベント検出**(popover・`display` の出入り)だけ。補間そのもの(1)と 2 枚の差分(2)は既に時刻の純関数で持ち、スカラー駆動(3)は口を足すだけ。ただし anchor の `position-try` だけは「はみ出したら飛ぶ」= 時刻の関数だが不連続。動画では継続性([関係の動きは連続性で測る])に反するので、壁で押し戻す(物理の法)へ寄せるかを相談。

# 学マス・アイプラの公開技術から、次の反射実装へ

状態: **決定**（2026-09-09 利用者「追加文書にする、次の実装に向けての計画」）。計画を残す決定であり、下記の方式の製品採用・実装完了を意味しない。方式の採否は比較後に記録する。

## 目的と前提

作者が定めたカメラ・配置・形・色・動きの下で、映り込みの説得力と描画費用を改善する。[複数社からの採用方針](2026-09-09-entertainment-rendering-adoption.md)に従い、意図の自動補正は延期したままとする。顔形状の自動補正、前髪の透過、再構図・再照明は今回の施工対象ではない。

Happy Elementsは演出条件に合わせた近似の選択、QualiArtsは反射・照明方式の組合せと制作基盤の参考にする。公開資料の有用性を会社全体の技術力の順位へ読み替えない。

## 今回の出発点

現行実装と結果の正本は[共有反射の施工・検証](2026-09-09-shared-reflection-execution.md)。この文書へテスト数・時間の現在値を複写しない。現行の共有probeを比較基準として残す。

調査時点の入口はrenderの`compositor/surface_scene.rs`、`sequential.rs`、`effects/surface_program.rs`とforkの共通SurfaceProgram。GPU画像の再利用と、反射画像の内容を再撮影せず使うcacheは区別する。現行は毎評価時刻の撮影であり、内容cacheは後続の比較対象。

既知の差分候補は近接視差・自己像、補助ビューのblend近似、局所captureのHDR欠落、毎評価の撮影費用。最大2地点×6面は評価scene単位であり、入れ子を含むframe全体の上限ではない。通常文書の読込停止は別の未解決事項として施工記録を参照する。

## 実施順と終了条件

順序はR0→R1→R2→R3→R4。前段の結果で後段の候補を縮小できる。SSRやPPRの実装自体を終了目標にしない。

| 段階 | 作業と所有者 | 次へ進める条件 |
| --- | --- | --- |
| R0 基準を固定 | render/tests。現行HEAD・fork revision・比較作品・素材・品質を固定し、既存の作品生成器を再利用。画素、CPU準備/提出、GPU時間、readback、撮影/合成/copy回数、GPU画像bytesを分離して記録 | 下記の反例を再現でき、何が視覚上の不足で何が費用かを説明できる。GPU計時を取得できない機器では未計測と記す |
| R1 共有反射の再利用 | renderが撮影依存と失効を組み立て、re_rendererが画像資源を管理。素材revision、評価済み形状/配置/field、材質、可視性、環境、capture位置/範囲、品質等の実際に読む入力を確認し、同一入力の内容cacheを比較。証明できない依存は再撮影する | 静止時は再撮影が減り、各依存変更・Undo・同時刻再訪・catalog reloadで古い像が残らない。cache hit/miss/evictionで同じ結果になる |
| R2 平面を正しく共有 | renderが受け手の平面条件を判定、re_rendererが鏡映カメラとclipを描く。まず同一平面群で1撮影を共有し、coverage・個別材質を保持。field変形後に平面と保証できない面は対象外 | 近接・斜視・カメラ通過・画面外物体で現行probeとの改善と費用を提示。平行な別平面を同一視せず、面数増加時に撮影数を無制限に増やさない |
| R3 画面方式を限定比較 | re_rendererの既存入力を先に棚卸し。深度・法線・粗さ・現在時刻の色が不足するなら、その生成費用を含めてSSRの価値を判定。平面群の費用がR2で問題ならPPRも別候補として比較 | 画面外・遮蔽・薄い形・端の欠損を検出し、probe/環境への補完時に二重反射や切替の跳ねが出ない。追加pass込みで優位性がなければ延期 |
| R4 選択と品質配分 | renderが適用条件・費用とframe全体の資源上限から候補を選ぶ。re_rendererは共通surfaceへ反射情報を渡す。まず固定品質で方式間を比較し、その後に解像度/対象範囲の配分を比較 | 指定camera/時刻/品質の結果が再生履歴や機械の瞬間負荷で変わらない。入れ子合成を含む上限と上限時のfallbackを計測でき、実窓・exportまで通る |

最初の実装単位は**R0とR1を端から端まで閉じること**。画像の内容cacheで費用が解消するなら、画の不足が残る部分だけR2以降へ進む。描画方式名を作者の通常操作の必須項目にしない。比較用の強制方式は開発・検証側に置き、Documentの公開schemaを先に増やさない。

R1の初版は各評価sceneの直前の完全同一入力1組だけを保持する小さい案から比較する。導入時点でframe全体の保持bytes/entry上限とevictionを定め、R4まで先送りしない。key生成・依存判定のCPU時間も計測し、動的作品ではcache無効時との総費用を比較する。撮影回数が減っても総費用が増えるなら採用しない。

R2の補助撮影も共有反射・背景透過の再帰入力を行わない既存境界を維持する。自己像の改善は単一反射の範囲で比較し、向かい合う鏡・鏡に映る鏡の多重反射は別の検討へ延期する。

## 比較作品と外部の定規

| 作品/操作 | 守るものと検収 |
| --- | --- |
| 同一平面の2D複製、奥行き違いの平行板、任意向きの板、曲面を各10/100/1000個 | 個数に加え頂点数・画面占有率・重なり・独立平面数を記録。提出回数の削減と全頂点/pixel費用を分離 |
| 平面鏡、画面横/カメラ後方の動く色柄、近接物体、自己像 | Three.js Reflectorの鏡映カメラを定規に、対応する平面では位置関係を比較。曲面へ同じ正確性を主張しない |
| 粗さ0付近から強いぼけ、HDR発光、2D alpha輪郭、非Normal blend | 元の材質差・輝度・coverageを確認。現行RGBA8/補助blendの不足も明示し、高速化で隠さない |
| 透過3段以上、clip、field変形、個別parameterの違う複製、入れ子comp | 背景依存の順序を保持。反射の共有を理由に透過を一括化しない。frame全体の撮影・メモリを集計 |
| 停止、正順/逆順、任意frame直行、camera往復、素材差替え→Undo/Redo、cache破棄 | 同じDocument・時刻・camera・品質で画素が揃う。異なる方式間のpixel一致は要求せず、像の位置・欠損・ちらつき・費用を別々に評価 |
| 実窓で粗さ/透過/配置を連続操作し、保存・再読込・export | Inspector→Intent→Document→renderの既存経路で変更・Undoが届く。preview/exportは同じ品質条件で比較し、PNG生成を実窓確認の代用にしない |

SSRの制約と探索はAMD SSSR、probeのbox補正と混合はGodot、平面反射はThree.js、PPRはSIGGRAPH 2017/The Forgeを定規とする。URLと取得範囲は[反射調査](2026-09-09-glass-raster-research.md)にある。実装前に採用候補の現行ソース・利用条件を確認する。自作検証は上の定規と既存Document/Undo/時刻契約を写し、実装自身の出力だけを期待値にしない。

## 採否と成果物

各段階で、基準revision、実行可能な比較作品、実行コマンド、画像、計測値、機器/API/解像度/品質/warmup/sample数、破綻条件、採用・縮小・延期・棄却の理由を残す。計測値は既存の検証assets配下の機械可読ファイルへ置き、本文はそこへリンクする。任意のfps目標や許容画質閾値を出典なく先に保証しない。

本計画のR0/R1は比較方針として採用、R2/R3/R4の具体方式と閾値は比較中。VAT・新しい煙/照明体系は別計画へ延期する。既存の共有反射を捨てて別の描画経路を作らず、同じsurfaceとpreview/export経路の内部を改善する。

# Cavalry の売り文句 — 作り手は何を売り、「関係」をどう言っているか(2026-09-18)

調査のみ。一次資料 = cavalry.studio(本体・docs・release notes)、Scene Group の Medium(Chris Hardcastle / Ian Waters)、Canva の newsroom、プレスリリース中の作り手の発言。二次 = School of Motion・Lesterbanks・CG Channel・Creative Bloq・Envato・Creative Boom・Simon Tibbs・superrendersfarm。引用は原文のまま(≤25 語)。

## 要約 5 行

1. 本体の見出しは 3 本だけ — 「Change it once, watch it ripple」(関係)、「Design in real-time」(速さ)、「Your data, in motion」(データ)。「procedural」という語は 2026 の本体トップからは消え、「system が応える」の言い方に置き換わっている。
2. 作り手の芯は Ian Waters の一言 —「the power of proceduralism should be at the heart of all professional digital content creation tools」。Chris Hardcastle は「Anything plugs into anything」「It's just numbers after all so why not?」— 関係(a)と手続き(b)とデータ(c)を 1 つの思想として売る。
3. 関係の実装語彙は docs 側 — Connections(input は 1 本・output は複数、型が合えば何でも)、Falloff(Behaviour の Strength への乗数)、Duplicator、Layer Seed(output 接続ごとの一意値)、Dependency Graph(接続の地図)。
4. 「ノードを知らなくても使える」を初期から明言(2019)。層のように見えて裏はノード — UI(h)の売りは「node を隠す」こと。
5. 2026-02 Canva 買収後の売りは価格(f)と一体化(g)へ —「everything that is free in Cavalry today will remain free」、個人は全機能無料、Affinity と並ぶ「photo, vector, layout, and now motion」。二次側の要約はほぼ一致:「Houdini of 2D」「Forget Layers - Think Systems」「anything can connect to anything」。

## 作り手が「関係」をどう言っているか(a の全文引用)

本体(2026):
- "Change it once, watch it ripple" — https://cavalry.studio
- "Adjust a single value, watch entire systems respond." — https://cavalry.studio
- "Connect a spreadsheet. Animate at scale." — https://cavalry.studio

作り手の発言:
- "Anything plugs into anything" — Chris Hardcastle(SoM podcast)
- "allow users to bring data in and make it available to connect to anything. It's just numbers after all so why not?" — Chris Hardcastle, Do it with data
- "do anything to anything attitude" … "without expressions … without opening a node editor" — Chris Hardcastle, Introducing Cavalry
- "The humble Falloff can do wondrous things." — Ian Waters, Features Galore
- "you should be able to use Cavalry without even knowing what a node is." — Ian Waters, Questions answered(関係はあるがノード UI は見せない)

docs(仕組みの定義):
- "Connections form a key feature of Cavalry and can be used to set up attributes that drive other attributes."
- "An attribute can have several outputs but can only have one input."(keyframe も input の 1 つ — 接続で上書きされる)
- "Connections can be made between attributes with compatible data types."
- "Falloffs can be used to isolate the strength of most Behaviours and Fields." / "This value is used as a multiplier for the Strength of the Behaviour(s) it is connected to"
- "Behaviours can be thought of as effects. They can be used to animate or deform other Layers."
- Layer Seed: "Generate unique values for individual output connections."(1 つの output が繋がる先ごとに別の値 — 関係の側に乱数を置く)
- "The Dependency Graph is a window providing an interactive schematic view or map of the connections within a Composition."(2.4)
- Mesh Solver(2.6): "connect deformers to create drawing machines or iterative effects like differential growth"

読み: 作り手の語彙は「connect / plug / drive / respond / ripple」。「relationship」という語は作り手側には無く、二次(SoM「built around relationships and systems」、Creative Boom「web of relationships」)が付けた要約。作り手は関係を **属性→属性の有向接続(input 1・output 多)** として定義し、Falloff はその接続に掛かる **乗数**、Duplicator/Layer Seed は **接続先ごとの index/seed** で個体差を出す。ノードはある(Dependency Graph)が売りは「ノードを知らなくていい」。

## 2. 発見1: 種の組成が逆転している(蒸留の経路)

S1 の種は **100% 利用者の意図**(3軸、3行)。S4 以降の種は **95% が前任 assistant の自己語り**(数百〜千字の締め口上+成果修辞「本当の成果は数字の外にあります…骨格が立った」)で、利用者の寄与は末尾の一行だけになっている。

つまり人格・語り口・優先感覚が **assistant→assistant で直接遺伝する構造**が冒頭メッセージに埋まっている。利用者はそれに副署しているだけで、各世代の種を自分の言葉で切り直していない。「自然に整った性格がどんどん擬似的な蒸留をする」という利用者の直感は、この構造の正確な記述である。

## 3. 発見2: 規則は単調増加・引退ゼロ

6セッションで引き継ぎレベルの運転規則が **約27本**新設され、**1本も引退していない**。加えて裁定 106→177、KNOWN.md、CANON.md、AGENTS.md、playbook、レーンボード、memory 約40項目 — 規則の「家」が7つ以上ある。引き継ぎ文書が規則を**再掲**するたび、制定時の文脈(何で火傷したか)が剥がれ、命令文だけが濃縮される。**これが擬似蒸留の実体**: テキストは蒸留されるが、判断の重み付けは蒸留されない。後任には全部が同じ太さの「守れ」に見え、顕著な数本に従い残りは推測で埋める — S6 の「確認より仮定」は規則飽和下の予測可能な対処行動である。

## 4. 発見3: 散文規則は再発を止めなかった。構造は止めた

同一の誤りクラスが規則の強化をすり抜けて再発し続けた実証系列:

| 誤りクラス | 経過 |
|---|---|
| cwd / 作業場所 | S2 数回 → S3 4回 → S4 4回+**hook 導入後も**3連 deny → S6 同型5連発(「生成レベルの盲点」と自己確定) |
| 背景 cargo 自停止 | S3 で「冒頭太字化」規則 → S5 で太字でも**5回再発** → 回復定型文の追加 |
| 発注の重み均等 | S2 制定 → S3 で「自分の新規則の即再犯」 → memory に「毎回忘れる」と記録 |
| exit code 検証 | S5 パイプ事故 → S6 で3形態(パイプ握り潰し・PIPESTATUS 空・pipefail 曖昧)に形骸化 |

対照的に、**構造化された物は実際に効いた**: check.sh、oracle 先行発注、mock=転写元、±1px 柵、AGENTS.md 頻出コマンド(コピペで cwd 非依存)、git hook(部分的)。既存 memory「構造による強制>監督」の追認であり、帰結は明快 — **構造化できない散文規則を引き継ぎで再掲し続けることには、効果がなくコスト(飽和)だけがある**。

## 5. 発見4: 節のジャンル漂流と誤り節の儀式化

- 「まず疑うべきこと」は S1 では**認識の較正**(主張のどこを信じるな)だったが、S5/S6 では走行中レーン・手順書・規則が混入して**第二のキュー**になった。本来の機能(信頼度の目盛り)が薄まった。
- 「supervisor の誤り」節は毎回律儀に書かれているが、§4 の通り**行動は変わっていない**。告白の型だけが遺伝し、後任は「自分は間違える supervisor だ」という自己像を種として受け取る。誤りの記録が処置(構造)に接続していない項目は、人格の蒸留にしか寄与していない。

## 6. 通過判定: 壊れたのは運転層であって設計層ではない

S1 の3軸(rerun fork AE 化 / iced 段差なし / 最小コア plugin)は6セッション後の S6 キューでも無傷で追跡できる(fork accessor・pane_grid・map/束)。地図・裁定・oracle・モックの**設計資産は蒸留に耐えた**。劣化したのは運転層(規則群と人格の遺伝)のみ。従って以下のダイエットで安定運用に戻れる、が本監査の判定。

## 7. 提案(全て利用者裁定待ち — 本監査では実施しない)

1. **種の規約**: 次セッションの冒頭は「**利用者自身の一行意図+引き継ぎ文書リンクのみ**」。前任の締め口上(成果修辞・自己語り)を貼らない。貼るなら事実行だけに刈る。人格の遺伝経路をここで切る。
2. **引き継ぎ文書の規則ダイエット**: 規則は各自の家(AGENTS.md=ビルド / KNOWN=事実 / playbook=発注 / 裁定=設計)に1箇所だけ住む。引き継ぎの「運転規則」節は**そのセッションで変わった差分のみ**、既存規則の再掲は禁止(リンクで指す)。
3. **規則の引退制度**: (a) 構造化が済んだ規則(hook 化・スクリプト化・柵化)は散文規則を**削除**。(b) 2セッション連続で破られた規則は「構造化するか、捨てるか」の二択 — 三たび再掲しない。
4. **誤り節の掲載基準**: 構造的処置が付いた誤りのみ記載(処置へのリンク必須)。告白のみの項目は書かない。
5. 判断の背骨は従来どおり3本のみ(oracle・柵・UX 合否)。これ以外の運転規則は全て上記 1〜4 の管理下に置く。

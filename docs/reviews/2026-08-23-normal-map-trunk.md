# 「普通」地図の幹 — 台帳が構造的に持てない物の棚卸し

利用者の問い(2026-08-23):

> 今の台帳は恐らく、枝の端の部分を示すことには成功しているが、恐らく、幹の部分があるはずで、
> そこから並列に切り出すことも計画できると思います。行き当たりばったりな並列ではなくてね

**結論**: 正しい。しかも幹は**既に書かれている**(`next/GOALS.md` M1〜M20 / `docs/ui-quality-bar.md`
Q0〜Q9 / B1〜B7)。欠けているのは幹そのものではなく、**幹と 1,551 枚の葉を突き合わせる工程**。
昨日いちばん収穫のあった調査3本(裁定212・214・216)は**全部この工程だった**が、軸を思いつきで
選んでいた。軸を先に数え上げれば、並列は行き当たりばったりでなくなる。

---

## 1. 台帳が持てない物は、抽出規則から決まっている

裁定154 の抽出法は「各製品が**公開する有限リスト4種**(メニュー木・ショートカット表・
Window/パネル一覧・環境設定)」。この規則の帰結を実測した:

```
awk -F'\t' '{split($10,a,":") ...}' next/reference/normal-map.tsv
  menu のみ      783
  shortcut のみ  586
  menu+shortcut   48
  pref            70
  panel           63
  menu+key+pref    1
  ---------------------
  どれでもない行   0     ← 1,551行すべてが「名前を持ち、呼び出せる項目」
```

つまり台帳は **「名前を持つ動詞」と「名前を持つ物(パネル・設定)」の在庫**であり、
それ以外を**構造的に1行も持てない**。持てない物を grep で確認した(全て台帳の全文検索):

| 探した語 | 件数 | 実際にある行 |
|---|---|---|
| `marquee` | **0** | — (矩形選択。GOALS **M6 の必須項目**なのに製品側が項目名を持たない) |
| `hover` / `tooltip` / `double`(-click) | **0 / 0 / 0** | — |
| `offline` / `relink` / `autosave` | **0 / 0 / 0** | — |
| `drag` | 3 | `Trim tool`・`Drop Shadow`・(無関係語) = **ドラッグ意味論の行はゼロ** |
| `scroll` | 3 | `Scroll to current time`・`Scroll topmost selected layer to top`・`Timeline Scrolling`(設定) |
| `missing` | 3 | `Find Missing Fonts/Effects/Footage` |
| `rename` | 1 | `Rename selected layer…`(ショートカット) |

読み方が2つある:

- **`Scroll to current time` は在るのに「タイムラインはスクロールできる」は無い。**
  製品は「スクロールという常時成立している性質」に項目名を与えず、その上に載る**便利コマンド**
  にだけ名前を付ける。裁定207(「量に耐えるか」は台帳に現れない)はこの一般形の1例だった
- **`Find Missing Footage` は在るのに「素材が欠けている状態」は無い。**
  製品は**回復コマンド**に名前を付け、**状態そのもの**には付けない

そして `freq=4`(4製品全部に在る=「普通の核」)はたった6行 —
Copy / Paste / Import / Inspector / Timeline panel / New Project。
一方**本当に全製品にある普遍**(スクロールする・ドラッグで動く・矩形で囲める・落ちない)は、
名前を持たないので **freq を持つことすらできない**。台帳の頻度列は「普通度」ではなく
**「名前になりやすさ」**を測っている。

## 2. 幹は既に在る。台帳と繋がっていないだけ

葉に一様に掛かる横断軸は、新しく発明する必要がない。3箇所に既に書かれている:

| 場所 | 中身 | 台帳との接続 |
|---|---|---|
| `next/GOALS.md` M1〜M20 | 合否条件(観測可能な形) | **無し**。M5(drag/trim/snap)・M12(触れそうな物は全部機能する)・M13(無反応ゼロ)・M14(正本1つ)・M16(どの入力でも落ちない)・M17(空 project)・M20(IME を壊さない)は**台帳に1行も対応が無い** |
| `docs/ui-quality-bar.md` Q0〜Q9 | 触達性・可逆性・沈黙禁止・単一の真実・頑健性・空状態・キーボード | **無し** |
| 同 B1〜B7 | 時間予算(p99 8ms、gesture 中 16.7ms 連続2枚禁止 …) | **無し**。しかも器具が無い — B1 の正典器具 `[MotoliiRerunStage]`/`[MotoliiTimelineProbe]` は `next/` に存在せず、旧 egui ホスト(`ui/motolii-rn`)にしか無い。iced 移行で移植されていない(AX-4 実測 2026-08-23)。**B2/B4/B6 は試験ゼロ** |

葉(1,551)と幹(20+10+7)を突き合わせる列も表も、いま存在しない。

## 3. 昨日の高収穫は全部「幹の軸 × 全葉」だった

| 裁定 | 軸 | 対象 | 出た穴 |
|---|---|---|---|
| **212** | その意図に**入口**が在るか | `Intent` 24枝 | **7枝が入口ゼロ**(カメラをアニメートできず、素材を外せない) |
| **214** | 映る値が**時間軸**に乗るか | Inspector に映る物 | **13件が未乗**(Hidden・Blend Mode・Speed・Matte・Mask Mode・テキスト6種…) |
| **216** | **マウスだけ / キーボードだけ**で完遂できるか | ジェスチャ34件 | **マウスのみ25**(原因は iced のキーボード到達性欠如=上流の穴) |

3本とも「全部の葉に同じ問いを1回ずつ掛ける」形で、**1軸あたり7〜25件**の穴を出した。
台帳の消化(葉を1枚ずつ実装する)では1件も出ていない種類の穴である。

**行き当たりばったりだったのは並列ではなく、軸の選び方。** 3本は利用者との対話の流れで
その場で決まった。軸を先に数え上げれば、同じ収穫率の作業を計画で並べられる。

## 5. 軸で切ると並列が構造的に安全になる

葉で切る並列(いままで)と軸で切る並列の違い:

| | 葉で切る | 軸で切る |
|---|---|---|
| レーンの仕事 | 機能を1つ実装する | **全葉に同じ問いを1回ずつ掛ける** |
| write-set | 同じ pane / 同じ store ファイルを奪い合う(裁定198・201 の事故源) | **軸ごとに新規ファイル1本** → 構造的に互いに素 |
| 成果物 | コード | **台帳1本 + 柵1本**(その軸が今後も自動で検査される) |
| 失敗の型 | 取り残し・重複実装 | 網羅の主張が甘くなる(→ 使った grep を残す規約で担保。GESTURES.md が前例) |

具体形: 各レーンは `next/reference/axis-<name>.tsv`(normal-map の `id` を鍵にする)と、
対応する柵テスト1本だけを書く。**normal-map.tsv 本体には触らせない**(1ファイル大物への複数レーンは不可)。

### レーン割り(重み均等 — 行数+判断の重さ+領域数で均す)

| レーン | 軸 | 器具 | 重み根拠 |
|---|---|---|---|
| **L1** | A3(時間・残り) + A9(可逆) | 静的(grep+型) | どちらも既存の棚卸し形を踏襲。判断は軽く量が多い |
| **L2** | A8(一括) + A1 追試(裁定212 以後に増えた枝) | 静的 | 一括は Inspector/Timeline 双方に跨るので単独では重い |
| **L3** | A5(欠落) + A7(空) | **実機**(窓を開ける) | どちらも「異常系の絵」を見る必要がある。同じ器具で2軸 |
| **L4** | A4(量) | **実機**(大 fixture) | 単独で重い(fixture 生成 + 予算計測の切り分け) |
| **L5** | A6(復帰) + A12(入力の物理) | **実機** | 両方とも OS 境界を触る |
| **L6** | A10(予告) + A11(予算) | 静的+telemetry | A11 は器具が既にあるので実装は薄い |

**L3〜L5 は「窓を開けた検分」を要求する** — 引き継ぎ §6 が挙げたとおり、この検分は
一度も行われていない。ここで初めて必須になる。

## 6. 決めてもらう必要がある所

1. **軸を台帳の列にするか、別ファイルにするか。** 上は別ファイル案(並列安全のため)。
   ただし「1つの意味の正本は1つ」(Q5)と緊張する。突き合わせビューを check.sh 側で作るなら解消する

   「キーボード到達性を自前で持つ」意見を名指しできなければならない。**この裁定が未了**

   利用者の直観による追加を歓迎する

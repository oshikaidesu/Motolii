## なぜ読んだか

egui Lab に Space の再生を入れた際、窓の追従を3回作り直して3回とも利用者から違和感の指摘を受けた。

1. **ページ送り**（窓の外へ出たら1画面ぶん飛ぶ）→ 「急にプレイヘッドが瞬間移動する」
2. **中央へ指数で寄せる** → 「中央より左に置いたときに瞬間移動する」
3. **掴んだ相対位置を保つ**（窓が playhead と同じ量だけ進む）→ 「違和感がある。DAW の実装を調べよう」

自分の直感で3回外したので、[先人の解決策を先に見る](README.md)ほうへ切り替えた。

## 分かったこと

### 1. 追従の型は2つしかない。「相対位置を保つ」は無い

| | Ardour | LMMS | Ableton Live 11 |
|---|---|---|---|
| ページ送り | Follow Playhead（既定） | `AutoScrollState::Stepped` | Follow Behavior: **Page** |
| 中央固定 | Stationary Playhead | `AutoScrollState::Continuous` | Follow Behavior: **Scroll** |
| 追わない | 上記の off | `AutoScrollState::Disabled` | Follow off |

3案のうち私が最後に作った「掴んだ相対位置を保つ」は**どこにも無い**。理由は読めば分かる — 相対位置を保つと**窓が止まっている時間がゼロ**になり、再生中はどこに置いても常に面が流れ続ける。

### 2. ページ送りは「ページの中に居るあいだ、1ピクセルも動かない」

Ardour `EditingContext::reset_x_origin_to_follow_playhead`（`editing_context.cc:3746`）は、playhead が現在のページの内側にあるとき**何もせずに戻る**。

**これが効いている。** 再生を押した瞬間に面が滑らないのは、寄せ方が上手いからではなく**そもそも寄せないから**である。私の2案目（中央へ寄せる）は、この「動かない時間」を自分で潰していた。

### 3. 前へ出たときの着地は「playhead が新しい左端」

Ardour（`editing_context.cc:3760-3780`）は着地点を4通りに分けている。

| | 着地 |
|---|---|
| 再生中・前進 | playhead が**左端** |
| 再生中・後退 | playhead が**右端** |
| 停止中（ロケート）・前進 | 3/4 の位置 |
| 停止中・後退 | 1/4 の位置 |

LMMS の Stepped も同じで、スクロール値へ playhead の位置をそのまま入れる（`SongEditor.cpp:773-779`）。

**再生中に左端へ置くと、これから来る1ページぶんが丸ごと先に見える** — 次の送りまでの間隔が最大になる置き方である。「中央へ送る」と半ページで次の送りが来る。

### 4. 瞬間移動は「避ける」のではなく「見せる」

LMMS は `smoothscroll` 設定のとき、送りを `QTimeLine` で **600ms かけてアニメーション**する（`SongEditor.cpp:727 animateScroll`）。送っている最中に次の送りが来たら、新しいアニメを作らず**終点だけ差し替える**。

私はずっと「跳ばない書き方」を探していたが、先例の答えは**跳ぶところを見せる**だった。

### 5. 追従を切る条件が決まっている

- **ドラッグ中は追従しない** — Ardour `EditingContext::follow_playhead()` は drag が active なら false を返す（`editing_context.cc:1570`。コメントに「ユーザーに親切であるため」と書いてある）
- **自分で横スクロールしたら Follow は一時停止する** — Ableton。停止/再開、または Arrangement のクリックで戻る
- Ardour の中央固定は、**ピクセルへ丸めて変化があるときだけ**窓を動かす（`editor.cc:5466-5475`）。サブピクセルのジッタを出さない

## Lab へ入れたもの（2026-08-16、**同日に全部撤廃**）

`crates/motolii-ui/examples/timeline_egui_lab.rs`

- `Follow::{Page, Centre, Off}`。**既定は Page**（Ardour / Ableton の既定と同じ）。`F` で巡回
- Page はページの内側では何もしない。外へ出たら、前進なら playhead が左端、後退なら右端
- 送りは `FLIP_SECONDS = 0.4` の ease-in-out（LMMS の 600ms は歩幅が大きく感じたので短くした。**数値は触って決める種類のもの**）
- ドラッグ中は追わない。再生中に自分でパンしたら追従は一時停止し、Space かスクラブで戻る
- 中央固定は端では動かない（`clamped` が窓を止めるので `None` を返す）

## この文書の身分

**一次資料は実コードなので事実の確度は高いが、規律6点の1に従い、これを設計根拠として製品契約へ焼かない。** 適用先は Lab（触って確かめる面）に限る。

反対側の見方も書いておく。

- **Page はスクロールが不連続**である。3つとも既定にしているが、既定であることは「良い」の証明ではなく「昔からそう」の証拠でもある。Ableton が Live 11 で Scroll を足したのは、不満があった側面の裏返しとも読める
- ここで読んだのは**音のタイムライン**である。Motolii は映像で、AE / AM 側の作法（AE は再生中ページ送り、AM は未確認）と食い違う可能性がある。**AM の実機確認は未実施**
- 数値（0.4s、2%のしきい値）はどの先例からも出ていない。**手触りで決めた値**であり、根拠は無い

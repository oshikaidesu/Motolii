# M3の価値観更新 — 「UIを作る工程」から「製品として繋ぎ直す工程」へ

日付: 2026-08-07
状態: **決定 / 技術採択は変更しない**

## 1. 何を変えるか

M3の**判定規律と読み方**を変える。既存の技術採択、Document意味、公開契約、
M4/M5の採択地図は**一切変更しない**。

| | 旧 | 新 |
|---|---|---|
| M3の性格 | UIを作る工程 | **先に作った資産を接続し、製品として成立させる統合ゾーン** |
| 既定の推定 | 無ければ`TARGET_MISSING` | **既定は`BUILT_UNWIRED`。`ABSENT`は探索して初めて言う** |
| 優先順位のsort key | 内部機構の緊急度 | **`concept.md`の完成条件** |
| 記録とコードのdrift | 暗黙 | **一級のriskとして扱う** |

## 2. 根拠（2026-08-07の実測）

62項目をcurrent codeへ read-only 照合した結果:

```
製品routeから到達可能        7
実在するが旧route/probeのみ  30   ← 最多
部分的に実在                23
本当に存在しない            11
コード読解では決着しない      7
```

**M3の作業の本体は構築ではなく接続である。**

同じ形がM4（probe済み・製品未接続）、M5（private検証DONE・runtime未実装）、
旧M3 route（VS-1は実Macで到達済み）の**3ヶ所で反復している**。

## 3. 旧M3地図の誤りの機序

旧地図は`TARGET_MISSING`を「必要なtyped targetがcurrent mainにない」と定義しながら、
実際には「**新RN routeから到達できない**」を書いていた。

例: `R2-KEY-COMMAND`は「現行`CommandKind`にkeyframe編集familyが無い」としていたが、
`AddPositionKey` / `SetPositionKeyValue` / `SetPositionKeyInterp` は**実在する**。

**書いた者は嘘をついていない。「UIから見て無い」を「無い」と書いた。**
M3を「UIを作る工程」と読むとこの圧縮は自然であり、
「先に作った資産を繋ぐ工程」と読むと致命的になる。

M4/M5の地図に同種の誤りが無いのは、「probeを通したか」という
**視点に依存しない事実**で書かれているためである。

## 4. 新しい判定規律

1. **視点依存の判断を事実として書かない。**
   「無い」と書く時は、何をどう検索して無かったかを併記する
2. **既定の推定は`BUILT_UNWIRED`**。旧route、probe、test、fixtureを探してから`ABSENT`と言う
3. **`BUILT_UNWIRED`を再実装しない。** 意味・command・oracleを再利用して接続する
4. **状態語彙は6値**（[成果駆動統合地図](../outcome-driven-integration-map.md)§2）を使い、
   「無い」と「繋がってない」を潰さない

## 5. 優先順位のsort key

`concept.md`が完成条件を明示している。

> **MVを1本書き出せる**: 3〜5分・音楽同期の最終書き出し(音声mux込み)が**完成条件**

内部機構の重さではなく、**この完成条件を塞ぐかどうか**で順位を決める。

2026-08-07の適用例: 仮コード合成テストで検出した14件の決定間合成失敗を本基準で仕分けたところ、
**完成条件を塞ぐのは3件**（parameter編集chain）、
残り11件は**作者・配布枝**（Fork / Author / Publish）であった。
concept.mdは解析駆動生成を「優先度=最終フェーズ、M1〜M5完成後」と定めており、
作者・配布枝の後置は**怠慢ではなく既決の踏襲**である。

## 6. 記録とコードのdriftを一級riskとして扱う

本日、記録層の欠陥が複数見つかった。

- `decision-index`が**5文書ぶん陳腐化**（Inspector write routeが索引に未反映）
- overlay renderer（rust-skia）が**どの地図にもnodeとして存在しない**。`Cargo.toml`にも不在
- gizmo機構の既知実装調査が指定されているのに**record ゼロ**
- microkernel決定（2026-07-25）が並列化を許可済みなのに、Host ABIは15-field unionのまま

`scripts/check-docs.sh`は**文書間の整合**を検査するが、**文書とコードの整合は誰も検査していない**。

本決定はこのdriftを一級のriskとして明示するに留め、**常設の検査機構を新設しない**
（機構の要否と形式は別途裁定する）。当面は node survey と仮コード照合を
**必要時に実行する器具**として使う。

## 7. 名称の扱い

`docs/specs/M3-ui-integration.md`のファイル名は変更しない（参照の連続性を優先）。
ただしM3の性格については**本決定が正**であり、名称から「UIの工程」と読まない。

## 8. 非目標

- M4/M5の技術採択、Document意味、公開契約、絶対規律の変更
- `BUILT_UNWIRED` 30件の再実装
- 作者・配布枝11件の先行着手
- 文書↔コード整合の常設検査機構の新設（本決定では裁定しない）
- 完成条件を「一般的な動画編集ソフトに必要な機能」へ読み替えること
  （baseline抽出は[baseline-required checkpoint](2026-08-07-m3-baseline-required-autonomy-checkpoint.md)の手続きに従う）

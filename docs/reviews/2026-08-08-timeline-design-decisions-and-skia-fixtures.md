# Timeline 設計決定と skia fixture — キーフレーム方式・行高・責任分界

日付: 2026-08-08
状態: **決定（利用者裁定）＋観察 / 実装発注は未実施**

## 0. この文書の扱い

会話で生じた意味を正本へ回収する（`AGENTS.md`「会話だけをauthorityにしない」）。
**本書を根拠に実装を発注しない。** 決定は意味と理由の確定であり、施工許可ではない。

## 1. なぜ今日これが決まったか

HTMLでモックを重ねても「なんとなく違う」が解けなかった。原因は2つあった。

1. **感覚で移植していた。** Ableton実物の値を一度も測っていなかった
2. **HTMLでは分からない層があった。** 小サイズ文字のラスタライズ、1px罫の整合、grid密度の破綻は
   目標rendererで描かないと出ない

一次資料（インストール済み Live 12 のテーマXML、公式マニュアル、利用者の実機スクリーンショット）を
測り、skiaで直接描いたことで、以下が判定できるようになった。

## 2. 決定

### 2.1 キーフレーム方式を維持する

**理由: パラメータの値域が確定しないため。**

DAWのエンベロープが成立するのはレーンの縦幅＝パラメータ値域だからである。
[Ableton公式](https://www.ableton.com/en/manual/automation-and-editing-envelopes/)は
Automation Shapesが「vertically to the automated parameter range へスケールされる」と明記し、
stretchは上下境界へクランプされる。

Motoliiは割れる。

| | 値域 |
|---|---|
| Opacity | 0〜100 確定 |
| Scale | 下限0のみ |
| **Position X/Y** | **無い**（正準座標、Output Frame外も正当） |
| **Rotation** | 無い（多回転が意味を持つ） |

一部だけエンベロープにすると操作規則が裏切られる（`ui-interaction-language.md`
「一度学んだ操作規則を、別機能、Advanced、pluginが裏切らない」）。**全面キーフレームで統一する。**

なお既決の [Easing区間](../mocks/README.md) は「key単体ではなく`左key → 右key`の間の動き」であり、
**区間を単位とする点は既に採っている**。本決定はそれと矛盾しない。

### 2.2 キーフレームmarkerは形を統一し、色だけが情報を持つ

AEはmarkerの**形**に補間種別を載せているが、**ほぼ全区間がイージングされる実運用では情報量がゼロ**になる。
Alight Motionは全て同一形である。形・大きさは候補から外す。

- 符号化するのは「**出ていく差**」＝ このkeyから次のkeyまでの移動量
- 基準は**絶対規律5の正準座標（高さ1.0）**。新しい約束を作らない
- **明るいほど大きい**。暗いほど大きいだと、最大の動きが既定の暗色markerと区別できず、
  一番どうでもいいホールドが最も目立つ（実測で確認）
- 段階は**3**。10px・2px stroke の内側は実質4pxで、それ以上は読めない
- **seedのような識別のみの値は差が定義できない**ため一律。例外規則を書かずに外れる

副産物として「動いていない区間」が読めるようになる。

規範の「Object paletteの色相だけへ可視性を依存させない」は**可読性の規則**であり、
二重コントラストの装甲があるため内側を色で塗ることは想定内である。

### 2.3 タイムラインの行高は固定・最小

**理由: コンポジットのタイムラインは縦方向が情報を持たないため。**

DAWで行高が可変なのは、縦が波形の振幅・MIDIのピッチ・オートメーションの値を運ぶからである。
キーframeをマーカーとして置く（2.2）と決めた時点で、行の縦方向は何も運ばない。
主たる観測面はStage（Preview）であり、タイムラインは最悪キーが見えればよい。

したがって **Abletonの Optimize Height (H) / トラック個別リサイズ / Waveform Vertical Zoom は
借りないのではなく前提が違うので不要**である。

下限はmarkerで決まる。fixtureでは**20px**（marker 10px＋余白＋名前）で成立を確認した。
Live実測の24pxより詰まる。

例外候補: **楽曲ベッドの波形**。MVは音に合わせて切るため、その1行だけは高さが要る可能性がある。
「全トラック可変」ではなく「音声だけ別扱い」で足りる。**本決定では開けない。**

### 2.4 object bar は読み取り専用

**理由: 誤爆のコストが操作ごとに非対称であるため。**

キーframeを押し間違えれば値や選択がその場で変わり、すぐ気づく。
ミュートを押し間違えると静かに消え、書き出すまで気づかない。
同じ20pxの帯に、気づける操作と気づけない操作を混ぜない。

| 面 | 役割 |
|---|---|
| **object bar** | 見るだけ。選択・移動・トリム・キーframe以外のクリック先が無い |
| **rail** | 帯単位の一括M/S（2.6） |
| **Inspector** | オブジェクト個別の状態変更 |
| **keymap** | 高頻度トグル（Soloは作業中に何度も切り替えるため小さなボタンに置かない） |

規範は既に「値はInspector、接続はArchitect、操作説明は下端Statusへ分離する」と定めており、
本決定はその分界へM/Sを加えるものである。Abletonも M/S を clip ではなくトラックヘッダに置く。

**mute は widget ではなく面そのもので示す。** 面を地へ沈めてハッチを掛ける。
13pxのMボタンより読みやすく、押す場所が消える。
**solo は他を沈める**ことで示し、ハッチの有無で「自分で消した」と「他が優先されている」を分ける。

### 2.5 タイムラインは時間の操作へ集約する

判定基準は1つ。**その操作は「いつ」を変えるか。**

- **集まる**: clip移動・トリム（ripple / roll / slip / slide）・分割、キーの時間移動と増減、
  リタイム、playhead・スクラブ、スナップ、ループ範囲、グループの畳み
- **出る**: パラメータ値、エフェクトの追加・並べ替え・有効無効、ブレンドモード、M/S、外観

**帰結: キーを縦にドラッグして値を変える操作を持たない。** 2.3で縦の値軸が無いため、
そもそもドラッグする相手がいない。2つの決定が同じ方向を向く。

Easingは既決が正しく割っている。タイムラインが「どの区間か」を決め（playheadが区間内部の時だけ点灯）、
Graph Viewが「どんな形か」を持つ。

### 2.6 rail は時間面の外のコントロール列として残す（明示的例外）

M/Sは時間の操作ではないため2.5に厳密には反するが、**例外として1件認める**。
railは専用の細い列でドラッグ面と競合せず、誤爆しない。
外すと「この帯だけ黙らせたい」が遠くなり、原則のために実用を落とす。

**例外であることを本書に明記する**（明記しない例外は後で崩れる）。

規範は既にこの席を用意していた ——
「Inbox右隣には、**従来の名前欄相当だが名前を持たない**細い帯アクションrailを置いてよい」。
禁じられているのは**名前**だけで、理由はpacking帯が複数Objectを載せるため帯に固有の名前が無いこと。
帯のObject集合から導出できるものは置ける。

### 2.7 畳みは「縦方向への射影」、rail は「横方向への射影」

同じ規則の別軸適用であり、新しい機構を作らない。

| | 射影 | 出力 |
|---|---|---|
| **グループ畳み** | 縦（子N行 → 1行） | 中身がある区間＋件数 |
| **rail** | 横（時間軸全体 → 1セル） | 帯の集合状態＋件数＋逸脱rollup |

畳んだ行は**展開した行と同じ構造**（identity bar＋その上のキー）になる。新しい行タイプが要らない。

キーも同じ規則で畳む。近接キーを1markerへ束ね、**明度は含まれる中の最大delta**（合計ではない。
合計は子の数と混ざり、密度は件数が既に持っている）。**件数＝いくつ、明度＝一番大きい動き**で直交する。

Abletonは畳んだGroup Trackに「overview of the clips in the contained tracks」を出す
（[manual 18.3](https://www.ableton.com/en/manual/mixing/)）＝**その場でミニチュア**。
Motoliiは行高固定（2.3）と両立しないため**1段へ潰し、「どの子か」を捨てる**。
落とした情報はhover / focusのInfoで戻す（規範「説明は時間方向に配分する」）。

状態の畳み方（全ON / 全OFF / 混在の三値導出）は規範のrail記述が既に同じ結論に達しており、
Abletonの half-colored Solo と一致する。**新規に借りたのはミニチュアの側だけ。**

### 2.8 逸脱時のみ表示する（既定は沈黙）

規範「状態語は逸脱時のみ表示し、正常・不変の既定表示は沈黙とする」をobject barへ適用する。
エフェクト無し・ミュート無し・逸脱無しのレイヤーは**名前だけ**を出す。

**平均密度を上げずに情報密度だけを上げる**ための機構である。
幅が足りない時は右から順に落とす。

エフェクト数の表示は、実装済みで`ui/`配下の呼び出しが0件だった`SetEffectEnabled`
（[合成失敗T3](2026-08-07-call-site-sketch-composition-failures.md)）の最初の呼び出し側になりうる。

### 2.9 逸脱glyphは文字コードでなく形で示す

`T`／`S`／`%`のような略号は覚えないと読めない。加えて`S`（ブレンド）はrailの`S`（ソロ）と衝突していた。

| 状態 | 形 |
|---|---|
| 不透明度が下がっている | 半分だけ塗った四角 |
| 合成モードが標準でない | 重なった二枚 |
| 速度が変わっている | 二重の山 |
| 無効化されたものがある | 斜線で潰した丸 |
| 個別にミュートされている | ハッチの四角 |
| ソースが無い | 感嘆符（**警告色**。規範「warning/errorは別tokenと形で示す」） |

### 2.10 帯は空になっても残る

**帯は利用者が作った器として扱う。ただし名前も型も持たない。**

規範の「Lane所有を持たない」は `V1` `V2` のような**同一性を帯に与えない**ことを言っており、
利用者が縦位置を決めることを禁じてはいない。
AE型の「1シェイプ1レイヤー」のほうが例外で、Premiere / Resolve / FCP / AM は
**利用者が任意にレーンへまとめる**。Motoliiもそれに従う。

空の帯が消えると、クリップを一時的にどけただけで行が畳まって下が繰り上がり、作業位置を失う。
**残す。**

### 2.11 タイムラインに必要な部品

完成条件（3〜5分・音楽同期）から逆算して、以下を欠けたままにしない。
配置順は Ableton に合わせる（借りるのは操作トポロジーの範囲）。

```
Overview → 小節ruler → locator lane → Inbox | rail | packing面 → 分秒ruler
```

- **分秒ruler**: 完成条件が尺で定義されている以上、小節番号だけでは足りない。
  上が小節、下が分秒（Abletonと同じ二本立て）
- **Overview**: 3〜5分を小節ズームで見ると画面に入らない。
  **畳みと同じ「その場でミニチュア」の別スケール適用**であり、新しい機構ではない
- **locator**: intro / verse / chorus。音楽同期の作品なので曲構造のマーカーが要る
- **選択**: 全操作の前提。clipは白outline、keyはさらに外側のoutline（規範どおり）

### 2.12 クリッピングはクリスタ型。表示は結果そのもの

**意味論は既に実装済みで、設計対象ではない。**
`ItemEnvelope.clipping_mask: ClippingMaskSettings { enabled: bool, mode: MaskMode }`、
`MaskMode { Alpha, Luminance, InvertAlpha, InvertLuminance }`、
`Command::SetClippingMask` / `PropertyId::ClippingMask` / undo逆変換まで揃っている。

**モデルはクリスタ型である。** クリップされる側が自分で持つ toggle であり、
Illustrator のような**ドキュメント再構成ではない**
（Illustratorはマスクを最上位へ置き、グループを作り、最上位オブジェクトをクリッピングパスへ変換して
見た目を捨てる。Photoshop / クリスタはアクティブなレイヤー上のボタン1つ）。

**「グループへクリップ」も既に成立している。** `TrackItem { Clip, Group }` が同じ `Vec<TrackItem>` に
並ぶ兄弟で、`Group` も自分の `ItemEnvelope` を持つため、下がGroupでもよく、Group自身もクリップできる。
Photoshopの制約はPhotoshop固有であり、Motoliiは最初から持っていない。

#### 表示

1. **乗っている側にだけ印を付ける。下のものは何も変えない。**
   下側に何かを付けると「下は装置である」と読めてしまい、テクスチャを乗せるという素直な理解が壊れる
2. **クリップされている面は半透明にする。** 破線の枠は**補助**。
   「自分だけでは成立していない」がそのまま透明度になる
3. **下のものから何も計算しない。** 見た目は当該itemの`clipping_mask.enabled`だけで決まる。
   下の対象の時間範囲を見て面を塗り分ける案は**棄却した** ——
   下が移動・トリム・グループ化されるたび追従が要り、UI側に stack 解決を持ち込むことになる。
   **バグの温床**であり、得られる情報に見合わない
4. **有効だが効いていない状態を表示する。** 印を彩度あり→灰色へ落とす。
   クリスタが参照元フォルダ「通過」時にアイコンを赤→灰にするのと同じで、**黙って無視しない**
5. **行を跨ぐ連結線を引かない。** packing帯の上下は stack order とは限らず、
   隣接に依存する絵は嘘になり得る。規範の「接続はArchitect」とも一致する

#### ミュートとの弁別

両者とも「弱まった面」なので、**模様で分ける**。

| | 面 | 模様 |
|---|---|---|
| **クリップ** | 色を保ったまま半透明（地のgridが透ける） | **破線の枠** |
| **ミュート** | 地へ沈む（彩度が落ちる） | **ハッチ** |

彩度が残るか落ちるかで一次識別し、破線／ハッチで確定する。
**ミュートを破線だけにしない**（模様があるほうが分かりやすいことを fixture で確認）。

#### 名前

**UI表記に「マスク」を使わない。** 「マスク」と呼んだ時点で「何かを隠す装置」の含意が入り、
下のレイヤーが装置に見える。クリスタは「下のレイヤーでクリッピング」としか言わず、
一度も「マスク」と言わない。**動作をそのまま名前にする。**
schemaの型名（`ClippingMaskSettings`）とUI表記が一致する義務はない
（規範に「通常UIは『エフェクト』等を使い、`Vism`はDeveloper infoへ下げる」という先例がある）。

#### 分離した宿題

`visible` は「自身の描画除外。**依存先(parent/mask/LookAt)としては評価可**」であるため、
非表示でも効き続ける参照元が存在しうる。2.4のミュート表現（面を沈める＋ハッチ）は
「何もしていない」を意味するので、その場合に誤解を生む。
**これはクリッピングではなくミュート表示の課題**であり、混ぜない。

## 3. 観察（決定ではない）

### 3.1 Ableton実測値

インストール済み `Live 12 Beta` のテーマXMLから抽出。scratchpadへTSV保全。

- `Default Dark Neutral Medium`: `Desktop #2a2a2a` / `SurfaceBackground #363636` /
  `SurfaceHighlight #464646` / `ControlBackground #1e1e1e` / `ControlForeground #b5b5b5` /
  `ControlContrastFrame #111111` / `GridLineBase #06060954` / `ArrangerGridTiles #0a0a1419` /
  `AutomationColor #ff4d47` / `ChosenDefault #ffad56`
- 利用者の実機は **Cool Medium**（地に青み。`SurfaceBackground #333540`）
- **記憶に基づく推測は全項目でずれていた。** 特に文字を明るくしすぎ、clip色を彩度高く見積もっていた

### 3.2 Arrangement Viewのレイアウト

縦: Overview → beat-time ruler → scrub area → locator → (拍子マーカー) → track lanes →
Mixer Drop Area → time ruler（上が小節、下が時間の**2本**）。
横: clipキャンバスが左いっぱい、**Track Controlsは右端**（Motoliiは採らない。世間標準は左）。
トラックは main lane + take lane + automation lane の**入れ子**。

**clip barだけがdrag可能で、波形やMIDI表示からはdragできない** ——
名前バーは装飾ではなく掴む場所である。

### 3.3 skiaで実測できたこと

- 9.5〜10pxの文字が潰れない（システム既定フォント）
- 1px罫が@2xで正確に出る
- 波形はmin/max envelopeの塗りで安い
- **grid密度**: 小節幅19pxで1/4拍まで引くと約5px間隔になり、罫線でなく縞のノイズになる。
  Abletonがズームで間引いているのはこのため。HTMLでは気づけなかった
- probeは `skia-safe default-features=false, features=["binary-cache"]` の**CPU raster**

### 3.4 CJKフォントの同梱が必須

`FontMgr::default()` のシステム既定はCJKを解決せず、日本語が豆腐になる。
Abletonが `NotoSansCJKjp` / `NotoSansCJKkr` / `NotoSansCJKsc` / `unifont` を同梱しているのはこのため。
**依存・ライセンス・配布サイズに効く具体的な製品要求。**

## 4. 設計値（暫定・fixture水準）

**G0-6のtheme token値を固定しない。** 実タイムラインの密度と実機で再判定する。

- Object palette: **OKLCH L=0.74 / C=0.075** の6スロット
  `#96aadb` `#6fb9c1` `#bfa973` `#89b992` `#d69a8b` `#c39bc5`
  共通暗色 `#141414` に対するコントラスト **7.73:1〜8.26:1（振れ幅0.53）**
- 行高 20px / rail 84px / marker 10px（13pxのほうが段階は読みやすいが密度未検証）
- delta閾値 hold `<0.01` / small `<0.12` / large `>=0.35`

  **合成順（`Vec<TrackItem>`の入れ子）を見せる面としてこれが担えるか**が、2.12から残った問い。
  クリッピングは順序の隣接で定義されるが、packing面はその順序を見せない

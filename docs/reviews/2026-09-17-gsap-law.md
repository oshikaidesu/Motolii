# GSAP の動きの法 — ease・stagger・位置の文法・repeat(2026-09-17)

利用者の裁定「GSAP の動きができるまで自走してくれ、次の参考先は GSAP」。芯は [Web の欄 a](2026-09-17-web-fields-a.md) と同じ: **ソフトが持つのは意味でなく道具、名前と既定は GSAP の語、値は時刻の純関数、式はそのまま写す、離散の切替の後に連続の収まりが置ける、発明しない — GSAP が開けている所は開けたまま列挙する**。定規は GSAP の source(MIT、`src/gsap-core.js` と `src/EasePack.js`)と取説(Eases / Staggers / Position Parameter)。参照値は本物の GSAP を node で走らせて取った(`gsap.parseEase(name)(t)`、`gsap.utils.distribute(vars)`)。

## 1. Ease 棚 — GSAP の ease の名前を既存の型へ

- **意図**: Web の写しで GSAP の ease(`power2` / `expo` / `sine.inOut` / `elastic.out(0.3)`)を Bezier の数で書いていた(c2・c3・c4・c7・c8・c10)。台本は GSAP の語で書き、数は 1 か所の表が持つ。利用者「ease は Motolii が持ってるだろ」— **評価器も型も足さない**(最初は `Interp::Gsap` を足して式を写したが、同じ意味を 2 箇所に書く形なので取り消した: efde75f30 → 本 commit)。
- **札**: 鍵の ease に GSAP の文字列 — `"power1".."power4"` / `"sine"` / `"expo"` / `"circ"` / `"back(overshoot = 1.70158)"` に `.in / .out / .inOut`(向きが無ければ GSAP と同じく `.out`)、`"elastic(amplitude = 1, period = 0.3)"`、`"bounce"`、`"steps(n)"`、`"none"`。別名(`linear` / `quad` / `cubic` / `quart` / `quint` / `strong` / `power0`、`Power2.easeOut` の大文字形)も `_easeMap` の通り。窓の型はそのまま(Hold / Linear / Bezier / Bounce / Elastic / Cyclic / Random / Steps / ElasticSteps)。
- **先例(GSAP source の行)**: `gsap-core.js` 1016 `_configEaseFromString`(`family.dir(args)` の読み)、1022 `_parseEase`、1023 `_insertEase`(向き無し = easeOut)、1046 `_configBack`(多項式)、1036 `_configElastic`(amplitude < 1 は period を割る)、1083 `SteppedEase.config`。写し先は CSS の cubic-bezier の表(easings.net = CSS の `ease-in-quad` 等)。
- **借りた物**: 既存の型の評価(`Interp::ease`)、窓の shape JSON の `kind`、`ease_kinds::decode`(窓の型に無い名前を表で引く)。**足した物**: `eval/gsap.rs` = **名前 → 既存の型の表**だけ(`interp_for`)。power1・power2・back の in/out は多項式なので Bezier に**厳密**に乗る(x1 = 1/3, x2 = 2/3 で x(t) = t、Bernstein 係数から y — `back.out(s)` = Bezier(1/3, (s+3)/3, 2/3, 1))、他は easings.net の数。elastic → 既存 `Elastic{limit: 1 + amplitude/2, period, damp: 0.35}`(period は同じ語、limit は最初の山で合わせた)、bounce → 既存 `Bounce{first_dip: 1.5/2.75, dip: .75}`(GSAP の最初の谷の (u, v))、steps(n) → 既存 `Steps{width: 1/n}`。表は doc に置いた — 項目 2 の `Stagger Ease` が doc の中で同じ表を引くため(台本側に置くと 2 箇所になる)。
- **絵**: 台本 12 本(c2・c3・c4・c7・c8・c10 と `_x`)の Bezier 定数を GSAP の文字列へ。evidence は §5 と同じ道で焼き直す。
- **test(借りた定規 = 本物の GSAP、node で `gsap.parseEase(name)(t)`、t = .25/.5/.75)**: `mapped_eases_stay_within_the_recorded_error_of_gsap` — 誤差の上限を行ごとに記す: 厳密(0): none、power1/power2 の in/out、back の in/out(overshoot 込み)。easings.net の Bezier: power3/4 の in/out ≤ .008、sine/expo の in/out ≤ .008、circ の in/out ≤ .002、inOut は .005〜.029(power4/expo/circ の inOut が最大 .029)、back.inOut .054。既存の型: elastic.out .039、**bounce.out .15**(減衰の則が違う — GSAP は振幅 1/4・幅 1/2、既存は振幅も幅も同じ比)、**steps(5) .2**(段の時刻が GSAP は k/(n+1)、既存は k/n)。`the_string_grammar_is_gsaps_and_unmapped_names_are_refused_by_name`、script `gsap_ease_strings_become_gsap_keys`。
- **GSAP が開けている所 / 写せない物(決めていない)**: (1) **写せない**: `elastic.in / .inOut`、`bounce.in / .inOut`(既存の型に向きの反転が無い)、`steps(n, true)`(immediateStart)、`back.inOut(s ≠ 既定)`、`slow` / `rough` / `expoScale`(EasePack)、`CustomEase`。断る時に名指しする。(2) elastic の式は別物(GSAP `2^(−10p)·sin`、既存は `(1−u)^n·cos` + smoothstep の入り)— 誤差 .039 を記録、直すなら既存の型の側。(3) `_parseEase` は知らない名前を黙って既定にするが、ここは断る。(4) Lottie の書き出しは既存の型の通り(Bezier は出る、Elastic / Bounce / Steps は断る)。

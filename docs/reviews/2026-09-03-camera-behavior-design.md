# カメラの挙動設計 — 動かす口・追随する面・傾きの持ち主

- 日付: 2026-09-03
- 位置づけ: **設計材料**(コードに触らない上流工程)。判断済みの物と利用者裁定待ちを分ける。
  縫い目の事実は [カメラ縫い目調査](2026-08-21-camera-seam-survey.md)、
  投影の意味は [M2 camera 決定](2026-07-16-m2-comp-camera-decision.md)、
  2台カメラは [Stage 対話の概念地図](2026-08-18-stage-interaction-concept-map.md) §4 を継ぐ
- 発端: 利用者「足りてなかったのがカメラ周りの挙動。今カメラが動くとどうなっている?」
  → 続いて「角度をつけた板を上へ動かすと視差で角度が変わってしまう。AE が畳むのには
  それなりの利益があった」

## 0. 現在地(2026-09-03、`main` c2c7a89 を読んだ事実)

| 段 | 在る | 無い |
|---|---|---|
| 意味 | `Composition.camera` = center / zoom / roll の 3 track(`motolii-store/src/view/resolve.rs:28` `resolve_camera`)。向きは固定で常に world +Z | 向き・注視点・被写界深度 |
| 投影 | `motolii-core/src/camera.rs` が唯一の正本。透視、既定の縦画角 55°。全層 z=0 かつ既定カメラで旧正射影と機械精度一致 | 正射影の variant(M2 の `PlanarOrthographic` は next/ で終わった) |
| 描画 | Stage の `render_frame_into` は毎フレーム `resolve_camera(t)` を読む。track が在れば絵は動く。`pinned` 層は `camera_screen_from_world_z0` の逆行列で打ち消し(`sequential.rs:105-121`) | — |
| **書く口** | `Intent::SetCameraTrack` / `SetCameraPropertySlot` | **front に camera の文字が 0**。Inspector・keymap・Timeline のどこからも触れない。fixture にもカメラ key は無い。Lottie 書き出しだけが読む |
| **Stage の操作面** | ギズモ・当たり判定(`probe/src/stage_widget.rs:167` `selection_geom_in`) | position/anchor/scale/rotation を comp 座標に直置き。**カメラも z も通していない**。カメラが動くと絵は動くのに枠は元の場所に残る |
| 観測カメラ | engine に `ObservationCamera`(pan/zoom のみ、`motolii-engine/src/lib.rs:146`)と `render_frame_with_view_camera` | Stage が呼んでいない。Stage 上のパン・ズーム閲覧は無い |
| `pinned` | `LayerAttrs::pinned`(`motolii-store/src/lib.rs:679`)。合成器は既に受ける | **触る口が無い**(Q0b 違反) |

一言で: **カメラは意味と描画では動くが、利用者は動かせず、動いたら Stage の操作面が置き去りになる。**

## 1. 語彙(この文書で固定する呼び名)

- **レンダリングカメラ** = `Composition.camera`。Document の作品意味。書き出しに出る。
- **観測カメラ** = Stage の閲覧視点。Document 非搭載・書き出し非影響(裁定156/157)。
  Blender の viewport camera、AE の comp viewport と同型。
- **ひっつき** = `pinned`。世界に居ない。カメラを無視して画面座標に貼る(HUD)。
- **傾きの持ち主**(新規、§4)= 板の `rotation.x/y` を誰が投影するか。**カード**(板が自分で
  焼く)か **世界**(共有カメラが投影する)か。

## 2. 判断済み(既存裁定から導ける。再導出しない)

- **カメラは 1 つ、世界は 1 つ、既定 z=0**(裁定113)。カメラレイヤー・層別カメラ・shot switch は持たない。
  → AE の「カメラレイヤーを作る」反射は継がない(「そういうものだ」と教わって覚えた物。AGENTS.md の篩)。
  カメラは Composition の常在属性として Inspector に**層を選んでいない時**に出る。
- **観測カメラは Document に乗らない**(裁定156)。書き出し経路は `render_frame(view, t)` の 2 引数固定のまま、
  観測は別エントリ `render_frame_with_view_camera` からしか呼ばない(縫い目調査 §3 の担保)。
- **z=0 はモードでない・境目を作らない**(裁定115/274)。AE の「3D スイッチ」の**見た目**は借りてよいが、
  意味を「3D を有効にする」にしない。欄(rotation.x/y/z)はスイッチの状態に関わらず常に出す。
- **Preview = Export**(裁定15)。レンダリングカメラで描いた枠の内側と書き出しが同じ画。観測カメラは
  その枠を**外から眺める**だけ。
- **Document への書きは Intent 経由のみ**。カメラの 3 property は `SetCameraTrack`、
  層の 2 スイッチは `SetAttrs`(patch)。どちらも 1 ジェスチャ = 1 undo(Q2)。

## 3. 挙動の設計(判断済みの上に置く)

### 3.1 レンダリングカメラを動かす口

| 面 | 挙動 | 根拠 |
|---|---|---|
| Inspector(層未選択時) | `Camera` 節に Center X/Y・Zoom・Roll の 3 行。既存の prop_row と同じ作法(ドラッグ scrub・key ◇・Enter 確定・Esc 取消) | Q0b、既存の Inspector 文法(Q1) |
| Timeline | camera は行を持たない。**Inspector の key ◇ が Timeline の key と同じ意味**で、camera の key はルーラー直下の帯(層行ではない)に出す | 裁定113「カメラレイヤーを持たない」と Q5(key の正本は 1 つ)の両立 |
| Stage | カメラ用ギズモは**作らない**。center は「Stage を掴んで世界を動かす」操作と紛らわしく、AE でもカメラの直接操作は orbit ツール(教わる操作)。Inspector から打つ | 篩(教わって覚える操作は継がない) |
| 打鍵 | 無し。カメラ操作に共通打鍵は無い([打鍵の逆算](2026-08-30-ae-shortcut-backsolve.md)に該当行なし) | — |

### 3.2 カメラが動いた時に**保たれるべき等式**(不変量台帳へ足す行)

[不変量台帳](2026-08-30-invariant-ledger.md)の流儀で、窓が要らず `Document` 水準で測れる物:

| 不変量 | 測り方 |
|---|---|
| **ギズモの枠 = 描かれた板の輪郭** | 層の四隅を `camera_screen_from_world_at_z(comp, camera, z)` で写した点と、Stage が描く枠の四隅が一致する。カメラ既定・z=0 なら恒等 |
| **クリックで拾う層 = その画素を描いた層** | 当たり判定を上と同じ写像で行う。カメラを動かしても「見えている物を掴める」 |
| **pinned 層はカメラで動かない** | center/zoom/roll を何にしても pinned 層の画面座標は不変 |
| **観測カメラは書き出しを変えない** | `render_frame` と `render_frame_with_view_camera(既定)` のバイト一致。観測を動かしても `render_frame` は不変 |
| **カメラ key は層の Move で動かない** | 層の帯をずらしても camera track は不変(camera は Composition の持ち物) |

Stage の追随は、`selection_geom_in` が返す `box_` を comp 座標のまま使うのをやめ、**四隅を投影して
枠を描き、当たり判定は逆写像**(固定 z の平面ではアフィンなので `try_invert` できる。
[ギャップ地図](../ui-inherited-grammar-gap.md) Stage 節「hit 系は逆変換併走」と同件)にする、が実装の形。
傾いた板(z が四隅で違う)は 4 点を個別に投影する。

### 3.3 観測カメラ(Stage の閲覧)

- 動詞は **パン / ズーム / fit / 100%** だけ。orbit は持たない(向きの表現は裁定115 で未開放。
  観測だけ orbit を開けると「観測では見えるが書き出せない」画が生まれ、Preview=Export の審判が濁る)。
- 入力: pinch = ズーム、Space+drag = パン、`Shift+Z` = fit、`Cmd+=`/`Cmd+-`(ギャップ地図 Tier 1.5)。
  Space は再生と衝突するので **Space 押下中の drag** だけをパンに割り当て、単押しは再生のまま。
- **枠の線**を Stage に描く。レンダリングカメラの可視矩形を `camera_screen_from_world_z0` で写した物。
  観測カメラで引くと枠の外の層も見える・選べる・編集できる(2026-07-23 決定「frame 外も同じ world/camera から表示」)。
- 置き場: `Session` ではなく Stage widget 直下(縫い目調査 §3 の推し「表示専用・Document 非搭載」の precedent)。

### 3.4 入力の調停(概念地図 §6 の 3 状態を採る)

ギズモ掴み中 / 観測カメラ操作中 / 素通し。掴んでいる間は Space+drag を観測へ流さない。
観測操作中はギズモの hit を止める。

## 4. 傾きの持ち主 — AE の「畳む」が持っていた利益を属性で取り戻す

### 4.1 事実

透視カメラでは板の見え方は姿勢だけでなく**画面内の位置**で決まる(視線が板の中心を通る角度が
変わる)。同じ傾きの板を上へ運ぶと見た目の角度が変わる。AE の 3D レイヤーも同じ。AE で
「畳む(collapse)を切ったプリコンポ」がこれを回避できるのは、中で 3D として描いた結果を
外で **2D の板として置き直している**から。

**カメラ設定では回避できない**: 正射影にすれば消えるが z の視差も消える(裁定115 の「インパクト」を
捨てる)。望遠にすれば小さくなるがゼロにならない。カメラを板に追従させると他の層が壊れる。
→ カメラの問題ではなく **「この傾きは世界の性質か、板の性質か」を層ごとに言い分ける問題**。

### 4.2 三段の分解

| | 位置・z | 傾き(rotation.x/y) | 実体 |
|---|---|---|---|
| **ひっつき** | カメラ無視。画面座標 | 板が焼く | `pinned`(既存) |
| **カード**(新規) | 世界。カメラのパン・ズーム・z の視差を受ける | **板が自分の中心から正対で焼く**。どこへ運んでも同じ見た目 | `tilt = Card` |
| **世界** | 世界 | 共有カメラが投影。位置で見え方が変わる | `tilt = World`(今の実装) |

利用者が困っていたのは**真ん中が無い**こと。AE はそれをプリコンポで作っていた(裁定「Group は precomp
でない」と整合: プリコンポは持たないので、属性で持つ)。

### 4.3 UI — AE の 3D スイッチの見た目を借りた 2 つの層属性

- Timeline の層行、M/S/L の隣に **2 つのグリフ**: ひっつき(📌 相当)/ 傾きの持ち主(カード ⇄ 世界のトグル)。
  Inspector の Transform 節にも同じ 2 つを出す(Q5: 同じ真実を両面が表示)。
- **意味は属性、モードでない**: どちらの状態でも rotation.x/y/z の欄は出す(裁定274「欄を消さない」)。
  「3D」という語を UI に置かない。
- **規則は 1 本**: ひっつき ON の間、傾きの持ち主は**カード固定**。トグルは消さず、押したら
  「ひっつき中はカード固定」と理由を返す(Q3 の拒否の報酬、Q0b)。
- 書き込みは `Intent::SetAttrs { patch }`(M/S/L と同じ経路)。1 クリック = 1 undo。
- Lottie に該当語彙は無い(camera-layer 系は不採用、裁定65)。**離れる裁定として [deltas](../motolii-deltas.md) へ 1 行足す**(裁定後)。

### 4.4 実装の形(合成器、1 段)

カードは **2 パス目を増やさない**。板の四隅を「板の中心を原点にした局所カメラ(既定の姿勢)」で
投影して 2D の四角(アフィンでは表せない一般四角形)を作り、それを world の `position`/`z` に置いた
平らな板として共有カメラへ渡す。`pinned` が `pinned_cancel` を transform に掛けてから同じ
カメラへ渡すのと同じ手口(`sequential.rs:120`)で、投影の正本は `motolii-core::camera` のまま。

## A. 利用者裁定待ち(手を出さない)

| 件 | 分岐 |
|---|---|
| **傾きの持ち主の既定** | **推し = カード**。傾きだけ持つ層にとって透視の位置依存は驚きしか生まない。反対側: 既存 Document で傾けた層(2026-08-30 の MOTOLII_TILT 検分のみ、製品データ無し)の見た目が変わる |
| 既定を z の有無で切り替えるか | **推し = 切り替えない**(境目を作らない裁定と同根)。属性 1 つ、既定 1 つ |
| グリフの絵 | ひっつき = ピン、カード/世界 = ? AE の立方体は「3D」を連想させるので避ける |
| camera key を出す場所 | ルーラー直下の帯(3.1 の推し)か、Inspector だけか |
| 観測カメラの orbit | **推し = 持たない**(3.3)。3D 素材が入った時に再審 |
| 既定画角 55° | カードが既定になれば広角の害は減る。据え置きで良いか |
| 手癖 | AE の `C`(カメラツール)は継がない(教わる操作)。継ぐなら Space+drag のパンだけ |

## B. 裁定後にすぐ出せる(器が在る)

1. `pinned` を触る口(Timeline グリフ + Inspector)。属性も合成器も既にある。**最小の Q0b 解消**
2. Inspector の Camera 節(層未選択時)。`prop_row` の流用、`SetCameraTrack` へ書く
3. Stage の枠と当たり判定をカメラ・z 込みの投影へ(3.2 の不変量 2 本を test で先に縛る)
4. `tilt` 属性の追加(`LayerAttrs` に 1 bit、`LayerAttrsPatch` に 1 欄)+ 合成器のカード投影 + グリフ
5. 観測カメラ(Stage のパン・ズーム・fit・枠の線)

順序は 1 → 3 → 2 → 4 → 5。1 と 3 は裁定を待たずに出せる。

## C. 先に測ってから出す

- 傾いた板の四隅投影が **宿題 G(板を傾けると消える)** と同じ穴を踏まないか。`DepthOffset` が
  同一平面前提なら、カード投影(平らな板)は G を**回避する側**になる。逆に世界投影の修正は G の解決待ち
- 観測カメラの Space+drag が Blitz のキー repeat と衝突しないか(Space 単押し = 再生の判定)

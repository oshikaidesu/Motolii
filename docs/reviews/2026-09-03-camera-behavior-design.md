## 1. 語彙(この文書で固定する呼び名)

- **レンダリングカメラ** = `Composition.camera`。Document の作品意味。書き出しに出る。
- **観測カメラ** = Stage の閲覧視点。Document 非搭載・書き出し非影響(裁定156/157)。
  Blender の viewport camera、AE の comp viewport と同型。
- **投影の状態**(新規、§4)= 層属性 `2D / 2.5D / 3D`。2D = 画面に貼る(旧 `pinned`)、2.5D = 傾きは層が自分で焼き
  位置と z は世界、3D = 共有カメラが投影する。

## 2. 判断済み(既存裁定から導ける。再導出しない)

- **カメラは 1 つ、世界は 1 つ、既定 z=0**(裁定113)。カメラレイヤー・層別カメラ・shot switch は持たない。
  → AE の「カメラレイヤーを作る」反射は継がない(「そういうものだ」と教わって覚えた物。AGENTS.md の篩)。
  カメラは Composition の常在属性として Inspector に**層を選んでいない時**に出る。
- **観測カメラは Document に乗らない**(裁定156)。書き出し経路は `render_frame(view, t)` の 2 引数固定のまま、
  観測は別エントリ `render_frame_with_view_camera` からしか呼ばない(縫い目調査 §3 の担保)。
- **z=0 はモードでない・境目を作らない**(裁定115/274)。AE の「3D スイッチ」の**見た目**は借りてよいが、
  意味を「3D を有効にする」にしない。欄(rotation.x/y/z)はスイッチの状態に関わらず常に出す。
- **Preview = Export**(裁定15)。レンダリングカメラで描いた枠の内側と書き出しが同じ画。観測カメラは
  その枠を**外から眺める**だけ。
- **Document への書きは Intent 経由のみ**。カメラの 3 property は `SetCameraTrack`、
  層の投影の状態は `SetAttrs`(patch)。どちらも 1 ジェスチャ = 1 undo(Q2)。

## 3. 挙動の設計(判断済みの上に置く)

### 3.1 レンダリングカメラを動かす口

| 面 | 挙動 | 根拠 |
|---|---|---|
| Inspector(層未選択時) | `Camera` 節に Center X/Y・Zoom・Roll の 3 行。既存の prop_row と同じ作法(ドラッグ scrub・key ◇・Enter 確定・Esc 取消) | Q0b、既存の Inspector 文法(Q1) |
| Timeline | camera は行を持たない。**Inspector の key ◇ が Timeline の key と同じ意味**で、camera の key はルーラー直下の帯(層行ではない)に出す | 裁定113「カメラレイヤーを持たない」と Q5(key の正本は 1 つ)の両立 |
| Stage | カメラ用ギズモは**作らない**。center は「Stage を掴んで世界を動かす」操作と紛らわしく、AE でもカメラの直接操作は orbit ツール(教わる操作)。Inspector から打つ | 篩(教わって覚える操作は継がない) |
| 打鍵 | 無し。カメラ操作に共通打鍵は無い([打鍵の逆算](2026-08-30-ae-shortcut-backsolve.md)に該当行なし) | — |

### 3.2 カメラが動いた時に**保たれるべき等式**(不変量台帳へ足す行)

[不変量台帳](2026-08-30-invariant-ledger.md)の流儀で、窓が要らず `Document` 水準で測れる物:

| 不変量 | 測り方 |
|---|---|
| **ギズモの枠 = 描かれた板の輪郭** | 層の四隅を `camera_screen_from_world_at_z(comp, camera, z)` で写した点と、Stage が描く枠の四隅が一致する。カメラ既定・z=0 なら恒等 |
| **クリックで拾う層 = その画素を描いた層** | 当たり判定を上と同じ写像で行う。カメラを動かしても「見えている物を掴める」 |
| **pinned 層はカメラで動かない** | center/zoom/roll を何にしても pinned 層の画面座標は不変 |
| **観測カメラは書き出しを変えない** | `render_frame` と `render_frame_with_view_camera(既定)` のバイト一致。観測を動かしても `render_frame` は不変 |
| **カメラ key は層の Move で動かない** | 層の帯をずらしても camera track は不変(camera は Composition の持ち物) |

Stage の追随は、`selection_geom_in` が返す `box_` を comp 座標のまま使うのをやめ、**四隅を投影して
枠を描き、当たり判定は逆写像**(固定 z の平面ではアフィンなので `try_invert` できる。
[ギャップ地図](../ui-inherited-grammar-gap.md) Stage 節「hit 系は逆変換併走」と同件)にする、が実装の形。
傾いた板(z が四隅で違う)は 4 点を個別に投影する。

### 3.3 観測カメラ(Stage の閲覧)

- 動詞は **パン / ズーム / fit / 100%** だけ。orbit は持たない(向きの表現は裁定115 で未開放。
  観測だけ orbit を開けると「観測では見えるが書き出せない」画が生まれ、Preview=Export の審判が濁る)。
- 入力: pinch = ズーム、Space+drag = パン、`Shift+Z` = fit、`Cmd+=`/`Cmd+-`(ギャップ地図 Tier 1.5)。
  Space は再生と衝突するので **Space 押下中の drag** だけをパンに割り当て、単押しは再生のまま。
- **枠の線**を Stage に描く。レンダリングカメラの可視矩形を `camera_screen_from_world_z0` で写した物。
  観測カメラで引くと枠の外の層も見える・選べる・編集できる(2026-07-23 決定「frame 外も同じ world/camera から表示」)。
- 置き場: `Session` ではなく Stage widget 直下(縫い目調査 §3 の推し「表示専用・Document 非搭載」の precedent)。

### 3.4 入力の調停(概念地図 §6 の 3 状態を採る)

ギズモ掴み中 / 観測カメラ操作中 / 素通し。掴んでいる間は Space+drag を観測へ流さない。
観測操作中はギズモの hit を止める。

## 4. 傾きの持ち主 — AE の「畳む」が持っていた利益を属性で取り戻す

### 4.1 事実

透視カメラでは板の見え方は姿勢だけでなく**画面内の位置**で決まる(視線が板の中心を通る角度が
変わる)。同じ傾きの板を上へ運ぶと見た目の角度が変わる。AE の 3D レイヤーも同じ。AE で
「畳む(collapse)を切ったプリコンポ」がこれを回避できるのは、中で 3D として描いた結果を
外で **2D の板として置き直している**から。

**カメラ設定では回避できない**: 正射影にすれば消えるが z の視差も消える(裁定115 の「インパクト」を
捨てる)。望遠にすれば小さくなるがゼロにならない。カメラを板に追従させると他の層が壊れる。
→ カメラの問題ではなく **「この傾きは世界の性質か、板の性質か」を層ごとに言い分ける問題**。

### 4.2 三段の分解 — 層属性 `projection: 2D | 2.5D | 3D`(利用者裁定 2026-09-03)

2 つのトグル(ひっつき / 傾きの持ち主)ではなく、**3 値の属性 1 つ**にする。「ひっつき中はカード固定」
という規則が要らなくなり、グリフも 1 つで済む。名前は利用者の語彙そのまま(MV 制作者は「2.5D で
動かす」と普通に言う。教える必要が無い)。

| | 位置・z | 傾き(rotation.x/y)・メッシュの姿勢 | 実体 |
|---|---|---|---|
| **2D** | カメラ無視。画面座標に貼る(HUD・ロゴ) | 層が自分で焼く | 今の `pinned` |
| **2.5D** | 世界。カメラのパン・ズーム・z の視差を受ける | **視線固定**: カメラがその層を真正面から見ているとして投影し、投影後に本来の画面位置へずらす。どこへ運んでも同じ向きに見える。**物体の奥行きは世界のまま**(板にしない・焼かない) | 新規 |
| **3D** | 世界 | 共有カメラが投影。位置で見え方が変わる | 今の実装 |

- **3D 素材にもそのまま通る**: 2D = メッシュを描いた結果を画面に貼る。2.5D = メッシュはどこへ運んでも同じ向きに見えるが、
  奥行き・深度テスト・他の 3D 物体との重なりや貫通(バグ表現)はそのまま生きる。3D = 世界に居る。
  動画・図形・テキスト・メッシュ・点群のどれでも同じ意味。**2.5D は impostor ではない** — 物体自身の奥行きまで畳むのは
  AE のプリコンポの畳みであって、ここでは畳まない(利用者 2026-09-03)。
- **素材の種類が既定を決める**: 動画・図形・テキスト = 2.5D、メッシュ・点群 = 3D。利用者は例外だけ切り替える。
- **語の意味の変更**(deltas へ 1 行): これまで「2.5D」は裁定115 の「プレビュー全体の透視表現」を指していた。
  以後は**層ごとの投影の状態**を指す。
- **モードにしない(裁定115/274 は据え置き)**: どの値でも `rotation.x/y/z`・`position.z` の欄は出て、いつでも打てる。
  変わるのは投影の仕方だけ。「3D を有効にする」儀式は無い。

### 4.3 UI

- Timeline の層行、M/S/L の隣に **文字グリフ 1 つ**(`2D` / `2.5D` / `3D`)。クリックで巡回、右クリック menu で直接選ぶ。
  Inspector の Transform 節にも同じ 3 択(Q5: 同じ真実を両面が表示)。
- 書き込みは `Intent::SetAttrs { patch }`(M/S/L と同じ経路)。1 クリック = 1 undo。`pinned: bool` は
  この 3 値へ置き換える(2D = 旧 pinned)。
- Lottie に該当語彙は無い(camera-layer 系は不採用、裁定65)。離れる裁定として [deltas](../motolii-deltas.md) へ 1 行。

### 4.4 実装の形(合成器、1 段)

2.5D は **2 パス目も texture も増やさない**。層ごとの view 行列を「層の中心を光軸に載せた」物に差し替え
(カメラを層の中心の真正面へ平行移動した view)、共有の投影で投影した後に**画面オフセット**(本来の画面位置と
光軸との差)を足す。深度値は本来の world の z から取るので、深度テストと 3D 物体同士の貫通は 3D と同じに
起きる。平らな層ではこれが「傾きが位置で変わらない」そのもの。`pinned` が `pinned_cancel` を transform に
掛けてから同じカメラへ渡すのと同じ手口(`sequential.rs:120`)で、投影の正本は `motolii-core::camera` のまま。

近似: 画面端で 2 つの 2.5D 物体が貫通する時の貫通線は、それぞれをずらした空間で計算した物になる。
物理ではなく表現なので許容する。

### 4.5 不変量(台帳へ足す行)

| 不変量 | 測り方 |
|---|---|
| **2.5D の層はどこへ運んでも同じ向きに見える** | 平らな層: 傾きを固定し position を変えても、四隅の画面座標の差分が平行移動だけ(形が変わらない) |
| **2.5D 同士の重なりは 3D 同士と同じ深度で判定される** | 同じ 2 物体を 2.5D と 3D で描き、貫通の有無(どちらが手前か)が一致する |
| **2.5D は奥行きを保つ** | 2.5D のメッシュの深度値の範囲が、3D で描いた時と同じ(板に潰れていない) |

## B. 裁定後にすぐ出せる(器が在る)

1. `pinned` を触る口(Timeline グリフ + Inspector)。属性も合成器も既にある。**最小の Q0b 解消**(4 で 3 値へ育つ)
2. Inspector の Camera 節(層未選択時)。`prop_row` の流用、`SetCameraTrack` へ書く
3. Stage の枠と当たり判定をカメラ・z 込みの投影へ(3.2 の不変量 2 本を test で先に縛る)
4. `projection: 2D|2.5D|3D` 属性(`pinned: bool` を置き換え、`LayerAttrsPatch` に 1 欄)+ 合成器の 2.5D 投影 + グリフ
5. 観測カメラ(Stage のパン・ズーム・fit・枠の線)

順序は 1 → 3 → 2 → 4 → 5。1 と 3 は裁定を待たずに出せる。

## C. 先に測ってから出す

- 傾いた板の四隅投影が **宿題 G(板を傾けると消える)** と同じ穴を踏まないか。`DepthOffset` が
  同一平面前提なら、2.5D(平らな板)は G を**回避する側**になる。逆に 3D の修正は G の解決待ち
- 観測カメラの Space+drag が Blitz のキー repeat と衝突しないか(Space 単押し = 再生の判定)

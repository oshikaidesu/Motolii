## 2. 基準を変えたら、測っていた物が全部消えた — A02

裁定216(昨日)は「マウス完遂路とキーボード完遂路の**両方**」を要求し、`GESTURES.md` が
**「34件中マウスのみ25」**を出した。本日の裁定217(利用者裁定)で主眼をマウス側へ移して再判定した結果:

> **25件のうち、新基準で実際に穴だったのは 0件。**

そして**実際の穴は GESTURES.md が見ていない場所に12件あった** — Inspector と Settings の数値欄が
`transform.rs` の drag 機構(`start_field_drag`/`continue_field_drag`/`finish_field_drag`)を継承せず、
**`text_input` だけで書かれている**箇所:

Fill/Stroke/背景 の RGBA・Composition の W/H/FPS/Duration・AutoSave の2値・Text Size・Line Height・
Tracking・Speed。**連続量なのにドラッグで動かせない。**

構造の根はこう出た: `transform_row`(drag 機構)は `effects.rs` / `mask.rs` / `audio.rs` へは import されて
共有されているのに、`text.rs` / `color.rs` / `attrs.rs` / `settings-pane` は**各々が独自に `text_input` だけを
書いた**。共有関数が在るのに繋がなかった、という一対多の病(2026-08-22 の通し記録が出した型と同じ)。

**とんちは1件も見つからなかった**(仮想キーボード・数値専用ダイアログ・隠しコマンドの grep が空振り)。
ポインタ入力を受け取れない箇所は1件(**iced fork にトラックパッドのピンチ API が無い** — M18 Zoom 実装時に直撃)。

## 9. 運転の記録 — 監督の失敗

**レーンを worktree 隔離せずに出した**(11本が main の作業ツリーを共有)。実害:

- 2本の成果物が別 commit に巻き込まれて着地(内容同一のため損失なし)
- 各レーンの第1手の作業ツリー巻き戻しは全員が**訂正通知の前に**実行済み。
  追跡外のファイルを消さない性質に救われた

走行中に送った訂正(巻き戻し・退避の禁止、全件ステージの禁止、自分の write-set だけパス直指定)
以降は事故ゼロ。**write-set が構造的に互いに素だったこと(1軸1ファイル)が被害を抑えた** —
軸で切る設計そのものが保険になった。

**次から**: `isolation: "worktree"` を発注時に必ず指定する。

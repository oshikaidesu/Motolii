# 枠(chrome)の文法監査 — 「野暮ったい」の機序特定(2026-08-22)

状態: **監査+裁定179**(利用者「そうやな」で方向承認)
発端: 利用者「基礎の UI が野暮ったい。最近のソフトっぽくない。各ウィンドウは大丈夫だが枠の部分。全体的な主張が多いのかも。色味? アクセント使いすぎ?」参照順列= **ableton / figma / AE**。
証拠: [実窓キャプチャ](evidence/2026-08-22-chrome-audit.png)(preview build・pane_grid 第1切片 merge 後)

## 1. 参照3製品が枠で共有する文法(較正の物差し)

1. **枠は内容と同族色、段差は明度1段だけ** — 線で区切らない(AE=暗い隙間 / Ableton=同一面+間隔 / Figma=明度差のみ)
2. **枠は単色既定、アクセント=状態の瞬間だけ** — 常時点灯している色は装飾=主張
3. **枠の文字・アイコンは内容より ink 1〜2段薄い** — 枠が静かだから内容がヒーロー(S5 と同原理)
4. **箱と線を減らし、affordance は hover で現れる** — 「最近っぽさ」の実体

## 2. 仮説の検定

- 「アクセント使いすぎ」→ **棄却**。画素上のアクセントは選択琥珀・playhead・Key 列程度で抑制されている。コード上も chrome での accent 直用はほぼ無し(selection 36箇所は状態なので正当)
- 「スクラッチのせい」→ **棄却**。同じスクラッチのモック転写 pane は合格している。差は「モックの有無」— 枠(メニューバー・transport)だけモック無しで組まれ、箱文法で書かれた

## 4. 処置(裁定179〜181)

- **裁定179(枠の文法)**: 上記文法4本+第5「**箱は状態の器**」— 常時輪郭は原則廃止。メニュー=素の文字+hover 面 / 値セル=素の数字+hover 箱(AE 型)/ チップ輪郭=選択時のみ / 区切り=明度1段。実装は線化 pass(裁定137)の続編・style 層のみ
- **裁定180(transport 統合)**: 下部 Play バーを撤去し、timeline pane に transport 帯(map 行 1041〜1045 の顔+1138 Timecode)。TL-transport レーン発注済み
- **裁定181(メニューバー= iced_aw menu 移植)**: MB-2 案A(自前 overlay::menu)を上書き — iced_aw の menu モジュールだけを fork API へ vendoring 移植(wraps>移植>スクラッチ)。全 crate 採用ではない。menubar レーン発注済み。D1 はこの新メニューバー+裁定179 スタイルで解消する

残処置: D2/D4/D5(Inspector 値セル・チップ・罫線)は PH-handle 返却後に線化 pass 続編レーンで。

# 2Dワープ・3D変位・配置の分離

2026-09-11利用者承認。2Dの歪みを掛けた素材を2.5Dで置き、その上へ3D変位を掛けられる。内部の画像／文字／図形表現で効果の意味を変えない。効果作者に対象別分岐を要求しない。

## 契約

- **2D Warp**は素材のローカルXY（論理pixel）で評価する画像入力→画像出力。Z・法線・観測カメラを入力にしない。輪郭素材はこの画像を必要とする境界で、投影に必要な密度へ描く。通常の輪郭描画は維持する。
- **3D Field**は位置と法線を持つ空間形状の変位。画像も平面形状として受け、画像だけを視差UVへ変換する分岐を通常路で使わない。2D Warpの出力を貼った平面にも同じFieldを掛けられる。
- **配置の2D/2.5D/3D**は上記と独立。素材内の歪みを決めた後に配置・3D変位・表面・合成へ進む。
- ノイズは既存rerunの同じ実装を使う。2Dの入口は`Turbulent Warp 2D`、既存`motolii.turbulent_displace`は`Turbulent Displace 3D`と明示する。既存ID・値・Undo履歴は書き換えない。AEのbit単位互換ではなく、平面内の歪みの意味を成立させる。
- 2D Warpの対象は平面素材。網・点群への直接適用は無言で無視せず理由を返す。棚からは隠さない。

## 順序と検収

1. `Warp`を既存画像passの仕組みで実行する素材段として宣言。ローカルの論理サイズと画像の画素密度を区別し、Amount/Sizeが画質密度で変わらないようにする。
2. 既存3D Fieldを保ち、平面の実行形状を共通化する。GPUへの平面分割・透明画素の扱いはrerun側へ置く。
3. 書き込み入口で新しい2D WarpがField/Surfaceより前へ入るようにする。逆転させる並べ替えは明示的に拒否し、見える順序と評価順序を揃える。グループWholeの既存未完事項は別タスクのまま保持する。
4. GPUで、Amount 0、時間変化、画像と同じ絵の輪郭、画像密度変更、2D/2.5D配置、2D Warp+3D Field併用を検査する。「画像が変わる」だけでは合格にしない。
5. 関連native/widget試験、build、実窓。既知のmacOS AXクラッシュで実窓が止まった場合は、未検収を明示し、機能完了とは混同しない。

参考: Adobe Distort effectsのTurbulent Displace（画像内の歪み・Amount/Size/Evolution）、現在のVism `pass`/`field`/`surface`、rerunのnoise WGSL・CpuMesh・透明合成、既存の平面paint順と投影密度の試験。

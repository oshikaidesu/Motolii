## 1. 道具立て: 「機構」と「軸」の定義

**機構(mechanism)** = 利用者が何をし(入力)、系が何をするか(書く/覗く/保存する)。見た目・配置・語彙は機構ではない。

### 1.2 「似たりよったり」の判定規則(これを今後の物差しにする)
- **規則 A: 軸のうち 2 つ以上で値が違う案だけが、別の機構。** 1 軸以下の差は NEAR-DUP(統合か敗退)。
- **規則 B: D(入口)の差は、機構の差に数えない。** 同じ engine(I・M・S・T・K の組)を、別の入口から呼んでいるだけの案は、**door(扉)の違い**。扉は競わせず、1 つの機構に束ねて「どの扉を持つか」で扱う。(例: 常設の検索欄と Tab メニューは、同じ「打つ→一覧→適用」の 2 つの扉。)
- **規則 C: 既定値・個数・語彙・配置・重みだけが違う案は knob。** 案として戦わせず、knob にして実操作で決める(PROCESS.md §3)。
- **規則 D: C(感覚の経路)も軸。** 全案が C1/C2 なら、感覚の軸は **空席** で、そこに挑戦者を立てる(§3)。
- 符号の読み方: `D3 I4 M2 S2 T1 C2 K1 L2` のように 8 つを並べる。既存の全案は C が C1/C2 なので、以降の比較では C を省いて 7 軸で書き、C は §3 で扱う。

## 3. 空席の軸と、挑戦者の指示書(challenger briefs)

### 3.0 どの軸が空席か(全 18 グループ共通の診断)
| 軸 | 現存案の状況 | 空席の意味 |
|---|---|---|
| C 感覚: 音 / 触覚 | **0 案**(grep で音・haptic の呼び出し 0) | 「確定していない」「限界」「既定」「数が変わった」を目以外で返す案が無い |
| C 感覚: キー順+意味(Semantics) | **0 案**(Semantics 0 件) | 構造を「読んで歩く」案が無い。hover 専用の入口が多い |
| I 入力: 身振り(flick) | 0 案 | 方向の記憶で選ぶ案が無い |
| I 入力: 打つ(コマンド) | 検索のみ(B3・I7-b)。**値・動詞・選択を打つ案は E10 の言及のみで未作成** | 「opacity 50」「選択: Blur の付いた text」が無い |
| S 構造: 空間の記憶(定位置) | 0 案(星・collection は名前で、位置を記憶に使わない) | 手が位置を覚える案が無い |
| T 時間: 押し続け・歩く・演奏する | hover scrub と B9-a のみ | 時間の中を歩く・動きを演奏して決める案が無い |
| K 確定: 系が前提条件を満たす | 0 案(「できません」と言って止まる) | 行き止まりの先を 1 手で埋める案が無い |
| 学習: やって覚える(learn-by-doing) | 0 案 | 手癖を作る道筋(マウスで覚えたキーを教える)が無い |
| 直接 on-canvas(Stage 上で完結) | I3-a/U1 のみ | 他は Browser/Inspector に閉じる(分割を壊さない既決の範囲) |
| 声・自然文の命令 | 0 案 | **採らない**(Motolii は言葉を発明しない・音声認識は host の責務を超える)。キーボードで打つコマンドで代替 |

### 3.0.1 共通の土台 U-0(各 brief が使う。ここに 1 度だけ書く)
- **キー:** panel 間は F6(または Cmd+数字)、panel 内は矢印(roving focus: listbox / grid / tree / slider の WAI-ARIA パターン)。Enter = 使う・確定、Space = 試す・持つ、Esc = 戻す、`?` = 今のキーを読み上げ。Shift = x10、Alt = x0.1(D-I3 と同じ)。
- **スクリーンリーダー:** 全要素に Semantics(label=名前、value=値+単位、hint=できる操作、state=選択/無効/展開/切替)。状態変化は live region に **1 文・30 字まで**。「何が・どれだけ・何件」を先頭に。
- **音(earcon)6 種:** `tick`(段が変わる、短い click、ピッチ=値の位置)/ `detent`(既定・整数・端・snap、少し長い低音)/ `unavailable`(濁った短音 2 回、書かない)/ `apply`(上昇 2 音、確定)/ `cancel`(下降 2 音、Esc)/ `peek`(試し中だけ鳴る小さな持続音、確定か Esc で止む = **「確定していない」を音で言う**)。音は文字の代わりでなく **並走**(耳の不自由な人の為、全 earcon に視覚と文字の双子)。音量・無音は 1 つの設定。
- **触覚:** `tick`/`detent`/`unavailable` に軽/中/強の 1 回。macOS トラックパッド・iPad の haptic が前提で、Flutter の `HapticFeedback` は desktop で限定的 → ネイティブ層が必要か **要確認 [unverified]**。無い環境は同じ event 表の音で代替(1 つの event 表を全 brief が共有)。
- **「触って分かる」の解釈:** (1) キーの矢印で 1 つずつ読み上げられる(構造を触る)(2) 値の変化が音と触覚で返る(動かして分かる)(3) 位置が固定で、手が覚える(筋肉が触る)。画面を点字や圧覚で出す事は範囲外。
- 各 brief の書式: **機構** / **言葉なしで** / **盲の人の操作**(キー+SR+音)/ **契約** / **置き換え** / **既存との軸差**。

### 3.1 G1 探す: 空席 = 身振り・音色・位置の記憶
**G1-α「Flick wheel(身振りの輪)」**
- 機構: 呼び出しキーを押している間だけ 8 方向の輪が出て、**方向で family を選び、2 度目の flick で候補を選ぶ**(marking menu)。方向は **利用者の使用に応じて固定**(勝手に並べ替えない。D-I7 と同じ理由)。
- 言葉なしで: 方向と形(blur=同心円、glow=光輪…。既存 tile の shape)で覚える。慣れたら輪を描かず flick だけで通る。
- 盲の人: 呼び出しキー+矢印 8 方向で同じ事。SR は「左上、Blur、12 件」。方向ごとに固定のピッチ+パン(左=左耳)。Enter で適用、Esc で戻る。
- 契約: 同じ 2 flick は同じ effect を指す。方向の割り当ては利用者が動かさない限り不変。1 手 = 1 undo。
- 置き換え: Tab メニューの family 帯(横にスクロールする語の列)。
- 軸差: I5(vs I3)、S1(vs S2)、C3、D5。4 軸。

**G1-β「Timbre scan(音色で走査)」**
- 機構: 各 effect family に固有の短い音色(blur=柔らかい雑音の sweep、glow=上昇する鐘、warp=揺れ、color=和音…)を割り当て、一覧を ↑↓ で **高速に(1 秒に 6-8 項目)走査すると音色だけが流れる**。止めると名前を読む。
- 言葉なしで: 音色の連なりで「この辺は blur 族」と分かる。
- 盲の人: ↑↓ 長押しで走査、離すと止まって名前+1 文。`Enter` 適用。視覚の人にも tile の shape と同期して鳴る。
- 契約: 同じ family は同じ音色。音は 150 ms 以内。reduce-sound で全無音。
- 置き換え: 「名前を打たないと見つからない」状況での手がかり(検索欄の補助)。
- 軸差: C3、T2(長押し)、I2(vs I3)。3 軸。実操作(印): 音色は学習が要る。1 日で覚えられるか。

### 3.2 G2 絞る: 空席 = 数を先に言う・歩いて掘る
**G2-α「Count lookahead(押す前に件数を言う)」**
- 機構: facet(種類・性格)の列を ←→ で動かすと、**押す前に「これを足すと 14 件 → 3 件」と結果の件数を言う**(K2: 絞りは Enter まで確定しない)。
- 言葉なしで: 件数 = クリック音の連打(12 件までは 1 個ずつ、超えたら 12 の倍で対数)。0 件は `unavailable`。
- 盲の人: facet 列は radiogroup。SR は「Blur、足すと 3 件」。Enter で確定、Esc で戻る。
- 契約: 確定前に件数が必ず分かる/ 0 件になる絞りは足せない(押しても書かない)。
- 置き換え: B4 の件数帯(絞った後にしか件数が分からない)と、「Nothing matches」の行き止まり。
- 軸差: K2(vs K0)、C3、I2。3 軸。

**G2-β「Walk the tree(定位置の木を歩く)」**
- 機構: 絞らず、**固定の木(種類 > family > 個別)を ←→ で階層、↑↓ で兄弟**に歩く。木の形は利用者の頭に入る(絞りは毎回変わるが木は変わらない)。
- 言葉なしで: 木の位置 = 手の記憶。階層は音の高さ(浅い=低、深い=高)。
- 盲の人: WAI-ARIA tree。SR は「Blur、family 2 の 5、12 件の子」。type-ahead で飛ぶ。
- 契約: 木は並べ替えない。件数は子の数で常に言う。
- 置き換え: タグ帯の「絞るが毎回位置が変わる」面。
- 軸差: S2→木(構造が固定)、I2、C5。実操作(印): 木の深さが 3 を超えると遅い。

### 3.3 G3 見てから使う: 空席 = 変化を音で言う・A/B を瞬時に
**G3-α「Sonified peek(試写の音)」**
- 機構: 試写の間、**元のコマと候補のコマの差を測り、少数の量を音に写す**(明るさの変化=ピッチ、エッジの量=低域の鈍り、色相のずれ=音色、動きの量=震えの速さ)。同じ effect・同じコマは同じ音。差が無ければ無音。
- 言葉なしで: 音の変わり方で「強い/弱い/ほぼ無い」が分かる。
- 盲の人: ↑↓ で候補を移す度に 0.4 秒の音+「明るさ +12%、輪郭 弱い」の 1 文。`peek` 持続音が鳴っている間は未確定。Enter で apply 音。
- 契約: 差の測定は決定的(同じ入力は同じ音)/ 確定まで何も書かない。
- 置き換え: B5-c の視覚だけの試写(視覚は残し、音を並走)。
- 軸差: C3 + 「差を測る」新しい出力(S は直列のまま)。**実操作(印):** 測る量と音の対応が学べるか。盲の人で検証が要る。

**G3-β「Flicker A/B(押している間だけ元)」**
- 機構: Space を押している間 **元のコマ**、離すと **候補**。音色の床が A と B で違う。
- 言葉なしで: 押す/離すで見比べる=手の動き。
- 盲の人: SR「A 元」「B 候補」+床の音色が違う。差を 1 文。
- 契約: 押している間は何も書かない/ 離した状態が現在の候補。
- 置き換え: B9-d の A/B 二枠(Stage を割る面、視覚専用)。
- 軸差: T2、D5(キー)、S2(分割しない)。3 軸。

### 3.4 G4 差し替え・置換/追加: 空席 = 命令で置く・掃くように試す
**G4-α「Place verbs(置く動詞をキーで)」**
- 機構: 選んだ tile で `Space` を押すと **動詞 4 つ(追加 / 置換 / 値を持ち越して置換 / 下に挿入)**。数字 1-4 で選び、対象は名前の一覧(type-ahead)から。drop も Alt も不要。
- 言葉なしで: 4 動詞の順序と数字が固定=位置の記憶。確定の前に「結果の差」を peek 音で。
- 盲の人: SR「置換: Layer 3 の Blur を Glow に。Enter」。Esc で書かない。
- 契約: 動詞は全棚で同じ 4 つ/ 修飾キーを使わない/ 結果の文を確定前に言う。
- 置き換え: B8 の drop+Alt(視覚と指の修飾が前提)と B8-d の二面。
- 軸差: I2(vs I6)、D5、C5。3 軸。

**G4-β「Audition rail(ラジオの preset 選び)」**
- 機構: ↑↓ で候補を順に試着し、**長押しで速度が上がって走査**、離した所で止まる。各候補は family 音色(G1-β)+名前。Enter 確定。履歴を増やさない(D-1)。
- 言葉なしで: 走査の速さ=手の力。止まった所が選択。
- 盲の人: SR は止まった時だけ名前を読む(走査中は音色だけ)。`peek` 持続音が未確定を言う。
- 契約: 走査中は 1 undo も増えない/ 離した候補が現在の試着/ Esc で元。
- 置き換え: B9-a の 1 手ずつの ↑↓(速度が無い)。
- 軸差: T2(長押し加速)、C3、K2 を継続。2-3 軸。

### 3.5 G5 クリックの文法: 空席 = 動詞を名前で呼ぶ・やって覚える
**G5-α「Verb menu on Space(全 panel 共通の動詞)」**
- 機構: どの panel の どの項目でも **Space = 動詞メニュー**(選ぶ・使う・置く・印を付ける)。同じ 4 動詞、同じ数字。単/dbl click は同じ動詞への近道に過ぎず、**文法の本体は動詞**。
- 言葉なしで: 4 動詞の位置と数字が全 panel で同じ。
- 盲の人: SR「使う、2 / 4」。数字で直接。実行後は「Blur を Layer 3 に適用、Cmd+Z で戻る」と 1 文。
- 契約: 全 panel で同じ 4 動詞/ 回数や修飾キーで動詞が変わらない。
- 置き換え: B7-a の「回数で動詞を決める」。
- 軸差: I2(vs I4)、C5。2 軸(弱い 2。実操作で意味があるか)。

**G5-β「Ghost coach(やって覚えるキー)」**
- 機構: マウスで行った操作に **キーの等価があれば、foot line・SR・音(キーのリズム)で 1 回教える**。同じ操作を 3 回すると「次はキーで」と言い、以後は静かに退く。
- 言葉なしで: 打鍵のリズムが音で鳴る(1 キーなら 1 音、chord なら 2 音)。
- 盲の人: 最初からキーを使う想定だが、混在の同席者向け。SR が毎回キーを言う。
- 契約: 同じ operation に 3 回まで/ 退いた後は設定でのみ再開/ 勝手に操作を実行しない。
- 置き換え: 「キーは覚える物」という前提(P10 の最小集合の暗記)。
- 軸差: T2(複数回)、L2、C3。3 軸。実操作(印): うるさくならないか。

### 3.6 G6 お気に入り: 空席 = 定位置・巡回
**G6-α「Pad bank(定位置 16 パッド)」**
- 機構: 利用者の top 16 の effect/preset を **キーボードの固定の 4×4 キー(1234/QWER/ASDF/ZXCV)に割り当て**、1 キーで適用(押し続けると試写、離すと確定)。位置は不変。
- 言葉なしで: 位置と tile の shape と音(各パッドに固有のピッチ)で覚える。
- 盲の人: キーを押すと SR が名前+音。`?` で全 16 を読み上げ。割り当ては「今の物を ⌥+キーで登録」。
- 契約: パッドの位置は利用者が決め、変えない/ 押す = 選択対象へ 1 手/ 空きは `unavailable`。
- 置き換え: Collections の数字キー(分類するだけで、適用は別手)。
- 軸差: I2、S1(位置)、D5、C3。4 軸。

**G6-β「Recent ring(effect 版 Alt-Tab)」**
- 機構: 修飾キーを押したまま Tab で **直近に使った 8 つを巡り**、離すと適用。巡回は時間順で位置は動く(が、巡る間だけ)。
- 言葉なしで: 順序=指の回数。直前の物が 1 回目。
- 盲の人: SR が 1 つずつ名前を読む。peek 音。
- 契約: 離した瞬間に適用/ Esc で何もしない/ 巡回の中身は B10-c と同じ。
- 置き換え: B10-c の積み(見ないと分からない)。
- 軸差: T2、M1、I2。3 軸。

### 3.7 G7 規模: 空席 = 位置の記憶・要約
**G7-α「Fixed map(定位置の 2 次元地図)」**
- 機構: 数千の素材/ effect を **固定の 2 次元の格子(x=種類、y=強さ・重さ)に並べ**、矢印で隣へ。位置が毎回同じなので手が覚える。**ピッチ = y、パン = x**。
- 言葉なしで: 位置と音で場所が分かる。
- 盲の人: grid。SR「x 3、y 2、Blur 20、隣: 左 Blur 10、右 Blur 40」。
- 契約: 格子は並べ替えない/ 新規は端に足す/ 件数が多い所は区切りを言う。
- 置き換え: B12-c(1 軸の帯)と thumbnail の「探索」。
- 軸差: S1、I2、C3。3 軸。実操作(印): 軸の意味付けが妥当か(素材の性質で決まる)。

**G7-β「Digest then sample(要約してから抜く)」**
- 機構: 結果が N 件を超えたら、**一覧でなく要約を先に言う**(「240 件: effect 180、preset 40、media 20。よく使う 3 つ: …」)。`R` で無作為に 5 件抜く、`N` で次の 5 件。
- 言葉なしで: 件数を長さ(音の長さ)で。
- 盲の人: 要約 1 文+抜いた 5 件。
- 契約: 要約は決定的/ 抜き取りは seed 付きで再現できる。
- 置き換え: 「長い一覧をスクロールする」(読み上げで 240 項目は不能)。
- 軸差: I2、S2→要約、C5。2-3 軸。

### 3.8 G8 選択に合わない物: 空席 = 前提を系が満たす
**G8-α「Fix-it(前提を 1 手で満たす)」**
- 機構: 合わない物を選ぶと `unavailable` 音+**理由の 1 文と「直す」1 キー**(「key が要ります。K で付けて続ける」)。押すと **系が前提(key を付ける・parent を選ぶ・layer を選ぶ)を満たして、元の操作を続ける**。
- 言葉なしで: 音が「だめ」と言い、直すキーが 1 つ(固定で `Enter`)。
- 盲の人: SR 1 文。Enter で直して適用。
- 契約: 前提を満たす操作は 1 undo にまとまる/ 満たせない時は理由と代替を言う/ 勝手に実行しない(Enter で初めて)。
- 置き換え: B13-b の淡色+理由(行き止まり)と B13-c の Stage 点滅。
- 軸差: K1(前提を書く)、I2、C3。3 軸。

**G8-β「Name-pick target(対象を名前で後から選ぶ)」**
- 機構: 先に tile を選び、**対象は名前の type-ahead 一覧から**(layer 名・種類・parent が見える)。Stage の点滅は不要。
- 言葉なしで: 一覧の位置が固定(Timeline の並びと同じ)。
- 盲の人: SR「Layer 3、text、Blur 付き」。Enter で適用。
- 契約: 一覧は Timeline の並びと同じ/ 型の合わない layer は一覧に出ない。
- 置き換え: B13-c の点滅(視覚専用)。
- 軸差: I3/I4、C5。2 軸。

### 3.9 G9 数値の文法: 空席 = 音程・打つコマンド
**G9-α「Pitch scrub(数値を音程で)」**
- 機構: scrub/矢印の間、**値の範囲内の位置を音程に写す**(scale 等は対数)。**既定値は固有の「home 音」、整数・端・snap は detent(音+触覚)**。速さは tick の密度。離すと値+単位を読む。
- 言葉なしで: 音程の上下で「増えた/減った」、home 音で「既定に戻った」。
- 盲の人: 矢印(Shift x10 / Alt x0.1)で同じ。SR は離した時と `Ctrl+;` で値を読む。
- 契約: 同じ値は同じ音程/ 既定は常に同じ home 音/ 範囲外は `unavailable`。
- 置き換え: 追加(視覚の scrub の置き換えでなく、感覚の経路を足す)。
- 軸差: C3/C4、T2(連続音)。2 軸(C を軸に数える規則 D による)。

**G9-β「Say it(値を打つ)」**
- 機構: Cmd-K の第二段に `opacity 50`、`x +20`(相対)、`scale *1.1` と打つ。選択に適用、確定前に結果の差を 1 文(`opacity 100 → 50`)。
- 言葉なしで: 打った物がそのまま履歴。単位は語でなく位置。
- 盲の人: そのまま(キーボードだけ)。結果を読み上げ。
- 契約: 相対/絶対は記号で決まる(D-I1 と同じ)/ 複数選択では「混在」を言う。
- 置き換え: 精密な 1 回の値の変更(scrub の往復)。
- 軸差: I3(vs I1)、D5、T1(vs T2)。3 軸。

### 3.10 G10 空間 GUI: 空席 = キーだけで空間・音の空間・関係で置く
**G10-α「Sonar stage(位置を音で)」**
- 機構: 選択 layer を **持続音で表す(x=パン、y=ピッチ、scale=音量で 100% が detent、回転=45° ごとに detent)**。中央・端・他 layer の anchor に `detent`(snap の磁石)。矢印で nudge(Shift 粗、Alt 細)。
- 言葉なしで: 音が動くのを聞いて位置が分かる。
- 盲の人: nudge の度に「x 120、y 40」。`G` で最も近い他の layer の名前と距離を言う。
- 契約: 同じ位置は同じ音/ snap は常に detent で告げる/ 1 gesture = 1 undo。
- 置き換え: I3-a/b/c の「見て掴む」だけの経路(視覚は残す)。
- 軸差: C3/C4、I2、S1 を継続。実操作(印): 音で 2 次元の位置が実用精度で分かるか。**盲の人での検証が必須 [inferred]。**

**G10-β「Anchor grid(再帰する 9 分割)」**
- 機構: Stage で `G` を押すと 3×3 の 9 領域(numpad 配置)。数字で領域を選ぶ度に **その領域がさらに 3×3 に分かれる**。4 回で 1 px 以内。`Enter` で選択 layer の anchor をそこへ。
- 言葉なしで: numpad の配置=位置。音の高さが領域に対応。
- 盲の人: SR「右上、さらに左下」。位置は数値で言う。
- 契約: 領域の番号は固定(numpad)/ 4 回以内で全画面に届く/ Esc で 1 段戻る。
- 置き換え: gizmo の「画面を見てポインタで合わせる」。
- 軸差: I2、S1 を再帰、D5。3 軸。

**G10-γ「Place by relation(関係で置く、一回きり)」**
- 機構: 座標でなく「**Layer 2 の中央に**」「**Layer 5 の左に、間 16**」「**画面の右端に揃える**」を型付きの一覧から選ぶ(結果は 1 回の移動で、**Relation は保存しない**: 既決「Relation は操作」と区別)。
- 言葉なしで: 配置の 6 動詞(中央・左・右・上・下・揃える)の順序を固定。
- 盲の人: 動詞→対象の type-ahead→数値(間)。結果を 1 文。
- 契約: 結果は 1 undo/ 対象が動いても追従しない(結ぶなら Relations へ)。
- 置き換え: 位置の数値 2 つを手で合わせる作業。
- 軸差: I2/I4、S3(関係で指す)、C5。3 軸。

### 3.11 G11 key の状態: 空席 = 状態を音で・時間を表で
**G11-α「Key walk with tri-state earcon」**
- 機構: `,` `.` で選択 property の前/次の key へ playhead が飛ぶ。**3 状態(動かない/動く・今 key 無し/今 key 有り)は音色で分かれる**。
- 言葉なしで: 状態の音色が 3 つ。key 上は `detent`。
- 盲の人: SR「key 3 / 7、2.0 s、opacity 40、ease out」。
- 契約: 状態は 3 つの音色に 1 対 1/ 飛ぶ度に必ず値を言う。
- 置き換え: 輪郭/半/塗りの diamond だけの 3 状態(視覚のみ)。
- 軸差: C3、T2。2 軸。

**G11-β「Keys as a table(key を行に)」**
- 機構: 選択 property の key を **表(時間・値・ease 名)**にし、矢印で行を歩き、値は打って直す。lane の代わりの直列形。
- 言葉なしで: 行の位置=時間の順。値の変化は音程で。
- 盲の人: 表(grid)。SR「2.0 s、40、ease out」。
- 契約: 表と Timeline の key は同じ物/ 編集は 1 undo。
- 置き換え: key を見て掴む lane の編集(視覚専用)。
- 軸差: S2(時間を行に)、I3、C5。3 軸。

### 3.12 G12 ease: 空席 = 動きを音と触覚で・演奏する
**G12-α「Ease by ear(動きを音程の滑りで)」**
- 機構: ease を **0.6 秒の音程の滑り(progress = ピッチ)**として鳴らす。ゆっくり始まって速く終わる、行き過ぎて戻る(overshoot)は **最終音を超えて戻る**として聞こえる。触覚は 10% ごとの tick(任意)。矢印で preset を巡ると 1 つずつ鳴る。
- 言葉なしで: 音の形で動きが分かる。
- 盲の人: 矢印で巡り、SR は名前+「後半が速い」等の 1 文(曲線の性質から機械的に生成)。Enter で書く。
- 契約: 同じ curve は同じ音/ 長さは実際の区間か固定 0.6 秒(切替可)/ 確定まで書かない。
- 置き換え: 視覚の曲線 plot と動く tile だけの経路。
- 軸差: C3/C4、T2。2 軸(規則 D)。 **ease は「感じ」なので、ここが空席だと G12 は U 落第のまま。**

**G12-β「Perform the ease(演奏して決める)」**
- 機構: **区間が実時間で再生されている間、1 本の fader(ポインタの縦位置/矢印の長押し)で progress を演奏**し、記録した経路を ≤ 2 handle の bezier に単純化する。やり直しは何度でも。
- 言葉なしで: 手の動きが動きになる。
- 盲の人: → 長押しで加速、離して減速。滑りの音を聞きながら演奏。結果を preset 名に最も近い物として言う。
- 契約: 演奏は 1 回 = 1 候補/ 確定まで書かない/ 近似は handle ≤ 2。
- 置き換え: handle を見て掴む。
- 軸差: I1/I2 を時間の中で、T2、K2。3 軸。実操作(印): 演奏が preset 選びより速いか。

### 3.13 G13 差分・戻す: 空席 = 差を歩く・時間で戻す
**G13-α「Diff walk and digest」**
- 機構: `D` で今の layer の **既定との差の要約**(「変更 7: Transform 3、Blur 2、駆動 1、key 1」)を言う。`[` `]` で **変えた行だけを巡る**。`Backspace` でその行を既定へ。
- 言葉なしで: 差の数=短い tick の数、変えた行は `tick`、駆動は別の音色。
- 盲の人: そのまま。各行 SR「Rotation、45 度、既定 0、Slider A に従う」。
- 契約: 巡るのは変更した行だけ/ 戻すのは値のみ、key と relation は残る(I6-c と同じ)/ 1 undo。
- 置き換え: I6-a の「濃さだけ」と I6-b のフィルタ(視覚で見る前提)。
- 軸差: I2、D5、C5。3 軸。

**G13-β「Layer time-machine(この layer の時間で戻す)」**
- 機構: `←` `→` で **この layer 自身の変更履歴**を 1 つずつ遡り(全体の undo と別)、各段で「戻した: blur radius 12 → 8」と言う。Enter でそこに留まる、Esc で今に戻る。
- 言葉なしで: 段ごとの tick+戻し量の音程。
- 盲の人: 段ごとに 1 文。
- 契約: 遡る間は何も確定しない/ Enter で 1 つの undo 単位。
- 置き換え: I6-d の戻る先の 3 択メニュー。
- 軸差: T2、K2、I2。3 軸。

### 3.14 G14 長い一覧: 空席 = 状態で飛ぶ・行にしるし
**G14-α「Property tree walker(状態で飛ぶ木)」**
- 機構: Inspector 全体を **tree** とし、`↑↓` で歩き、`←→` で階層、**`Alt+↓` で次の「動く行」、次の「変えた行」、次の「駆動された行」へ飛ぶ**。行は常に「Opacity、40%、動く、key 2 s、既定 100」と読める。
- 言葉なしで: 行の状態音色(G11-α の 3 状態+差・駆動)で、歩くだけで「この辺は動く」が分かる。
- 盲の人: WAI-ARIA tree、type-ahead、`?` で今のキー。
- 契約: 行の読みは固定の語順(名前・値・状態・既定)/ 飛ぶ先が無ければ `unavailable` と件数 0。
- 置き換え: Advanced の畳み+検索欄だけの経路。
- 軸差: I2、S2→tree、C5、D5。4 軸。

**G14-β「Row marks(行のしるし ⌥1-9)」**
- 機構: 歩いている行に `⌥1-9` でしるしを付け、`1-9` で戻る(DAW の marker と同じ)。しるしは layer をまたぐ(effect 種ごと)。
- 言葉なしで: 数字=位置の記憶。
- 盲の人: SR「しるし 3: Blur radius」。
- 契約: しるしは自動で動かない/ 同じ effect 種で同じ位置。
- 置き換え: I7-c の星(hover/選択時だけ見える標)。
- 軸差: I2、S1 に近い記憶(位置)、D5。2 軸。

### 3.15 G15 結ぶ: 空席 = 持ち運び・文・なぜ動く
**G15-α「Carry mode(持ち上げて、置く)」**
- 機構: 値の行・effect・key で `Enter` = **持ち上げる**(音: lift)。以後は **通常のキーで panel を渡り歩き**、置ける所だけを `Tab` で拾う(型の合わない相手は **飛ばされる**)。`Enter` = **置く**(音: drop)、`Esc` = 戻す。**pick-whip・drop 置換・copy 先を 1 つの動詞に束ねる**。
- 言葉なしで: 「持った」音と「置いた」音。持っている間は小さな持続音(`peek`)。
- 盲の人: SR「持っている: Rotation of Layer 3。置ける所: Slider A、Layer 5 の Position。Enter で置く」。
- 契約: 持っている物は常に 1 つ・常に読める/ 置ける所だけが巡回対象/ 置いた結果を 1 文/ 1 undo。
- 置き換え: I9-a の掴んで引く線(ポインタ専用)、B8 の drop、I11-c のスポイトの hover。
- 軸差: I6 のキー形、M1、D5、C3、S3。4-5 軸。**ここが最大の「1 つで多くを置き換える」案。**

**G15-β「Trace why(なぜ動く?を順に鳴らす)」**
- 機構: 選択 layer で `W` を押すと **動く原因を 1 つずつ**(key・relation・parent・既定との差)**種類ごとの音色**で、順に鳴らし、文で言う。`W` を押すたびに次の原因へ、原因にいる間 `Enter` でそこへ飛ぶ。
- 言葉なしで: 原因の数=音の数、種類=音色。
- 盲の人: SR「動く理由 3 つ。1: key 2 s の opacity。2: Slider A に従う rotation。3: 親 Group 1」。
- 契約: 原因は全て漏れず列挙/ 同じ状態は同じ音列。
- 置き換え: E9「動く理由の一覧」の視覚版(R7)。
- 軸差: C3、T2、D5。3 軸。

**G15-γ「Sentence builder(文で結ぶ)」**
- 機構: 3 つの枠「**[何を] が [何] に従う、[範囲]**」を type-ahead で順に埋め、完成した文で作る。既存の relation も **同じ文で読み出す**。
- 言葉なしで: 枠の順序と音(対象=低、源=中、範囲=高)。
- 盲の人: 各枠で一覧を読み、最後に文全体を言う。
- 契約: 作る文と読む文が同じ/ 型の合わない相手は一覧に出ない。
- 置き換え: I9-b の lasso/I9-c の macro の「作る」手順。
- 軸差: I3/I4、S3 を言語で、C5。2-3 軸。

### 3.16 G16 一側面コピー: 空席 = 並列の袋・同じ事をもう一度
**G16-α「Aspect pockets(4 つのポケット)」**
- 機構: 固定の 4 つのポケット(Ease / Colour / Keys / Effects)があり、**コピーは該当ポケットだけを上書き**し、貼る側は **どのポケットかをキーで指す**(`⌥⌘1-4`)。複数の側面を同時に持ち運べる(単一の clipboard は 1 つだけ)。
- 言葉なしで: ポケットの位置=側面。各ポケットの音色が違う。
- 盲の人: SR「ポケット 1 Ease: ease out 0.4」。空は `unavailable`。
- 契約: 4 つは不変/ ポケットの中身は常に 1 語で言える/ 貼る時は選択中の全 layer へ 1 手。
- 置き換え: I11-a の単一の clipboard と、その中身を表示する面。
- 軸差: S1(位置)、I2、L2、C3。3-4 軸。

**G16-β「Do-again(同じ事をもう一度)」**
- 機構: 利用者が 1 度手で行った編集は host が **意味のある操作として記録**(「ease を out に」「色を X に」「effect Blur を足す」)。`⌘⇧R` で **今の選択に同じ操作を再実行**。`⌥R` で直近 5 つから選ぶ。copy・paste 無し。
- 言葉なしで: 同じ操作の再実行=同じ音(apply)。
- 盲の人: SR「もう一度: ease を out に、Layer 4」。
- 契約: 再実行は **操作の意味**を使う(値の写しでない)/ 選択に合わない時は G8-α の Fix-it。
- 置き換え: I11 全体(copy→選ぶ→paste の 3 手)の繰り返し作業。
- 軸差: I0/I2(明示の copy が無い)、L2、D5。3 軸。

### 3.17 G17 effect の積み: 空席 = キーで持って動かす・並びを聞く
**G17-α「Stack walker(積みを持って動かす)」**
- 機構: card に focus して `Space` = 持つ(lift)、`↑↓` で動かす(位置の tick)、`Enter` = 置く、`Esc` = 戻す。
- 言葉なしで: 動く度の tick の数=位置、端は `detent`。
- 盲の人: SR「Blur、2 / 4、持っている。上: なし、下: Glow」。
- 契約: 持っている間は他の操作を受けない/ 1 undo/ 順序の意味(上から下へ適用)を 1 度言う。
- 置き換え: I8-a の drag grip。
- 軸差: I2 のキー形、M1、C3。2-3 軸(G15-α と同じ「持つ」動詞)。

**G17-β「Stack as phrase(積みを 1 つの短い音列で)」**
- 機構: 積みを **上から下へ 1 つずつ短い family 音色で鳴らす**(bypass は休符)。並びを変えると音列が変わる。
- 言葉なしで: 音列がそのまま積み。
- 盲の人: `P` で再生。SR は名前の列も。
- 契約: 決定的/ bypass は休符。
- 置き換え: 積みの全体像を見る目。
- 軸差: C3、T2。実操作(印): 実用か疑わしい。後回し。

### 3.18 G18 一括: 空席 = 規則で選ぶ・打ってずらす
**G18-α「Fan-out by typed rule」**
- 機構: 複数選択に `step x 20`(選択順の等差)、`random x ±10 seed 3`、`offset t 3f` を打つ。結果を **表(名前・元・新)で確認、Enter で確定**。
- 言葉なしで: 表の列の位置が固定。変化量は音程で。
- 盲の人: 表を歩く。SR「Layer 3、x 100 → 140」。
- 契約: 規則は決定的(seed)/ 確定まで書かない/ 1 undo。
- 置き換え: I12-b/c の「ずらしつまみ」「Falloff 図」(視覚と drag 前提)。
- 軸差: I3、K2、S2。3 軸。

**G18-β「Query select(規則で選ぶ)」**
- 機構: Cmd-K に `select: effect=blur, animated` と打つと **条件に合う全 layer が選択**になる。結果の数を言い、以後の操作(G18-α を含む)はその集合に。
- 言葉なしで: 件数=音。条件は固定の語彙。
- 盲の人: SR「23 layers selected」。`[` `]` で集合内を巡る。
- 契約: 条件は決定的/ 集合は保存できる(名前を付けて L3)/ 選択自体は 1 undo。
- 置き換え: 「Timeline で 30 個を目で探してクリックで選ぶ」(E7 の R5)。
- 軸差: I3(選択を打つ)、S2、D5。3 軸。**盲の人にとって「多数を選ぶ」唯一の手段。**

## 4. 「言葉が要るか」の判定: Words test の提案

目的: 「今の UI は言葉で説明が要る」を **測れる形** にする。ユニバーサルの定義(PROCESS.md)に対応する 5 つの検査。判定者は作者と別(独立)。

### 4.1 検査
| 検査 | 何をするか | 合格 |
|---|---|---|
| **T-W1 Words-off** | Widgetbook の knob `Words: on / off / blocks`。off では `T.*` の文字を **同じ幅・高さの無地の帯**に置換(記号・色・位置・形はそのまま)。初見の人(Motolii を知らない、AE 経験あり)に E1/E2 を走らせ、**状態質問 5 問**(「これは動いている?」「既定のまま?」「確定した?」「今の対象は?」「次に何が起きる?」)に答えさせる | 走行完走、かつ質問 5 問中 4 問以上 |
| **T-W2 Semantics-only** | 同じ knob `Read aloud` で、**Semantics 木を平文に書き出した面**(focus 順に 1 行 = label / value / hint / state / role)を出す。画面は隠す。**その平文だけ**を渡された別の人が、キーの表だけで E1 を完走できるか。自動検査も付ける: ①全 focusable に label と role、②値に単位、③状態変化は live 1 文、④focus 順が読み順、⑤色・hover・位置だけで伝わる情報が 0 | 自動検査 0 違反 + 人の走行が完走 |
| **T-W3 Screen-off 走行** | 画面を消し(黒い overlay)、macOS VoiceOver+音あり、キーボードのみで E1/E2 を走る。**盲の当事者**に頼めない間は晴眼者の代理(proxy)で行い、**代理の結果は「当事者の結果ではない」と明記**する | 完走、時間が基準線の 3 倍以内、「今どこ?」迷いが 3 回以内 |
| **T-W4 Sound-off / Pointer-off** | 音を切った走行(全 earcon に視覚・文字の双子があるか)、マウスを切った走行(hover・drag 専用の入口が無いか) | どちらも完走 |
| **T-W5 Words budget** | 課題を完走するのに **読む必要のある distinct な文字列**の数を数える。語を足して直す案(説明文)は、足した語の数も数える | 案どうしで数を比べる。少ない方が勝つ |

### 4.2 静的な走査(コードを書かずに、grep で足りる)
- `Semantics` / `ExcludeSemantics` の数(現在 0)。
- `MouseRegion` / `onHover` だけで状態や操作が現れる箇所 → 各々に **focus とキーの双子**が要る一覧にする(今: panel_browser_a 4、inspector_a_kit 2 など、実数は検査時に再計測)。
- `Text` を取り除くと状態が消える部品 = 「言葉が担い手」の部品一覧(「混在」「N filters」「Animate」…)。
- 作業木に `book/lib/a11y_addon.dart`(未コミット)が既にある。**検査を作る時は、それを土台にするか先に確認する**(PROCESS.md §0: 作る前に探す)。

### 4.3 U の等級(各案に付ける)
| 等級 | 意味 |
|---|---|
| U0 | Words-off で目的が分からない |
| U1 | Words-off で目的が分かる(形・位置・色が担う)が、読み上げは不能 |
| U2 | **U1 + Semantics-only で完走** |
| U3 | **U2 + Screen-off(音・触覚あり)で完走** |
| U4 | **盲の当事者が独立に E1 を完走**(最終基準) |

**ゲート:** 挑戦者は U2 以上で決勝(試合)に出られる。既存案は、機構として U2 に届かない物(hover 専用、2 次元の位置だけが意味、色だけが意味)を **決勝に出さない**。優勝の目標は U3、製品の目標は U4。
**やらない事:** Words-off を「文字を足して直す」で通すのは不可(足した語は T-W5 で数える)。見た目の assert を UI テストに入れるのは別問題(UI テストは動きだけ、の既決)— Semantics の検査は見た目の assert ではないので許される。

# 幹の軸台帳(axis ledger)

`../normal-map.tsv`(葉= 名前を持つ項目 1,551行)に対して、**幹の軸を1本ずつ全葉に掛けた結果**を置く。
根拠は [normal-map-trunk](../../../docs/reviews/2026-08-23-normal-map-trunk.md)。

**1軸1ファイル。`normal-map.tsv` 本体には誰も触らない**(1ファイル大物への複数レーンは不可・裁定198/201)。

## 取り違えを構造で封じる — 軸idを3重に持つ

行を別の軸ファイルへコピペした瞬間に柵が落ちるようにする:

1. **ファイル名** `A04-scale.tsv` の `A04`
2. **ヘッダ** `#axis: A04 量` の `A04`
3. **全データ行の第1列** が `A04`

この3つが一致しない行が1つでもあれば `axis_ledger_fence.rs` が赤になる。
「同じ形の台帳が10本並ぶ」構造なので、人間の注意力に頼らない。

## ファイル形式

```
#axis: A04 量
#question: 50レイヤー・10分尺・4K で壊れないか
#verdicts: 耐える|壊れる|未計測
#sweep: grep -rn "scrollable" next/ui next/shell   ← 使った探索をそのまま残す(GESTURES.md 前例)
#sweep: cargo test -p motolii-shell --test ...
axis	map_id	対象	判定	証拠	穴
A04	711	Scroll to current time	耐える	rail.rs:120 が scrollable の子	-
A04	-	Timeline 縦スクロール	壊れる	`scrollable` 使用ゼロ・行高20px	穴
```

- **タブ区切り**。ヘッダ行は `#` 始まり(`#axis` / `#question` / `#verdicts` / `#sweep` は必須。`#sweep` は1本以上)
- `map_id` = `normal-map.tsv` の `id`。**台帳に対応行が無い物は `-`** —
  **この `-` の行が本命**(幹だけが要求していて葉に名前が無い= 今回探している穴そのもの)
- `判定` は `#verdicts:` で宣言した値のどれか。軸ごとに違ってよいが、**宣言しない値は使えない**
- `穴` 列は `穴` か `-` の2値。集計はここで数える

## 網羅の主張はしない

GESTURES.md と同じ規約: **使った grep を `#sweep:` にそのまま残す**。
「全部見た」と書かず、「この探索範囲で見た」と書く(KNOWN.md「探したが無いと書く時は探索範囲を必ず併記」)。

## 現在地は生成物が持つ。この台帳は「動線に現れない穴」のレンズ

**進捗の正本は [`../generated/steps.md`](../generated/steps.md)**(手順書から導いた段階)。
`BOARD.md` は 2026-08-23 に手書きの現在地として作られたが、**同日中に生成物へ置き換わり撤去した**。

**この軸台帳は捨てない。役割が違う** — 実測(2026-08-23):

| | 何を指すか |
|---|---|
| 手順書(段階) | 利用者の動線に沿った穴。**やる順番**を決める |
| **軸台帳(ここ)** | **動線に現れない穴**。`transform.rs` 7件・`gizmo.rs` 5件など、手順書を辿っても踏まない場所 |

重なりは9ファイルだけで、**軸だけが指すファイルが25ある**。手順書だけを階段にすると
そこが永久に順番待ちになるので、**段階を通すときに一緒に見る参照**として残す。
優先順は段階が決める(裁定: 先回りで作らない)。

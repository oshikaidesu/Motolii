# 手順書(procedures)— 名前の無い操作を名指しさせる検出器

`../normal-map.tsv`(葉= **製品が名前を付けた項目** 1,551行)と
`../axis/`(幹= 全葉に掛かる横断軸)に続く第3の器具。
根拠は [normal-map-trunk](../../../docs/reviews/2026-08-23-normal-map-trunk.md)。

## なぜ手順書なのか

台帳はメニュー木・ショートカット表・パネル一覧・環境設定から作った。**どれも製品が自分で書いたリスト**で、
そこには「スクロールする」「全部選ぶ」「掴んで動かす」が1行も無い(`marquee` / `hover` / `drag` の grep が0件)。
**手順書は違う。** 手順は動作の順序で書くので、名前の無い操作を**書き手の側から名指しせざるを得ない**。

## ペルソナ調査との違い(重要 — 同じ物を2回作らない)

| | ペルソナ調査(`docs/reviews/2026-08-22-persona-*`) | 手順書(ここ) |
|---|---|---|
| 止まったら | **止まって報告する**(壁の手前まで) | **止まらない。書き切る**(壁の先も全部書く) |
| 成果物 | 調査報告 | **製品の成果物**(いずれ利用者が読む物) |
| 穴の出方 | 最初の壁1枚 | **書けなかった行が全部並ぶ** |

書き切ることを形式で強制するのが目的なので、**省略・「以下同様」・「ここは後で」は不合格**。

## ファイル形式

1手順書1ファイル。`P1-lyric-mv.md` のように連番+主題。

各手順は**表の1行**で、必ず全列を埋める:

| # | 利用者は何をするか | どこで | 実装の証拠 | 判定 |
|---|---|---|---|---|
| 12 | レイヤーを全部選ぶ | Timeline | `next/ui/motolii-timeline-pane/src/nav.rs:88` `SelectAllLayers` | 書ける |
| 13 | 50枚目まで下へスクロールする | Timeline | — (`scrollable` 使用ゼロ) | 【穴】入口が無い |

**判定は4値**:

- `書ける` — 実装の証拠に `file:line` が必ず要る。証拠の無い `書ける` は不合格
- `【穴】入口が無い` — 意味(store/eval)は在るが UI から到達できない
- `【穴】意味が無い` — store/eval にも無い。何を作るかから要る
- `【未確認】` — 実機でないと判定できない。**このターンはビルドしないので、そう書いてよい**(推測で `書ける` と書かない)

## 粒度の規約 — ここが本目的

**名前の無い操作を、独立した1手順として必ず書く。** まとめない:

- 「歌詞を50枚置く」ではなく、**置く / 見えない所までスクロールする / 全部選ぶ / まとめて色を変える** に割る
- 「位置を調整する」ではなく、**掴む / 動かす / スナップさせる / 離して確定する / Esc で戻す** に割る
- 待ち・確認・やり直しも手順に数える(**待たされる / 結果を確かめる / 元に戻す**)

「普通のソフトなら当然できるので書くまでもない」と感じた操作こそ書く。**それが台帳に無い物**。

## 末尾の集計(必須)

```
全手順 N / 書ける N / 【穴】入口が無い N / 【穴】意味が無い N / 【未確認】N
```

さらに **`normal-map.tsv` に対応行が在るか**を穴ごとに書く。
対応行が無い穴が、今回探している「幹だけが要求していて葉に名前が無い物」。

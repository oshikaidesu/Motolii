# design-sense-lab 概要(他の LLM に相談するための要約、2026-10-02)

## これは何か
Motolii(Flutter 製のモーショングラフィックス編集ツール)の「新しい UI のトンマナ」を、本体から隔離して作っている実験室。Widgetbook(Flutter の部品カタログ)で、部品を実画面で見て選べるようにしてある。本体の UI は参照しない(反面教師)。

- 場所: `design-sense-lab/`(Motolii リポジトリの `design-lab` ブランチにも同じ物がある)
- 正本の文書: `DESIGN.md`(出所の印つき)、`PROCESS.md`(作り方)、`research/`(調査と判定の記録)

## 現在の部品(Widgetbook 19 コンポーネント、約 166 use case、book/lib 約 1.8 万行)
| 区分 | 中身 |
|---|---|
| 基盤 | `tokens.dart`(グレー階調 N、関係の 6 色 Fam、アクセント C、文字 T、行 TL)、`kit.dart`(Look 切替、knob)、`parts/glyphs.dart`(線の記号 15 個) |
| 基礎部品 | Controls(値の井戸、スイッチ、セグメント)、inputs 14(スクラブ数値、Vec3、検索、ドロップダウン、スライダー、色など)、navigation 14(タブ、ツリー、メニュー、コマンドパレット、ダイアログなど)、feedback 14(進捗、トースト、ステータスバー、エラー行、書き出しシートなど) |

## 基礎は全部作れているか(正直な評価)
- **見た目としての基礎部品: ほぼ揃っている。** 入力・ナビ・フィードバック・メディア・Timeline・Stage・Relation・Inspector の主要な部品が、同じトークンから出ている。前の独立した判定では 122/126 まで上がった(判定は静止画)。
- **足りないもの(確認済み):**
    1. **操作の状態の仕様がない**: フォーカス・押下・無効の見え方(open-decisions #7)。キーボード操作も未整備。
    2. **ほとんどが静止した見本**: ドラッグ・ホバー・キー操作の中身は、新しい `inspector-gui` と `Dose` 以外はほぼ作っていない。操作の検証は、静止画の判定では測れない。
    3. **利用者が決めていない項目が多い**: 軸の色、再生・録画の色、重大度の色、アクセント色、危険の赤、選択の見せ方(`research/open-decisions.md` の A〜I と、先例との差 10 項目)。
    4. **新しく足した部品は、まだ判定の途中**: `inspector-gui` と `Dose` は 2 回判定して、はっきりした欠陥は直した。主従(数値と図のどちらが主か)は未決。
    5. **本体とはつながっていない**: 隔離環境。FFI も実データもない。

## 方向と、いま決まっていること
- 決まっている: 今の静かなトンマナを保つ。旧 Motolii は反面教師(拾うのは意図だけ)。記号は少なく。数値を意図として GUI にする(盤・輪・取っ手)。
- 取り下げられた: 雑誌(コロコロ)/ペルソナ/ゲーム UI の方向(仕様ではない。研究は参考として残る)。
- 未決: 数値と GUI のどちらが主か。操作の仕方(一体の GUI / モード切り替え / 欄をなぞる / 触ると出る)。

## 進め方(夜間に作って成果の出た手順)
現物を見る → 問題を特定 → 必要な先例だけ調べる → 複数案を同じ Widgetbook で比較 → 利用者が決める。判定は独立したサブエージェントが、実画面のスクリーンショットで yes/no。利用者の発言は、問題や意図を見つける材料として扱い、そのまま仕様にしない。

## 他の LLM に聞きたいこと(候補)
1. 部品の基盤として、足りない物はあるか(状態、キーボード、アクセシビリティ、テーマ)。
2. 操作を伴う部品(ドラッグ・モード切り替え)を、静止画でなく動きで検証する、現実的な方法。
3. 「数値を意図の GUI にする」ことの先例(Figma、Blender、Ableton、Cavalry、After Effects、Apple Motion)で、数値と図の主従をどう決めているか。
4. 判定者(LLM)が見落としやすい観点の補い方。

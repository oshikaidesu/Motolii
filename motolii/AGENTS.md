# Motolii — rerunを軸に持ったAE(Lottie)インタフェースのソフト

この一行が憲法。迷ったらこの行に戻る(裁定はdocs/decision-index.mdの「stage4」行)。
ここは四代目の世界。crates/ next/ app/ は歴史であり、この世界は読まない。

## 三本柱

1. **技術層 = Rerunフォークの部品。** 作る前に在庫を引く。自作してよいのは
   **編集の意味**だけ。再発明は罪。
   線引き: **GPU資源(pipeline・shader・layout・texture)の所有はre_rendererのプールへ返す。
   パスの連鎖の組み方はMotoliiが持つ**(連鎖の器はre_rendererに無く、エフェクトスタックの
   順序は編集の意味)。`Renderer` traitはビューに描かれる物のための拡張点で、
   scratch texture間のblitには着せない。
2. **意味 = Lottieが審判。** 保存される物が何かはLottieに聞く。
   Lottieが黙る所と意図的に離れる所だけが利用者裁定。
   **ただし操作の体系はAEが出典で、Lottieに聞く問いではない**(下記)。
3. **面 = 単一プロセス・単一wgpu Device。** 境界(WebView・別プロセス・OS共有面)は
   作らない。

## 誰に向けたソフトか

**まず利用者自身が使うMV制作ツール**(完成条件は`../docs/concept.md`)。
**AEユーザーの乗り換えは「手癖で触れる」程度のサブ目標**であって、製品の背骨ではない。

操作文法は二層。**土台は一般的な編集ソフトの共通文法**(Premiere/DaVinci/Final Cut/
CapCut/AviUtl の交差集合)で、**AEの体系はその上に乗る** — AE自体がガラパゴスなので、
土台に据えると孤島を継承する。上の層では篩をかける: **AEユーザーが何も教わらずに
やっていることは引き継ぎ、「そういうものだ」と教わって覚えたことは引き継がない**
(利用者の理解を求める動きが要る時点で引き継がない)。

## UIを触る前の3つの問い

3本の文書が、この順に別々の問いへ答える。**規則はそちらに在る。ここには写さない。**

1. **どの審判に聞くか** → [motolii-deltas.md](../docs/motolii-deltas.md) 冒頭の3審判表。
   AEに追いつく話=Lottie / **UIの分岐=意図論** / AEから離れる話=上記の篩+同文書。
   **Lottieに聞いてよいのは1行目だけ** — UIの分岐をLottieに聞くと、Documentが持っている物が
   そのままUIになる。同文書は「試験は生成規則なので、既決事項を独自に導出し直す」事故も
   警告している。**離れる裁定を出したら同文書へ1行足す**
2. **何が在るべきか** → [ui-inherited-grammar-gap.md](../docs/ui-inherited-grammar-gap.md)。
   刻まれた反射の在庫。**無いこと自体が負債**
3. **できたと言えるか** → [ui-quality-bar.md](../docs/ui-quality-bar.md) のQ0〜Q9・B1〜B7。
   Q0=触れそうな物は必ず機能する、Q3=触ったのに何も変わらないのは不合格。
   **検収でQ番号を引用する**

## ビルドの不変量

- このworkspace(`motolii/`)だけがビルドされる。**`motolii/`の外を指すpath依存は
  1つも無い** — 使うクレートは全部この家の中に居る(`core/` `engine/` `ui/`)
- **cargoは`motolii/`の中から回す。** `.cargo/config.toml`はカレントディレクトリ基準で
  探されるので、リポ根から`--manifest-path`で回すとシェーダのホットリロード設定が効かない
- **1つのtargetを同時に共有しない**(競合で壊れる)。**冷ビルドをレーンごとに
  増やさない**(ディスクと時間が爆発する)。この2つを守る限り、レーンが
  ビルドすること自体は禁止しない——warm cacheの複製や共有キャッシュ等、
  その時点の道具はdocs/reviews/の日付付き文書を引く
- profileと`[patch]`はworkspace rootでしか効かない

## 風化する事実は各自の家へ

現在の事実をここに書かない。何に依存しているかは各Cargo.toml、罠と制約は
コードのその場所のコメント、経緯はdocs/reviews/の日付付き文書、裁定は
docs/decision-index.mdを主題でgrep。

コメントは**事実だけを書く。コードは感想を書く場所ではない**。
何のための関数か、何のための変数か、破ると壊れる制約は何か——それだけ。
日付・裁定番号・実測の経緯・以前の実装との比較・弁明は、その場で風化する
出所情報であり、コミットメッセージと日付付き文書の持ち物。
嘘になったコメントはバグ。
